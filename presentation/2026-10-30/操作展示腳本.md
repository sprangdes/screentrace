# ScreenTrace 操作展示腳本

2026-10-30（五），後端技術分享。全程使用 `demo/react-reservio.html`（`analyze/reservio/report/` 的副本，自有 Spring Boot＋React 專案，41 個畫面、66 支 API）。

報表是單一離線 HTML，雙擊即可用瀏覽器開啟，不需要網路，也不會啟動 reservio、登入或送出任何後端請求。

## 會前準備

1. 用 Chrome 或 Edge 先開一次 `demo/react-reservio.html`（約 19 MB，第一次開啟要幾秒）。
2. 使用乾淨的瀏覽器設定檔，或把所有畫面恢復「未確認」，避免彩排留下的標記。
3. 第一次標記時若跳出進度檔選擇，選「稍後再說」；需要 md 時用「下載 md」。
4. 不建議現場跑 CLI 分析（需要 Java、Maven、Node、Playwright，第一次 setup 要下載）。投影片 6 只展示指令。

## 第一段：怎麼使用（投影片 7–9，約 4 分鐘）

1. **報表總覽（投影片 7）**：開啟報表，指出左側畫面清單與搜尋、中間依網址分組的畫布、上方「畫面／API」頁籤、右上角確認進度與「下載 md」。
2. **打開畫面（投影片 8）**：左側搜尋 `/service`，點兩下 **編輯服務**（`/service/:id/edit`）。
   - 中間是靜態重建的預覽，欄位內容是「示例值」。
   - 右側：保留／移除／未確認；展開「按鈕 27 個」；「呼叫的 API 7 個」；「從哪些畫面可來到這裡 1 個：服務管理」。
3. **API 頁（投影片 9）**：切到 **API**，點 `POST /api/businesses/services/{id}/modify`。
   - 處理程式 `BusinessApiController.modifyServiceItem()`，`BusinessApiController.java:394`。
   - 呼叫來源：編輯服務的「重試（第 1 個）」「儲存服務」。
   - 展開 **Request／Response**：`ServiceItemRequest` 的 duration、name、id（PATH），回應 `ApiResponse<Void>`。

## 選用：保留／移除決策（約 1 分鐘）

1. 在 API 頁先看 `POST /api/businesses/services/{id}/modify` 是「使用中」。
2. 回到畫面頁，把 **編輯服務** 標成「移除」。
3. 再看 API 頁：這支 API 的呼叫來源只有編輯服務，所以變成「可移除」；說明文字會寫「這是推導結果，不是刪除建議」。
4. 按 **下載 md**，打開給大家看決策紀錄與「分析限制」。
5. 結束後把編輯服務改回「未確認」。

## 現場常見問題

- **這是不是啟動了 reservio？** 沒有。原始碼唯讀；Chromium 只渲染工具產生的靜態 HTML，且關閉 JavaScript。
- **畫面上的資料是真的嗎？** 不是。動態欄位填的是「示例值」。
- **為什麼儲存服務那條是 INFERRED？** 前端網址是樣板字串 `${id}` 組出來的，只能依規則正規化後配對；後端的 `@PostMapping` 是字面值，所以 HANDLED_BY 是 CONFIRMED。
- **多個可能的下一頁怎麼辦？** 全部列為候選，不自動挑一個（例如「返回首頁」連到 `/`，訪客與商家首頁兩個都保留）。
- **可以直接刪掉「可移除」的 API 嗎？** 不行。排程、外部系統、書籤仍可能使用，需要工程確認。
- **準確率多少？** 沒有量測準確率。每條關係都附 file:line，可以逐條核對。
