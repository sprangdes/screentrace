# ScreenTrace 介面設計與自檢

## 設計基準

以 Awwwards、Webby Awards、FWA 的作品品質作為設計目標，將辨識度、可讀性與互動完成度用於分析工作台。這是內部自檢，並非獎項認證或評審結論。

參考：[Awwwards 互動網站作品](https://www.awwwards.com/websites/web-interactive/)、[Awwwards 行動體驗指引](https://www.awwwards.com/mobile-excellence-guidelines.pdf)、[Webby 評審準則](https://www.webbyawards.com/judging-criteria/)、[FWA 精選作品回顧](https://thefwa.com/FWA25/RobFWA.html)。

設計概念為 Application Atlas：畫面總覽使用暖白紙面、墨綠標題與來源路徑，流程使用點陣畫布與同步追蹤高亮。識別色只用於選取、焦點與關聯；保留／移除／未確認仍各有文字及獨立狀態色。字型由本機系統提供，報表不需外部字型或動畫服務。

## 八項自檢結果

| 面向 | 完成的改善與檢查 |
| --- | --- |
| 排版 | 品牌、專案名、麵包屑、總覽標題、統計、區塊與來源路徑形成明確順序；路徑採等寬字型，長名稱折行或截斷並保留 tooltip。 |
| 留白 | 標題與內容採一致邊距；卡片間距 20px；詳情採單一抽屜，桌面導覽與內容獨立捲動；密集卡片與長路徑仍可瀏覽。 |
| 視覺層級 | 大字標題、次要說明、小字來源標籤、數字統計與節制卡片陰影；選取畫面具有明確外框；Project APIs / Project UI 為全專案統計，Screens 為目前資料夾及其子資料夾。 |
| 色彩 | 統一暖白、墨色與追蹤綠，移除資料夾輪替的隨機粉彩；修正統計數字繼承舊版淺色文字的問題；狀態不只靠顏色辨識。 |
| 動效 | 總覽與清單採 260ms 小幅進場；按鈕與卡片使用短暫 hover／press 回饋；Page view 不做整頁進場動畫；減少動效設定停用進場動畫。 |
| 微互動 | hover 與鍵盤焦點同步標示關聯；確認狀態循環可用鍵盤操作；修正卡片攔截內部確認按鈕 Enter 的問題；補上熱區名稱、縮圖替代文字、資料夾展開狀態、模式按壓狀態。 |
| 響應式 | 1440 / 1024 / 768 / 390 / 320px 無整頁水平溢位；中尺寸兩欄、手機一欄；窄螢幕詳情置於下方；工具列留在畫布內，避免遮住詳情；觸控控制至少 44px；窄版表格於自身容器捲動。 |
| 原創性 | 以「來源地圖」建立工具本身的視覺語言：路徑、圖節點與證據為主要內容，總覽與流程共享同一套識別；不引入與分析任務無關的裝飾場景。 |

## 驗證

- `mvn -q verify`：54 項測試通過。
- Chromium：Spring MVC JSP 與 Struts fixture 產出的真實報表，檢查總覽、流程、Page view、互動與 API 清單。
- 瀏覽器回歸：5 種寬度，確認狀態循環、模式切換、搜尋空結果、鍵盤操作、觸控版尺寸、減少動效、工具列邊界與 JavaScript 錯誤。
- 壓力自檢：18 張合成卡片、多語系長專案名稱及長路徑；1440 / 768 / 390 / 320px 可捲動且無整頁溢位。
- 截圖覆核後修正：統計文字對比、手機工具列遮擋、確認按鈕鍵盤冒泡，以及資料夾切換後樹狀導覽的捲動位置。

可重跑的瀏覽器檢查（先產生並啟動含畫面與互動元件的 JSP fixture 報表）：

```bash
node screentrace-capture/report-design.test.mjs http://127.0.0.1:8765/report/index.html
```

檢查腳本攔截確認狀態 PUT，避免寫入報表的使用者決策檔。

本次自檢範圍內未發現待修正的明顯排版或操作缺陷。Safari、Firefox、真實行動裝置與大型客戶專案尚未驗證；原始 JSP 預覽的視覺品質取決於被分析專案，不能用工作台樣式改寫。
