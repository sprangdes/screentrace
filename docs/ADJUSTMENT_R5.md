# ScreenTrace 第五輪調整指示（R5）

給 Codex 執行。執行前依 AGENTS.md §10 讀取 `AGENTS.md`、`docs/CODEX_INSTRUCTIONS.md`、`docs/REQUIREMENTS.md`、`docs/ARCHITECTURE.md`、`docs/ROADMAP.md`、`docs/reports/R3.md`、`docs/reports/R4.md`，以及 OPEN_QUESTIONS 中 OQ-015。REQUIREMENTS §1 原文與 §2 決策 D1–D8 不得更動。R3／R4 的「不要做」與「停止條件」仍適用。

## 0. 背景與範圍

R4 完成介面改版。以 petclinic 實測後仍有三個問題，本輪處理：

1. **導覽元件名稱不佳**（OQ-015 擱置的另案）：全站導覽連結顯示為 `find owners`、`home page`、`trigger a RuntimeException to see how it is handled`，以及 `按鈕 1`、`連結 1`，而畫面上的可見文字是 Find owners、Home、Error。
2. **頁面導向被當成 API**：單純換頁的連結在右側欄寫成「呼叫 GET /owners/find」，API 頁也混入 `GET /`、`GET /owners/find` 這類頁面路由，稀釋了後端人員要看的 API。
3. **總覽版面不表達流程方向**：目前是格狀，49 條邊全開時像電路板；需求是看出「從哪個畫面走到哪個畫面」。

本輪**不新增 schema 欄位**。若任何項目證明非加欄位不可，寫 OPEN_QUESTIONS 並停止該項。

### 已查證的事實（可直接利用，請自行再驗證）

- ENDPOINT 節點已有 `attributes.category`：petclinic 中為 `MVC_SCREEN`（17 個，渲染畫面的控制器）與 `REST_API`（2 個：`/vets.json`、`/vets.xml`）。**頁面 vs API 的分類資料已存在，WP22 只是呈現層用它。**
- 導覽元件（來自 `menuItem.tag`）的圖節點屬性只有 `title`／`href`，沒有可見文字；可見文字來自呼叫處 `<petclinic:menuItem ...><span>Find owners</span></petclinic:menuItem>` 的 body，經 `<jsp:doBody/>` 展開，是**靜態可證明的文字**，不需要預覽 DOM 對應。

## 1. 預先授權（同 R4 §0）

改版會使鎖定舊文字／舊結構的斷言失效。授權如下：

1. 只可修改**直接鎖定被取代的呈現文字、結構或排版結果**的斷言（例如「右側欄寫呼叫 GET …」「畫面為格狀座標」）。鎖定資料正確性、證據、安全、決策保存、md 往返、決定性、API 狀態推導的斷言**一律不得修改**。
2. 每處被改的斷言在新 ADR 逐處記錄：測試名稱、舊預期、新預期、原因。
3. 改完後，在**舊實作**上確認新斷言會失敗，結果寫進報告。
4. 無法歸入第 1 點又與新設計衝突者，寫 OPEN_QUESTIONS 並停止該項。

## 2. 工作包

### WP21　元件名稱取自靜態可見文字（OQ-015 另案）

目標：圖中 COMPONENT 的 `name`（及 viewer 顯示標籤）優先使用**靜態可證明的可見文字**。

1. 優先序：可見文字 → `aria-label` → `title` → `name` → `id` → 類型＋序號。
2. 可見文字來源：元素自身的文字內容（含子元素文字，如 `<a><span>Home</span></a>`）；自訂 tag 展開後 `<jsp:doBody/>` 代入的呼叫處 body；`fn:escapeXml(x)`、`<spring:message>` 等包裝：常值可證明者取值，不可證明者視為無文字、退回下一優先序。**不得**以 DOM 順序、文字相似度或專案硬編碼猜配。
3. 文字正規化：去除首尾空白、合併連續空白、截至 40 字並加 `…`；保留原文於 evidence／attributes（例如既有 `title` 屬性不得刪除）。
4. 呼叫處不同的 tag 展開必須各自得到自己的名稱（四個導覽項分別為 Home、Find owners、Veterinarians、Error），來源記錄呼叫處與 tag 定義處（R3 WP17 已有）。
5. 動態文字（含 EL 且不可證明）不得顯示為 `${…}`；退回下一優先序。

驗收：
- 合成 fixture 新測試：tag 屬性帶 `title`、body 帶可見文字、body 為 EL、無文字，各一例；巢狀 tag；同一 tag 被呼叫多次且 body 不同。先提交失敗測試。
- 不得更動既有 graph golden 之外的任何 golden；若 golden 因名稱改變而不同，依 `fixtures/wp10/README.md` 的人工核准流程，在提交說明列出原因、受影響 family 與欄位、前後數量。
- petclinic：四個全站導覽元件分別顯示 Home、Find owners、Veterinarians、Error；不再出現 `按鈕 1`／`連結 1` 型別標籤於導覽元件（其他確實沒有文字的元件仍可用類型＋序號）。

### WP22　頁面導向與 API 的分離（僅呈現層）

目標：後端人員在 API 頁看到的是 API；需求方在畫面右側欄看到的是「前往」而不是「呼叫」。

1. **API 頁分類**：以 `ENDPOINT.attributes.category` 分群。篩選晶片新增 **API（`REST_API` 等非畫面）**／**頁面路由（`MVC_SCREEN`）**／全部，預設為 **API**。表單送出到 `MVC_SCREEN` 的 POST 屬於「頁面路由」群，但在畫面右側欄仍以「送出表單」呈現。其他 category 值（若有）歸入「API」並列出實際值；缺值者歸「未分類」，不得丟棄。
2. 預設隱藏頁面路由時，工具列顯示「另有 N 個頁面路由」並可一鍵切換；統計與篩選數字（使用中／可移除／未被使用）**依目前分群顯示**，總數仍可見。
3. **不得改變**任何 API 使用狀態的推導（使用中／可移除／未被使用）及其共用向量（`docs/examples/api-usage-vectors.json`）與 md 內容。頁面路由仍參與使用狀態與「所有來源都被移除」判定（D4）；本項只改呈現分群，不改判定。
4. **右側欄動作措辭**：
   - 連結／導覽（NAVIGATE，目的為 `MVC_SCREEN` 路由）：只顯示「前往『畫面名稱』」及 URL，**不再**另顯示「呼叫 GET …」。
   - 表單送出：「送出表單 → 路由」。
   - 載入時或元件觸發的 AJAX／REST：「呼叫 API：方法 路徑」。
   - 「API」標籤頁只列真正的 API 呼叫；頁面導向放在「操作」。
5. 畫面右側欄的「API」標籤頁在沒有 API 時顯示空狀態「這個畫面沒有 API 呼叫」，而非列出頁面路由。
6. md 匯出：**內容與格式不變**（維持決策與 API 狀態完整性）。若認為 md 的 API 區也應分群，寫 OPEN_QUESTIONS 提案，不要自行改格式。

驗收：viewer 單元／E2E 測試涵蓋三種群組切換與預設值、統計依群顯示、頁面連結在右側欄只出現「前往」、AJAX 呼叫出現「呼叫 API」；既有 API 狀態與 md 往返測試不改且通過；petclinic 預設 API 頁只剩 `/vets.json`、`/vets.xml`（以實測確認並寫進報告）。

### WP23　流向排版（總覽）

目標：總覽一眼看出主要流程方向，而非格狀擺放。

1. **只用流程邊排版**：全站導覽邊（R3 WP20 已分類）不參與排版；自我迴圈不參與。排版輸入＝畫面節點＋流程邊。
2. **演算法（決定性，同輸入逐位元組相同）**：
   - 入口畫面：無入向流程邊者；若無（全環），取主要 URL 為 `/` 或最短路徑者；仍無則取畫面 ID 排序最前者。
   - 以 DFS 移除回邊（循環）後做最長路徑分層，層由左到右。
   - 同層以重心法（barycenter）排序減少交叉，並以畫面 ID 作為最後決勝，確保決定性。
   - 沒有任何流程邊的畫面放在最右側獨立一欄，標題「未連結的畫面」。
   - 回邊與跨多層的邊在層間空隙走線，不穿越非端點卡片；箭頭方向清楚。
3. **互動**：hover／聚焦某畫面時，其進出邊加深、其餘淡化；顯示全站導覽的切換仍可用，開啟後導覽邊以更淡的樣式疊上，不改變節點位置。
4. 載入時仍自動適合視窗；節點尺寸、檔案結構、搜尋、聚焦視圖不變。
5. 規模保護：節點 >150 或邊 >600 時沿用現行行為不得變慢（R2 WP16 的量測基線：總覽 51ms、聚焦 56ms、搜尋 15ms 等級；超過 3 秒視為失敗）。

驗收：
- 單元測試：線性鏈、分叉、合併、含循環、含自我迴圈、含孤立節點、全環、多入口，各一例；斷言 DAG 邊皆由左指向右（回邊除外）、同輸入兩次座標相同、無邊穿越非端點卡片。
- E2E：petclinic 風格 fixture（合成）上，Find Owners → Owners List → Owner Details → 各表單的 x 座標嚴格遞增。
- 報告列出 petclinic 的交叉數：格狀 vs 流向（以幾何交叉計數）。
