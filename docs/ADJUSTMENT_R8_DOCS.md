# ScreenTrace 第八輪調整指示（R8：使用說明重寫、截圖可重現、CLI 友善失敗）

給 Codex 執行。執行前依 AGENTS.md §10 讀取 `AGENTS.md`、`docs/CODEX_INSTRUCTIONS.md`、`docs/REQUIREMENTS.md`、`docs/ROADMAP.md`、`docs/USER_GUIDE.md`、`docs/reports/R6.md`、`docs/reports/R7.md`。REQUIREMENTS §1 原文與 §2 決策不得更動。前幾輪的「不要做」與「停止條件」仍適用。

## 0. 背景

R3–R7 新增了流向排版、縮圖卡片、完整畫面原型檢視、模擬操作、覆蓋率分類、確定性元件對應。現行 `docs/USER_GUIDE.md` 的問題：

1. **是補丁堆疊的結構**：前面是舊的第 1–10 章，後面把新功能以未編號小節附加（「完整畫面原型檢視（R6）」「離線模擬操作（WP26）」…），章節順序與使用順序不一致。
2. **混入內部術語**：出現 `R6`、`WP26`、`R7`、`ANCHOR`、`UNRESOLVED` 等，需求方看不懂也不需要知道。
3. **內容偏工程**：大量實作細節與限制堆在同一段，沒有「我要完成什麼」導向。
4. **截圖不足且無法重現**：只有 6 張，原型檢視、模擬結果、流向排版、覆蓋率都沒有圖；程式庫裡找不到產生這些圖的腳本，之後改版無法更新。
5. 還留有「截圖說明位置」之類的待辦句子。

另有一個小問題：`analyze`／`report` 在沒有設定檔又沒有互動終端機時會無限等待（或丟出堆疊追蹤），應直接以清楚訊息失敗。

操作報表的是**非工程師的需求方**；操作 CLI 的是分析人員。兩種讀者的文件要分開。

## 1. 預先授權（同 R4 §0）

只可修改**直接鎖定被取代的文件結構或措辭**的斷言（若有）。鎖定安全聲明、資料正確性、決定性、md 往返的斷言一律不得修改；每處在 ADR 逐處記錄並證明新斷言在舊文件上失敗。重寫文件時，下列**必須保留的聲明**不得刪除或弱化：不啟動／不修改被分析專案；模擬不是真實運行、不執行專案腳本、不連線；「未被使用」不等於可刪除；md 附錄 A 不可手動修改；`UNRESOLVED`／`AMBIGUOUS`／`INFERRED` 的意義與處理方式；範例截圖均來自自行撰寫的合成專案。

## 2. 工作包

### WP30　文件重組與重寫

1. **拆成兩份**：
   - `docs/USER_GUIDE.md`：給需求方，只講「如何用報表」。
   - `docs/ANALYST_GUIDE.md`：給分析人員，包含 CLI 指令（config／analyze／report／library validate／import／list／unbind）、元件庫 manifest 綁定與更換流程、報表交付檢查清單（大小、決定性、不含本機路徑）、疑難排解（缺少預覽、context path 未設定、診斷代碼意義、CLI 無互動環境的處理）。原 USER_GUIDE 末尾的「分析人員」段落搬入此檔。
2. **USER_GUIDE.md 重寫為任務導向**，建議章節（可微調，但順序須符合使用流程）：
   1. 這份報表是什麼、能做什麼、不能做什麼（含「模擬不是真實運行」）
   2. 開啟報表與畫面總覽（地圖、縮圖卡片、流向由左到右、全站導覽開關、搜尋、檔案結構）
   3. 查看單一畫面（點卡片 zoom in、完整畫面、縮放、流程視圖、前往的畫面）
   4. 試著操作畫面（操作／檢查模式、點連結、送出表單與候選、彈窗、API 提示、重置、上一頁）
   5. 查看按鈕、API 與來源資訊（右側欄各標籤）
   6. 標記保留／移除／未確認（確認模式、三態、統計、批次、衝突提示）
   7. 查看 API 頁（預設 API、頁面路由、狀態意義、呼叫來源）
   8. 元件庫建議與手動覆寫
   9. 匯出與匯入 md、交給 AI
   10. 如何判斷結果可信（信心標示、覆蓋率三類、「無法確認」的原因、何時請分析人員協助）
   11. 常見問題（FAQ）與詞彙表
3. **文字規範**：
   - 全程使用需求方語言；不得出現 `WP\d+`、`R\d`、`OQ-\d+`、ADR 編號、類別／檔案名稱，以及未經說明的英文列舉（`UNRESOLVED` 等僅在詞彙表與「可信度」章以「中文名稱（英文）」並列出現一次）。
   - 每章開頭一句話說明「你可以在這裡做什麼」；步驟用短句、編號；限制與警語用獨立的「注意」區塊，不混在步驟內。
   - 每個步驟章節至少一張對應截圖；截圖有一句說明，不留「截圖說明位置」之類待辦句。
   - 全文不超過約 250 行；細節（欄位定義、容量、格式）以連結指向 REVIEW_MD_CONTRACT、ANALYST_GUIDE 等。
4. **詞彙表**至少含：畫面、流程（關聯線）、全站導覽、完整畫面、模擬操作、有圖支持的行為、可直接輸入的欄位、無法確認（含「沒有已知的行為」「目的未解析」「有多個候選」）、已確認／依證據推定／未解析／有歧義、使用中／可移除／未被使用、保留／移除／未確認、隨畫面移除、md 附錄 A。
5. 更新 `README.md` 的「調整進度」段落：移除過時敘述，改為簡短現況與兩份指南的連結；`docs/ROADMAP.md` 新增 R8 列（含 R3–R7 的一句話摘要，若尚未記錄）。

驗收：
- 新增文件結構測試：USER_GUIDE 不含上述內部術語模式；含必須保留聲明的關鍵語句（以關鍵詞檢查，列在測試中）；所有 `docs/*.md` 內部相對連結與圖片連結皆存在；行數上限。
- 先提交失敗測試（對舊 USER_GUIDE 會失敗），再重寫。

### WP31　可重現的截圖

1. 新增 `screentrace-viewer/tools/guide-screenshots.mjs`（或同等位置）與 npm script（例如 `npm --prefix screentrace-viewer run guide-shots`）：以**自行撰寫的合成 fixture** 的報表（沿用 WP10 的產物或在腳本內產生），用 Playwright Chromium 固定視窗 1440×900、固定語言與字型設定，自動操作並輸出截圖到 `docs/images/user-guide/`。不得使用 petclinic／eMusicStore 或任何第三方專案內容。
2. 截圖清單（檔名固定，供 USER_GUIDE 引用）：
   - `overview-flow.png`：總覽流向排版（全站導覽隱藏）
   - `overview-global-nav.png`：開啟全站導覽
   - `zoom-viewer.png`：完整畫面檢視器（工具列、URL、縮放）
   - `simulate-link.png`：點連結後前往目的畫面（含上一頁可用）
   - `simulate-submit.png`：表單送出的結果窄條（候選＋可能的伺服器檢核訊息）
   - `simulate-dialog.png`：彈窗開啟
   - `coverage.png`：右側欄的覆蓋率三類與原因分類
   - `inspect-mode.png`：檢查模式的元素樣式／來源
   - `review-mode.png`：確認模式（三態、統計）
   - `api-page.png`：API 主從頁（預設 API，含頁面路由切換）
   - `analysis-info.png`：分析資訊抽屜
   - `library-override.png`：元件庫覆寫
   - 既有 `shell.png`、`preview.png`、`focus-review.png`、`api-details.png` 若被新圖取代則刪除並移除引用，不留孤兒檔案。
3. 腳本須**決定性**：同環境重跑兩次，圖像逐位元組相同；若因動畫或字型載入造成差異，以等待明確條件（不用固定延遲）解決，並在報告說明方法。腳本若遇到不可用的引擎或字型，明確失敗而不是產生空白圖。
4. 圖中不得含本機絕對路徑、使用者名稱、時間戳；以測試檢查（掃描報表 HTML 與截圖旁的文字來源）。
5. 在 ANALYST_GUIDE 說明「改版後如何重新產生截圖」。

驗收：測試確認 USER_GUIDE 引用的每張圖都存在且非空、`docs/images/user-guide/` 內沒有未被引用的圖；腳本在 CI 指令中不被要求執行（避免環境差異），但報告須附實際執行結果與兩次輸出一致的證明。

### WP32　CLI 在無互動環境下友善失敗

1. 現況：缺少設定檔時，`analyze`／`report`／`library` 等指令會啟動互動提問；在沒有互動終端機（標準輸入已關閉或非 TTY）時，丟出 `EndOfFileException` 堆疊追蹤，或在標準輸入保持開啟時無限等待。
2. 要求：偵測無互動環境（標準輸入非終端機，或 jline 取得 dumb terminal）且需要提問時，**立即以中文訊息失敗**並說明如何設定（「尚未設定專案根目錄與輸出根目錄。請先在終端機執行 `./bin/screentrace config`」），結束碼非 0（建議 2），不輸出堆疊追蹤。已有完整設定時行為不變。
3. 先提交失敗測試：以子行程啟動 CLI，分別測試標準輸入為 `/dev/null`、為保持開啟且無資料的管道（需有逾時保護，測試本身不得卡住）、為互動模擬（若現有測試已有）；斷言訊息與結束碼，且在設定存在時照常執行。
4. 不改設定檔格式與互動流程本身（互動模式下行為不變）。

- 不弱化「必須保留的聲明」；不為了簡短而刪除限制。
- 不新增外部相依或網路資源。
- WP31 完成後不得自行進入 WP32。
