# ScreenTrace 第十二輪調整指示（R12：版面精修、名稱與說明更好懂）

給 Codex 執行。執行前依 AGENTS.md §10 讀取 `AGENTS.md`、`docs/CODEX_INSTRUCTIONS.md`、`docs/REQUIREMENTS.md`、`docs/ROADMAP.md`、`docs/USER_GUIDE.md`、`docs/reports/R10.md`、`docs/reports/R11.md`。REQUIREMENTS §1 原文與 §2 決策不得更動。R3–R11 的「不要做」與「停止條件」仍適用（特別是 R11：不得新增任何「模式」或全域開關）。

## 0. 背景

R10、R11 完成後，功能已齊備。需求方選定本輪兩個方向：**版面精修**、**名稱與說明更好懂**。以下問題均由審查者在 petclinic 報表（Chromium、1440×900）實際觀察：

**版面**
1. 頂部列右側擠了 8 個控制項：搜尋、確認進度、下一個未確認、?、匯出 md、匯入、分析資訊，再加上中間的「畫面｜按鈕｜API」。違背「簡潔」。
2. 總覽「適合視窗」後，整張圖只佔畫布約一半，四周留白多，卡片與名稱偏小（名稱約 8px）。
3. 右側欄寬度固定且偏窄，流程大綱、觸發按鈕說明常折成 3–4 行。
4. 首次引導卡片固定在右下角，會蓋到總覽右下角的縮放按鈕。
5. 左側欄的「確認統計」文字與頂部進度、確認儀表板重複顯示相同數字。

**名稱與說明**
6. 沒有文字的元素顯示為「按鈕 1」「連結 1」「下拉選單 1」，需求方無法分辨是哪一個（例如導覽列的品牌標誌連結、漢堡選單按鈕）。
7. 表單名稱與流程大綱的觸發說明出現技術資訊，例如「表單（畫面 Create Or Update Owner Form，第 13 行）」、標籤直接用元素 id「search-owner-form」。
8. 信心與狀態用語不一致：同一個意思出現「依證據推定」「靜態推定」，以及「已確認」「已由來源確認」。
9. 只有圖示的按鈕（＋、－、適合視窗、返回、上一頁、下一頁、⋯）部分沒有滑過提示文字。

## 1. 預先授權（同 R4 §0）

只可修改**直接鎖定被取代的版面、控制項位置或顯示文字**的斷言。鎖定資料正確性、證據、安全、決策保存格式與鍵、md 內容與往返、決定性、API 狀態推導、模擬規則結果的斷言一律不得修改。每處在新 ADR 逐處記錄（測試名稱、舊預期、新預期、原因），並證明新斷言在舊實作上失敗。無法歸入者寫 OPEN_QUESTIONS 並停止該項。

## 2. 硬性原則

1. 只改 viewer 的呈現與互動。不改分析器、graph schema、模擬規則、API 狀態推導、決策資料模型、md 格式與內容。
2. **元件在圖中的 `name` 不變**；本輪的「顯示名稱」是 viewer 內由既有資料機械推導的呈現名稱。md 繼續使用圖中的名稱（若認為 md 應改用顯示名稱，寫 OPEN_QUESTIONS 提案，不要自行修改）。
3. **不猜**：顯示名稱只能用元素本身與其靜態 DOM 位置可證明的資訊；**不得依 CSS class 名稱推測用途**（例如不能因為 class 是 `navbar-toggler` 就叫它「選單切換」）。
4. 資訊只能移動，不能消失：被收進選單或摺疊的控制與資訊都必須仍可到達（含鍵盤）。
5. 單一 HTML、離線、決定性、不含本機路徑；報表大小增幅不超過 3%；指南截圖產生器維持逐位元組決定性。
6. 不新增任何模式或全域開關。

## 3. 工作包

### WP41　版面精修

**1. 頂部列整併**（右側最多 4 個可見控制項）：

```text
ScreenTrace · 專案名   [ 畫面 | 按鈕 | API ]         [🔍 搜尋 ⌘K]  [已確認 23／78 ▸]  [匯出 md]  [⋯]
```

- 「搜尋」保留，按鈕上顯示快捷鍵提示（macOS 顯示 ⌘K，其他平台 Ctrl+K）。
- 「確認進度」與「下一個未確認」合併為一個分段按鈕：左半點開確認儀表板，右半「▸」為下一個未確認（`n` 仍可用）。
- 「匯出 md」維持主要按鈕。
- 「⋯」選單收納：匯入 md、分析資訊（顯示診斷數量）、說明（?）、重新開啟引導。選單可用鍵盤操作，選單項目有圖示與文字。
- 1024px 以下時，「搜尋」縮為圖示，「確認進度」縮為「23／78」，仍不得逐字折行或溢出。

**2. 總覽適合視窗**：以所有可見卡片與關聯線的外框計算縮放與置中，四周留白固定（例如 24px），縮放上限 1.0。petclinic 這類 10 個畫面的專案，適合視窗後內容在寬或高至少一個方向佔畫布可用空間 ≥ 85%。切換「顯示全站導覽」、篩選區域或視窗改變大小後重新適合。

**3. 右側欄可調寬**：欄左緣有拖曳把手，寬度範圍 300px 至視窗寬 50%；鍵盤可聚焦把手並以方向鍵調整；寬度存於瀏覽器暫存（讀寫包在 try/catch，暫存不可用時使用預設寬）。另有收合按鈕，收合後主區使用全寬。

**4. 首次引導卡片**：不得覆蓋任何可互動控制項。改為貼近當前步驟所指的區域顯示（附小箭頭），或置於頂部列下方的中間；以測試保證其外框不與任何按鈕、輸入框、縮放控制重疊。「略過」與完成後不再自動出現（暫存不可用時，同一次瀏覽內不重複出現）。

**5. 去除重複統計**：左側欄只保留狀態篩選晶片（全部／未確認／保留／移除／隨畫面移除，含數量），移除重複的「確認統計」文字；完整統計在確認儀表板。

**驗收（WP41）**：
- E2E：頂部列右側可見控制項 ≤ 4；「⋯」選單內能到達匯入、分析資訊、說明、重新開啟引導（滑鼠與鍵盤各一次）；分段按鈕兩半各自作用；1024px 以下不溢出。
- 總覽：以 petclinic 風格合成 fixture 斷言適合視窗後內容佔比 ≥ 85%（寬或高其一），切換全站導覽後重新適合。
- 右側欄：拖曳與鍵盤調寬、範圍限制、重新載入後保留、暫存不可用時使用預設、收合與展開。
- 引導卡片外框與所有互動控制項不重疊。
- 左側欄不再出現「確認統計」重複文字，篩選晶片數字與儀表板一致。
- **WP41 完成後停止**，等需求方檢視。

### WP42　名稱與說明更好懂

**1. 元素顯示名稱**（viewer 內單一純函式，決定性，可單元測試），優先序：

1. 可見文字（含子元素文字、`jsp:doBody` 已展開者）
2. `aria-label`
3. `title`
4. 內含圖片的 `alt`（例如品牌標誌圖片的 alt）
5. 按鈕／輸入的 `value`
6. 表單：表單內第一個標題（`legend`、`h1`–`h4`）或其提交按鈕的文字，組成「Find Owners 表單」「New Owner 表單」
7. `name`／`id` 人性化（`search-owner-form` → 「Search Owner Form」），並加上類型字尾（「Search Owner Form 表單」）
8. **位置描述**：「<類型>（位於 <最近的區塊>）」，最近的區塊依靜態 DOM 祖先判定：`nav` → 導覽列、`header` → 頁首、`footer` → 頁尾、`form` → 「<表單顯示名稱>」內、最近的標題文字 → 「<標題> 區塊」；若有已知的導覽目的，再加「，前往 <畫面名稱>」
9. 以上皆無：「<類型>（無文字）」

規則：不得依 CSS class 推測用途；不得出現「按鈕 1」這類純序號名稱，除非同一畫面有多個元素在第 1–9 項全部相同，才在名稱後加「（第 n 個）」以區分。

**2. 去除技術資訊**：主要標籤、流程大綱的觸發說明、按鈕總表與搜尋結果中，不得出現行號、檔案路徑、元素 id 原文；這些移到「技術細節」。

**3. 用語統一**：建立單一用語字典模組（例如 `terms.ts`），所有需求方可見的狀態與信心用語只從這裡取：
- 信心：已確認、依證據推定、未解析、有歧義（移除「靜態推定」「已由來源確認」等變體）。
- 決策：保留、移除、未確認、隨畫面移除。
- API 狀態：使用中、可移除、未被使用。
- 其他重複出現的詞（全站導覽、無法確認、有圖支持的行為等）。
加一個 lint 型測試：掃描 `screentrace-viewer/src`，禁止上述變體字串出現在字典以外的地方。

**4. 圖示按鈕提示**：所有只有圖示的按鈕都有 `aria-label` 與滑過提示（＋放大、－縮小、適合視窗、返回總覽、上一頁、下一頁、更多選項、收合右側欄等）。以測試掃描 DOM 中所有無文字按鈕必須有可存取名稱。

**5. 文件**：更新 `docs/USER_GUIDE.md`（新頂部列、右側欄調寬、名稱說明），維持精簡與所有必須保留的聲明；更新 `guide-shots` 與受影響截圖（維持逐位元組決定性，移除孤兒圖）。

**驗收（WP42）**：
- 單元測試：顯示名稱函式涵蓋第 1–9 項各至少一例、同畫面重名加「（第 n 個）」、不依 class 推測（給一個只有 `class="navbar-toggler"` 的按鈕，結果必須是位置描述而非「選單切換」）。
- E2E／DOM：petclinic 風格合成 fixture 中，任何畫面的按鈕清單、按鈕總表、搜尋結果、流程大綱不得出現符合 `/^(按鈕|連結|下拉選單|表單|文字欄位) \d+$/` 的名稱，也不得出現 `第 \d+ 行`；用語 lint 通過；所有圖示按鈕有可存取名稱。
- md 匯出內容與本輪之前逐位元組相同（用既有 md 往返 fixture 鎖定）。
- **WP42 完成後停止**。

## 4. 測試與報告

每個工作包提交前執行完整驗證（指令同 R3 §5，E2E 用預設並行，不得改成序列執行來規避不穩定）；基線以 R10 結束時為準（284 Java、40 JS、104 viewer、43 capture、113 E2E），只增不減（被授權修改的斷言除外）。

報告 `docs/reports/R12.md`：各 WP 狀態與提交；被授權修改的每處斷言（對應 ADR）及其在舊實作上失敗的證明；報表大小前後；**以 petclinic 實際重新分析並開啟報表的觀察**（1440×900 與 1024×768：頂部列、總覽適合視窗、右側欄調寬、引導卡片、各畫面的元素名稱前後對照表——特別列出原本叫「按鈕 1」「連結 1」「下拉選單 1」「search-owner-form」「表單（…第 13 行）」者現在的名稱）；截圖產生器連跑至少 3 次逐位元組一致；所有數字來自一次實際執行並註明命令。未驗證不得寫成已完成。

- 不新增模式或全域開關；不隱藏資訊。
- 不新增外部相依或網路資源；不複製真實專案內容、截圖或輸出進 repo。
