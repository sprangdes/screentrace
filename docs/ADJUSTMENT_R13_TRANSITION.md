## 0. 需求方回報的問題

> 在畫面上點擊功能後，畫面會有一個展開的動畫，然後切成下一個畫面，感覺很奇怪。

## 1. 審查者已確認的現況（petclinic，Chromium，1440×900）

操作：在「Owner Details」完整畫面中點「Edit Owner」連結（模擬導覽到「Create Or Update Owner Form」）。以 Web Animations API 讀出的實際參數：

| 項目 | 實測 |
|---|---|
| 觸發位置 | `simulation-ui.ts` 導覽時呼叫 `options.focus(target)`；`main.ts` 的 `attachSimulation` 回呼把**目前預覽的外框**當作 `transitionFrom` 傳給 `focus()`，於是走進 `prototype.ts` 的 `transition()`（原本設計給「總覽卡片 → 完整畫面」的 zoom） |
| 舊畫面 | 點擊當下立刻被移除（DOM 只剩新的 iframe） |
| 新畫面 | 立即建立，但 `opacity: 0` 隱藏到動畫結束 |
| 動畫主體 | 一個「幽靈」元素，內容是**目的畫面的縮圖**（640×400 PNG，只截頂部一屏），被拉大到約 1028×643 顯示，明顯模糊 |
| 動畫起訖 | 起點＝舊預覽外框 (80,338,1028×643)；終點＝**整個主區** (56,188,1076×712)，覆蓋到工具列與標題區。關鍵影格 `translate(24px,212px) scale(0.955, 0.902)` → `none`，**X／Y 縮放比例不同**（非等比，畫面會被拉扁） |
| 時間 | 300ms，`cubic-bezier(.2,.8,.2,1)` |
| 結束 | 幽靈直接移除、新預覽瞬間變成 `opacity: 1`（**沒有淡入**）；幽靈停在主區中央，真正的預覽在工具列下方 (80,338)，**兩者位置不同，結束時會跳一下** |

因此使用者看到的是：舊畫面瞬間消失 → 一張模糊、被輕微拉扁的目的縮圖從舊畫面的框往外「長大」到蓋住整個主區（含工具列） → 300ms 後硬切成清晰的真正畫面，而且位置往下跳。

根本問題有兩層：
1. **語意錯誤**：「zoom 展開」是為了表達「從地圖上的這張卡片放大進去」，有空間上的來源。在完整畫面裡點連結換頁，沒有任何空間來源，套用 zoom 只會讓人覺得奇怪。
2. **實作缺陷**（即使在卡片 → 畫面的情境也存在）：終點是主區而不是真正預覽的位置、非等比縮放、用低解析縮圖、結束時硬切且位置不一致。

## 2. 預先授權（同 R4 §0）

只可修改**直接鎖定被取代的切換動畫行為**的斷言（例如「導覽時存在 `.prototype-transition`」「`data-transition` 的狀態序列」）。鎖定資料正確性、安全、決策、md、決定性、模擬規則結果、歷史（上一頁／下一頁）行為的斷言一律不得修改。每處在新 ADR 逐處記錄並證明新斷言在舊實作上失敗。

## 3. 設計

### 3.1 兩種切換，各用各的動畫

| 情境 | 動畫 |
|---|---|
| **總覽卡片 → 完整畫面**（以及「返回總覽」的反向） | 保留 zoom，但修正實作（§3.2） |
| **完整畫面內換頁**：模擬點連結、表單送出後選擇結果、「可前往的畫面」清單、上一頁／下一頁、流程大綱節點、全域搜尋跳轉、確認儀表板「下一個未確認」、按鈕總表點列跳轉 | **不用 zoom**。改用短暫淡入淡出（§3.3） |

### 3.2 卡片 zoom 的修正

1. 終點必須是**新畫面預覽實際會出現的外框**（工具列下方、適合寬度後的位置與大小），不是整個主區。先完成新畫面的版面計算（含 fit 縮放）再取外框，必要時等一個 frame。
2. **等比縮放**：只用單一 scale；寬高比不同時，以 `object-fit: cover` 搭配裁切（clip-path 或 overflow hidden）處理，不得拉扁或拉長。
3. 結束時**淡入交接**：幽靈與真正預覽重疊在同一位置，幽靈在 120ms 內淡出、預覽同時淡入，不得出現「位置跳動」或「瞬間換圖」。
4. 新預覽尚未載入完成時（iframe `load` 前），幽靈停在終點等待，載入完成再交接；設逾時（例如 1.5 秒）後直接交接並顯示既有「載入預覽…」占位，不得無限等待。
5. 縮圖解析度不足以放大到終點尺寸時，動畫期間可接受模糊，但交接後必須是清晰的真正預覽。
6. 反向（返回總覽）沿用同一套規則：從目前預覽外框等比縮回卡片位置，結束後淡出。

### 3.3 畫面內換頁

1. 點擊後，被點的元素先有 80–120ms 的按下回饋（沿用既有選取外框或加淡色），然後開始換頁。
2. **舊畫面保持可見**，直到新畫面的 iframe 載入完成；不得出現「舊畫面已消失、新畫面還沒出現」的空白期。新畫面載入時間超過 300ms 時，在預覽區上方顯示細進度條或「載入中…」，舊畫面略微變淡（例如 opacity 0.6）表示正在切換。
3. 新畫面就緒後，以 **150ms 交叉淡入淡出**切換（舊畫面淡出、新畫面淡入於同一位置），不縮放、不位移。捲動位置：前往新畫面時回到頂部；上一頁／下一頁回到記錄的捲動位置（沿用既有歷史行為）。
4. 工具列的 URL、畫面標題、上一頁／下一頁狀態在交接時同步更新，不得先跳後換。
5. 不建立 `.prototype-transition` 幽靈元素，不使用縮圖。
6. 連續快速點擊（前一次切換未完成又點下一個）時，取消前一次切換，只完成最後一次；不得同時存在兩個 iframe 或殘留半透明狀態。

### 3.4 共通

- `prefers-reduced-motion: reduce` 時兩種情境都**不做動畫**：卡片 → 畫面直接顯示；畫面內換頁直接替換（仍需遵守「舊畫面保持可見直到新畫面就緒」）。
- 所有動畫用 Web Animations API 或 CSS transition，結束狀態由程式明確設定，不依賴動畫結束事件才恢復互動（避免動畫被中斷時卡在 `opacity: 0` 或 `pointer-events: none`）。
- 動畫期間不得阻擋鍵盤操作；Esc 仍能返回總覽或關閉彈窗。

## 4. 工作包

### WP43　畫面切換動畫重做

依 §3 實作。先提交失敗測試，再修正。

驗收（E2E，Chromium，預設並行執行）：
1. **畫面內換頁不使用 zoom**：在完整畫面中觸發模擬導覽、上一頁／下一頁、可前往的畫面、搜尋跳轉、下一個未確認，任何時刻都不存在 `.prototype-transition`，也沒有對預覽套用 `scale` 的動畫。
2. **沒有空白期**：從點擊到新畫面就緒的每個取樣時點（以 `setInterval` 或攔截 iframe `load` 時序，不依賴 requestAnimationFrame，背景分頁也要可測），至少有一個預覽為可見（opacity > 0）。
3. **交叉淡入淡出**：新舊預覽同時存在的期間 ≤ 200ms，結束後只剩一個 iframe，且 opacity 為 1、`pointer-events` 恢復。
4. **連續點擊**：在切換未完成時再觸發一次導覽，最終只顯示最後一次的目的畫面，只剩一個 iframe，沒有殘留半透明。
5. **卡片 zoom**：關鍵影格的 X、Y 縮放比例相等（誤差 ≤ 0.01）；終點外框與交接後真正預覽外框的差距 ≤ 2px；交接期間幽靈淡出與預覽淡入重疊，不出現預覽瞬間由 0 跳到 1；新預覽未載入時幽靈會等待，逾時後交接。
6. **reduced motion**：兩種情境都沒有任何動畫物件（`document.getAnimations()` 為空）。
7. 既有的模擬、歷史、捲動位置還原、零網路請求、零 script 執行等測試全部維持通過。

另外：
- 以 petclinic 唯讀重新分析並實際開啟報表，在 `docs/reports/R13.md` 記錄：點「Edit Owner」、表單送出後選結果、上一頁、從總覽點卡片、返回總覽，各自的動畫參數（以 `getAnimations()` 讀出）與主觀描述；所有數字來自實際執行。
- 指南截圖產生器維持逐位元組決定性（截圖不應受動畫影響；若受影響，截圖前等待切換完成的明確條件）。
- `docs/USER_GUIDE.md` 若有描述切換動畫，同步更新。
