# ADR 0016：歷史報表入口與正式 schema 退場

## 背景與選項

OQ-006：舊報表／JSON 匯出測試使用歷史 2.1 圖，schema 2.2 強制入口會破壞既有成功行為。選項 A 遷移 fixture，B 保留即將由 WP7／WP8 取代的歷史入口。需求方採 B，禁止更動既有 fixture 與斷言。

## 決定

ReportGenerator、ReviewResultGenerator 標 @Deprecated，註解明定分別在 WP7／WP8 隨舊測試移除。歷史輸入的 HTML／JSON 輸出列出 schema 版本與「歷史資料,未經 2.2 證據驗證」。2.2 報表仍使用嚴格 validator；舊 2.1 入口保留原驗證／成功行為，不冒充嚴格證據。

此例外僅限歷史入口。WP7 新檢視器資料注入、WP8 md 匯出與新共用模組必須用 requireAnalysis 的版本與嚴格驗證門檻；其他版本清楚失敗。靜態測試枚舉現有報表公開 write 入口，必須恰為兩個 Deprecated 類別；新入口不得承接此例外。

正式 adapter 全部使用完整八參數建構子與明確 2.2；輸出回傳時嚴格驗證。Spring Boot 在來源產生處補上自己的 parser 證據與元件種類，保留原信心與實際來源；不是對歷史圖事後更名升版。CLI 在呼叫歷史報表前強制新分析 2.2。靜態測試掃描全部正式 Java 來源，禁止呼叫歷史 ApplicationGraph 建構子。

合併嚴格 2.2 圖仍為 2.2，且輸入／輸出均驗證。混合版本拒絕；兩份明確 2.1 歷史圖保留 2.1 並附 HISTORICAL_SCHEMA 診斷，採 OQ-005 已授權的「明確標示歷史資料」選項，保留既有合併測試。缺證據的 2.2 圖拒絕，不再混合降版。

同 ID 行為的觸發者／事件／種類／條件／父行為／運算式須一致；證據合併，結果不同時 targetId=null，候選皆留證據。CLI 在合併後重跑共用 URL 引擎，不擇一。已對應的前端暫時描述及其相同 URL／method 呼叫邊移除，避免混合分析重複列 API；其他呼叫來源仍保留。

## 後果

依新增通則，預定後續工作包取代的舊程式不投資測試遷移，先用標示明確的相容入口維持行為；只有需放寬長期保留程式斷言的衝突才再停問。移除歷史報表／JSON 入口與原測試，分別列為 WP7／WP8 驗收。

本次**既有測試、fixture、斷言修改清單：無**，包含任何 schema 版本字串均未修改。新增 SchemaProductionTest、ProductionSchemaTest、HistoricalSchemaEntryTest；先確認拒絕／標示／版本／淘汰標記測試失敗，再實作。完整測試亦發現混合行為重複貢獻與暫時 API 未清理，保留所有斷言並修正。無新增相依。
