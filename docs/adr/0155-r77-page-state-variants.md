# ADR 0155：R77 頁面狀態拆成畫面變體（OQ-052）

## 背景

reservio 的顧客預約精靈 `/reservation/new` 以元件狀態 `useState<Step>(1)` 切換三個步驟，按鈕呼叫 `moveToStep(2)`／`moveToStep(3)`，時段衝突時直接 `setStep(2)`。網址不變，所以只算一個畫面：

- 圖：第 2、3 步的元件與 API 都有記錄，帶 `step===2` 等條件，全部歸在同一個畫面。
- 預覽：依 ADR 0103，`step` 取初始值 1，只畫第 1 步。
- 模擬：「下一步」只寫入狀態，沒有導覽或 API 行為，點了沒有反應，走不到第 2、3 步。

需求方 2026-11-18 決定（OQ-052）：步驟成為畫布上的子畫面；各步驟的 API 歸到該步驟。

## 決定

1. **哪些狀態會拆**（`screentrace-js/react/state-variants.mjs`），不依變數或函式名稱判斷，以下條件都要成立：
   - 路由內元件以常值初始化的 `useState`，可能值依 ADR 0105 可證明：初始值加上所有常值寫入（含經由區域函式參數的寫入），沒有未知寫入。
   - 可能值都是字串或數字，2～8 個。
   - 把狀態固定成各個值分別渲染，出現的元件不同。
   - 至少有一個只在部分值出現的元件，在使用者事件中把狀態寫成另一個值。分頁（tab）的按鈕在每個值都出現，不符合這一條，維持一個畫面。
   - 同一路由有一個以上的狀態符合時不拆，記 `REACT_STATE_VARIANTS_MULTIPLE` 診斷。
2. **變體**：每個值各渲染一次（圖與預覽都把狀態固定成該值），與身分變體、查詢參數變體相乘。初始值的變體沿用原畫面 ID，既有決策不受影響；其他值的 ID 為原 ID 加上 `:state:<名稱>=<值的 JSON>`。
3. **SCREEN 屬性**：`stateVariant`（如 `step = 2`）、`stateVariantName`、`stateVariantValues`；非初始值另有 `stateVariantOf`（初始值變體的 ID）。畫面名稱加上「（step = 2）」，證據記錄可能值、初始值與寫入點。路由唯一性檢查（Java `GraphIntegrityValidator`、viewer `strictGraph`）把 `stateVariant` 併入鍵。
4. **導覽**：使用者事件中把狀態寫成另一個值（直接呼叫 setter，或經由函式）記為 `NAVIGATE`，`stateTransition` 標明狀態與值，目標是同一路由、同一身分變體下該值的畫面，產生 `NAVIGATES_TO` 邊。寫入相同值與 `useEffect` 中的寫入不記。
5. **進入**：網址只開啟初始值。只有初始值變體有入口的 `RENDERS` 邊、列入依路由找畫面的候選；其他頁面的連結、轉址與角色流程的起點都指向初始值，其他步驟只能從畫面內走到。
6. **API 歸屬**：各步驟的元件只在自己的變體出現，API 跟著元件歸到該步驟。其他步驟才出現的元件不列入「此身分下不顯示」。
7. **viewer**：有 `stateVariant` 的畫面在顯示名稱後加「（step = 2）」。

## 影響

- Graph schema 版本不變；SCREEN 多了上述屬性。
- 不符合條件的專案輸出不變：原有 JS 191 個測試與 Maven 測試都不需修改。
- 以函式形式更新（`setStep(s => s + 1)`）、`useReducer`、值來自 API 回應的狀態不拆，維持 ADR 0089／0103 的單一預覽。
- 每個符合條件的候選狀態在偵測時要多渲染「值的個數」次；只有常值寫入的狀態才是候選。

## 驗證

- `StateVariantTest`（Maven）：三個步驟各為一個畫面，第 1 步沿用原 ID；「下一步」與衝突處理指向正確步驟；首頁連結只指向第 1 步；只有第 1 步有 RENDERS；送出的 API 歸第 3 步；分頁維持一個畫面。
- `r77-state-variants.test.mjs`（JS）：各步驟的預覽只畫該步驟；寫入成為指向該步驟的導覽；函式形式更新、分頁、無法求值的寫入不拆；兩個狀態都符合時記診斷不拆；其他畫面的連結只開啟第 1 步。
- `r77-state-variant-name.test.mjs`（viewer）：三個步驟的顯示名稱各帶狀態值。
- reservio 實測需由需求方在 sandbox 外執行。
