# ADR 0127：R36 放大畫面的關聯線標籤對齊與預覽比例

## 背景

R35（ADR 0126）把放大畫面的關聯線改成左進右出、依區塊合併後，需求方在 reservio 的「LINE 整合」畫面看到三個問題：

1. 標籤寬度各自不同：合併線的標籤靠外側對齊、依文字長短變寬，單一畫面的標籤又是另一種寬度，兩側看起來不一致。
2. 單一畫面的線仍從畫布邊緣畫到預覽框（或從預覽框畫到畫布邊緣），標籤蓋在線上；出去的線箭頭在最外側，被標籤遮住。
3. 左右留白加寬到 176px 後，預覽框在側欄打開時變得接近正方形，畫面不像一般電腦螢幕。

## 決定

- R36-1：有標籤時，每一列都有標籤（區名加數量，或單一畫面的名稱），寬度一律填滿該側留白、只留 28px（`LABEL_GAP`，R36-5 改為 20px）給線與箭頭；文字靠左，放不下以省略號結尾，滑過以 `title` 顯示全名。
- R36-2：所有的線都從標籤內側邊緣畫到預覽框，或從預覽框畫到標籤內側邊緣；箭頭停在標籤之前，不再被遮住。沒有標籤時（沒有合併線），單一畫面的線維持從畫布邊緣起訖。
- R36-3：預覽框的高度不超過寬度 ÷（1440／900），也就是 16:10 的桌機螢幕比例；多出的高度平均留在上下。寬度不受影響，畫面比例較寬時維持原樣。
- R36-4：線寬仍依 ADR 0126 R35-2 隨合併的畫面數增加，單一畫面的線寬不變。
- 只改 viewer 的程式、樣式、測試與文件；分析與 graph JSON 不變。

### R36a（同一 PR 的追加修正）

R36-3 上線後，需求方指出預覽在側欄打開時變得太小：預覽的大小受畫布寬度限制，兩側各 176px 的標籤留白占掉了寬度。需求方選擇縮窄標籤留白（另一個選項是放大時自動收起右側欄，未採用）。

- R36-5：取代 ADR 0126 R35-4 的固定 176px。有合併線時，每一側的留白依該側最寬的標籤在一行內所需的寬度決定（以 canvas `measureText` 量測文字，畫線前就能算出預覽框），加上外側 8px 與 `LABEL_GAP` 20px，最寬 140px（`LABEL_SIDE_MAX`）；沒有線的一側維持 56px。同一側的標籤仍同寬（R36-1）。
- R36-6：放不下時，畫面名稱換到第二行，兩行仍放不下才以省略號結尾；區名（網址）維持一行，放不下以省略號結尾，不在字中間斷行。



兩側標籤排成整齊的兩欄，所有箭頭都看得到；預覽保持桌機比例，代價是側欄打開、畫布較窄時預覽框上下會有留白；R36a 縮窄標籤留白後，同樣的視窗下預覽約寬 6–9%，較長的名稱改為兩行或省略。
