# ADR 0065：WP42 易懂的元件名稱與說明

## 背景

檢視器在元件清單、按鈕總表、搜尋結果、流程大綱及關聯提示中，會顯示解析器產生的內部名稱或純序號名稱。需求方難以辨認這些項目。WP42 只改檢視器呈現名稱；圖中的元件 `name`、分析證據、決策鍵及 md 契約保持原樣。

## 決定

以 `labels.ts` 的純函式，依固定優先序從可見文字、ARIA 標籤、標題、圖片替代文字、按鈕值、表單標題、屬性名稱與靜態 DOM 位置產生呈現名稱。位置只依標籤祖先和標題判斷，不使用 CSS class。已知目的畫面可附在名稱後；同畫面重名才加序號。狀態、信心與 API 狀態用語集中在 `terms.ts`。

左側畫面列的三態標記控制預設隱藏，在滑過、鍵盤焦點或觸控長按時顯示；已決定項目保留狀態圖示。按鈕仍可單擊標記，原有鍵盤操作與決策寫入邏輯不變。

## 測試先行與斷言調整

新測試先於實作加入。舊版呈現邏輯下，名稱優先序測試無法從靜態 DOM 得到可讀名稱；按鈕表格與流程大綱仍顯示圖中 slug／序號名稱；左側決策控制在靜止狀態仍可見，分別違反新名稱與收合規格。新測試已在舊行為上重現這些差異，再以同一顯示名稱函式與互動樣式修正。

因為名稱屬於本次明確取代的呈現文字，以下既有顯示預期依 R12 §2 授權更新；資料、決策、安全、來源與輸出斷言未改：

| 測試 | 舊預期 | 新預期 | 原因 |
|---|---|---|---|
| `r4-labels.test.mjs`，無文字連結 | `連結 3` | `連結（無文字）` | 不再以純序號命名。 |
| `r5-names.test.mjs`，無文字連結 | `連結 1` | `連結（無文字）` | 不再以純序號命名。 |
| `wp38-flow-outline.test.mjs`，無可讀按鈕名稱 | `按鈕（畫面 Create Or Update Owner Form，第 13 行）` | `按鈕（位於 Create Or Update Owner Form 畫面）` | 以已知靜態位置描述，不把來源行號當名稱。 |
| `wp38-flow-outline.test.mjs`，無可讀連結名稱 | `連結（畫面 Find Owners，第 9 行）` | `連結（位於 Find Owners 畫面）` | 同上。 |
| `wp38-flow-outline.test.mjs`，流程按鈕觸發名稱 | `按鈕（畫面 Owner Information，第 8 行）` | `按鈕（位於 Owner Information 畫面）` | 流程觸發名稱沿用同一規則。 |
| `wp36-button-feedback.test.mjs`，動作列排序 | `Alpha`、`Zulu` | `Alpha 連結`、`Zulu 連結` | 同名需帶上元素類型以利辨認，排序仍依名稱。 |
| `wp38.e2e.mjs`，呈現流程觸發項 | 含 `第 9 行` 的連結 | `連結（位於 Find Owners 畫面）` | 不把來源行號作為需求方名稱。 |
| `wp38.e2e.mjs`，收合流程大綱的 DOM 顯示 | 收合時已建立所有流程節點 | 收合時節點尚未建立；展開後建立 | 延後建立收合中的流程內容，避免初始畫面處理未顯示資訊；展開後節點與內容不變。 |
| `wp20.e2e.mjs`，搜尋顯示名稱 | `search` | `Search` | 將可讀屬性名稱人性化。 |
| `api.e2e.mjs`，呼叫來源按鈕 | 原始呼叫元件名稱 | `Owner Information › 按鈕（位於 Owner Information 畫面）` | 呼叫來源也統一使用顯示名稱。 |

其中最後一項測試定位 API 呼叫者並驗證可點擊跳轉的行為不變，只更新按鈕顯示文字。

## 後果

不同區域共享同一套顯示名稱推導，避免畫面詳情、按鈕表格、搜尋和流程大綱各自產生不同叫法。若缺少可證明的可讀值，回退為「類型＋位置」或「類型（無文字）」，不依 CSS class 猜用途。使用者仍能在技術細節查看原始名稱與來源。
