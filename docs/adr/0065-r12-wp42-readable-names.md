# ADR 0065：WP42 易懂的元件名稱與說明

## 背景

檢視器在元件清單、按鈕總表、搜尋結果、流程大綱及關聯提示中，會顯示解析器產生的內部名稱或純序號名稱。需求方難以辨認這些項目。WP42 只改檢視器呈現名稱；圖中的元件 `name`、分析證據、決策鍵及 md 契約保持原樣。

## 決定

以 `labels.ts` 的純函式，依固定優先序從可見文字、ARIA 標籤、標題、圖片替代文字、按鈕值、表單標題、屬性名稱與靜態 DOM 位置產生呈現名稱。位置只依標籤祖先和標題判斷，不使用 CSS class。已知目的畫面可附在名稱後；同畫面重名才加序號。狀態、信心與 API 狀態用語集中在 `terms.ts`。

左側畫面列的三態標記控制預設隱藏，在滑過、鍵盤焦點或觸控長按時顯示；已決定項目保留狀態圖示。按鈕仍可單擊標記，原有鍵盤操作與決策寫入邏輯不變。

## 測試先行與斷言調整

新測試先於實作加入。舊版呈現邏輯下，名稱優先序測試無法從靜態 DOM 得到可讀名稱；按鈕表格與流程大綱仍顯示圖中 slug／序號名稱；左側決策控制在靜止狀態仍可見，分別違反新名稱與收合規格。新測試已在舊行為上重現這些差異，再以同一顯示名稱函式與互動樣式修正。

因為名稱屬於本次明確取代的呈現文字，以下既有顯示預期依 R12 §2 授權更新；資料、決策、安全、來源與輸出斷言未改：

## 後果

不同區域共享同一套顯示名稱推導，避免畫面詳情、按鈕表格、搜尋和流程大綱各自產生不同叫法。若缺少可證明的可讀值，回退為「類型＋位置」或「類型（無文字）」，不依 CSS class 猜用途。使用者仍能在技術細節查看原始名稱與來源。


## WP42 修正：靜態名稱、位置與快取

### 決定

顯示名稱不讀取預覽渲染後的樣本文字。來源標記 `labelSource=visibleText` 可證明圖中值是來源文字；預覽文件明確標成動態，或該畫面有動態運算式而元件沒有來源文字標記時，略過預覽文字並回退到靜態屬性或位置。位置只依最近的 `nav`、`header`、`footer`、`form` 或標題祖先；沒有這些區塊時不加「前往 X」。全站導覽合併列的無文字回退使用共同位置「位於 導覽列」。

`main.ts` 對每個畫面解析一次惰性文件，`labels.ts` 以 index 為鍵快取每個畫面的 DOM 上下文與名稱；按鈕總表、詳情、搜尋、流程、儀表板、API 呼叫來源與匯出前檢查共用該名稱索引。預覽路徑標記也在初始化時一次套用到惰性文件，選取未對應預覽元素時沿用同一個純函式。

### 舊實作失敗證據與效能

WP42 的測試先提交於 `f3400c7`、`5b42971`、`b8ea83a`。在 `ed91b1a` 舊實作上重跑名稱測試，`r4-labels.test.mjs` 預期來源標籤 `find owners`，舊實作仍選用 `displayLabel` 輸出 `Find owners`；名稱單元測試也先後重現「Alex Johnson」被當成名稱，以及兩次 `componentLabelsByScreen` 回傳不同 Map 的失敗。舊實作另無條件在名稱後附目的地；`Owner` 斷言實測舊輸出為 `Owner，前往 Owner Details`。

根因是初始載入先遍歷並解析全部文件、逐筆對預覽 selector 查詢可見文字，之後又為畫面標題重新解析文件；再把每個元件複製進新圖節點並重建索引。修正移除此重複解析與逐元件複製，並快取一次計算的名稱／位置索引。原 `performance.e2e.mjs` 834 ms 斷言完全未改：WP41 基線為 455.8 ms；WP42 舊實作為 1,340.4 ms；修正後預設並行完整 E2E 三輪為 530.3、594.6、542.9 ms，均低於 834 ms。
