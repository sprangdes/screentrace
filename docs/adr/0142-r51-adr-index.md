# ADR 0142：R51 ADR 索引與現況摘要

## 背景

[HEALTH_CHECK_20261111](../HEALTH_CHECK_20261111.md) HC-008：`docs/adr/` 已有 141 份 ADR（約 440KB），沒有索引。新加入的人必須讀很多份才知道現在的做法，也看不出哪些決策已被後來的 ADR 取代。只有 ADR 0113 在內文寫了「已由 ADR 0114 取代」，其他取代關係散落在後來的 ADR 正文裡。

## 決定

- R51-1：新增 [`docs/adr/README.md`](README.md)。依主題分成 12 組，每組先用一段話說明現況，再列出每份 ADR 的編號、決定與狀態。12 組是：
  - 基線
  - Struts
  - Spring
  - JSP 與 URL
  - JavaScript／React
  - 角色
  - 預覽擷取
  - 報表檢視器
  - 審查 md
  - 元件庫
  - 驗證用專案
  - 建置與品質
- R51-2：狀態只依明確的證據判定，分成三種：
  - 「已被取代」：後來的 ADR 寫明取代。目前只有 0113。
  - 「部分被取代」：後來的 ADR 寫明取代其中一部分（0021、0034、0052、0069、0111、0114、0119、0126），或 [ADR 0084](0084-r17-two-page-report-and-retired-tests.md) 在 R17 移除了它的功能，並刪除鎖定該功能的測試（元件庫 0027～0030、R4 介面殼層 0040～0044、0058～0060、0062～0064、0068、0070、0071）。
  - 「有效」：其餘全部。

  沒有明確依據的一律標「有效」，不推測。
- R51-3：各 ADR 的內文不改，保留當時的紀錄。新增 ADR 時，在索引的對應主題加一列；如果新 ADR 取代了舊決策，同時更新舊 ADR 那一列的狀態。AGENTS.md 的實作流程加上「先讀 ADR 索引」。
- R51-4：ROADMAP 是逐輪的歷史紀錄，同一個 WP 的多次驗證也是當時的事實，這一輪不整理。索引中有連結指向 ROADMAP。

## 後果

- 想知道現況時，先讀索引裡各組的現況說明；需要細節時，再依連結讀個別 ADR。
- 索引需要人工維護：新增或取代 ADR 時，若沒有同時更新，索引就會過時。
- 驗證：141 份 ADR 都恰好出現一次。標為取代的 27 份，各自都有取代它的 ADR 連結。只改文件，沒有改程式碼與測試。
