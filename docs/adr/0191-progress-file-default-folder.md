# ADR 0191 進度檔的預設資料夾與接續修正

## 背景

ADR 0086 的進度檔每份報表都要在「另存新檔」對話框選一次位置。需求方審查多份報表時希望進度檔集中在同一個資料夾，不用每次選。另有三個接續問題：上次記住的進度檔被移動或刪除後，頁面仍一直提供「繼續上次進度」卻永遠載入失敗；檔名長時撐開存檔選單；在選單上點擊會讓重新繪製的選單自行關閉。

限制：

- 仍只用 File System Access API 與 IndexedDB（ADR 0086）；不使用 OPFS。
- 不在使用者沒有選擇的情況下覆蓋已存在的進度內容。

## 決定

1. **預設資料夾。** 存檔選單提供「設定預設資料夾…」（`showDirectoryPicker`，`mode: 'readwrite'`）。資料夾 handle 與各報表的進度檔 handle 存在同一個 IndexedDB store，鍵為任何應用名稱都產生不出的 `\u0000default-folder`。store 以 `PermissionHandle` 為型別，讀回時依 handle 的 `kind`（及是否有 `getFile`／`getFileHandle`）分辨檔案與資料夾，不以型別轉換假設。
2. **預設資料夾中的檔名。** `screentrace-review-<名稱>-<雜湊>.md`：名稱與「另存新檔」相同的安全化結果，雜湊為應用名稱的 FNV-1a 32 位元（8 位十六進位）。安全化會把不同名稱（`a b` 與 `a-b`，或不分大小寫磁碟上的 `App` 與 `app`）變成同一個檔名，雜湊讓每份報表在共用資料夾中各有自己的檔案。另存新檔的建議檔名不變。
3. **何時使用。** 尚未設定進度檔時：
   - 已有預設資料夾且瀏覽器已授權：第一次標記時直接在資料夾建立或載入該報表的 md，不跳出選單；未授權時選單提供「存到預設資料夾」（點擊時請求授權）。
   - 開啟報表時，沒有記住的進度檔而資料夾已授權且已有該報表的 md：與記住的進度檔相同，未標記時自動載入，否則請使用者選擇。
   - 資料夾中的 md 有內容而頁面已有標記：進入待決定（pending），由使用者選擇以哪一方為準；空檔或不存在則寫入目前的標記。
4. **不搶已設定的進度檔。** 預設資料夾的自動存檔在每個非同步步驟之後確認仍沒有進度檔；開啟報表時尋找上次進度期間不啟動自動存檔，找完且沒有結果、期間有標記時才嘗試。
5. **記住的進度檔不存在。** 載入時得到 `NotFoundError`：忘記該 handle（從 store 刪除），回到未設定狀態。有預設資料夾時重新嘗試它（建立新的 md 或載入資料夾中現有的），否則打開選單請使用者選位置。
6. **待決定的提醒。** 每次進入待決定只主動打開選單一次；做出決定（離開 pending）後重設，下次進入待決定再提醒一次。
7. **選單版面與點擊。** 選單內的檔名以 `code` 元素呈現並可換行；判斷點擊是否在選單外改用 `event.composedPath()`，點擊當下的路徑包含已被替換的按鈕所在的選單，因此選單不會自行關閉。

## 後果

- 已設定的預設資料夾在每份報表共用；更換預設資料夾不會搬移已存在的進度檔，已設定的報表仍寫入原本的檔案。
- 預設資料夾中的檔名比另存新檔多出雜湊，與另存新檔建立的檔案不會互相取代。
- 測試套件已於 2026-11-19 從現行版本移除（見 ROADMAP），本輪以 TypeScript 嚴格建置、ESLint 與 Prettier 檢查；瀏覽器的資料夾授權對話框無法自動化。
