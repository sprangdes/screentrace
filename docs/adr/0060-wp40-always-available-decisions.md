# ADR 0060：WP40 常駐決策介面與送出按鈕選取

## 背景

WP40 將決策介面改為隨時可用，並保留原有 review state、複合鍵、匯入匯出格式及模擬結果。WP39 的提交按鈕點擊會先選取按鈕，接著送出處理再次選取所屬表單，令右側欄顯示表單而非使用者實際點選的按鈕。

## 舊實作失敗證明

在 WP39 舊實作、尚未變更產品程式碼時執行 node --test screentrace-viewer/test/wp40-always-on-decisions.e2e.mjs：

- WP40 decisions stay available without a mode and synchronize across overview and focused viewer：失敗。頁面仍有 1 個「確認模式」核取方塊，預期為 0。
- submit click keeps the clicked button selected and includes its owning form summary：失敗。送出後右側摘要仍顯示「標籤：送出表單」，預期顯示被點擊的「Find Owner」按鈕及「所屬表單」。

## 決定

1. 移除模式開關；進度、篩選、三態決策、統計、衝突提示與說明固定可用。未確認畫面不顯示狀態圖示，卡片只在已有決策時顯示狀態色條及圖示。
2. 卡片、畫面標題、右欄元件摘要、畫面清單及按鈕總表都直接寫入既有 review state。鍵盤與觸控操作沿用相同決策更新函式。
3. 提交按鈕點擊後以實際按鈕作為選取目標；右欄在按鈕摘要下顯示所屬表單。表單本身的模擬與結果不變。

## 既有測試預期調整

以下只調整被「移除模式、常駐決策」直接取代的呈現預期；原本的決策值、匯入匯出、資料、模擬結果與安全斷言均保留。

| 測試 | 舊預期 | 新預期 | 原因／舊實作證明 |
|---|---|---|---|
| `r4-shell.e2e.mjs` UI1 shell | 有 1 個確認模式核取方塊；模式開啟後有 4 個狀態篩選 | 核取方塊為 0；五種狀態篩選常駐 | WP40 移除開關，並將「隨畫面移除」篩選固定顯示。新增 WP40 測試在舊實作上因找到 1 個核取方塊而失敗。 |
| `r4-canvas.e2e.mjs` UI2 卡片 | 未確認卡片可顯示狀態圖示／徽章，僅確認模式可標記 | 未確認卡片沒有狀態標記；標記保留後顯示一個狀態圖示 | WP40 要求未確認保持安靜、卡片決策常駐。 |
| `wp25-prototype.e2e.mjs` WP25 標記 | 未確認元素帶 `data-review-status="UNDECIDED"` | 未確認元素不帶狀態標記 | 未確認不顯示標記；保留既有決策值與預覽載入斷言。 |
| `r4-details.e2e.mjs` UI3 決策控制 | 每個查詢位置只見一組三態控制 | 每個可見位置各有一組，順序均為保留、移除、未確認 | 清單與右欄現在同時常駐；新增位置不改決策狀態。 |
| `review.e2e.mjs` 批次標記 | 未確認卡片有「未確認」狀態圖示 | 未確認卡片狀態圖示數量為 0 | 對應「未確認不顯示標記」規格；按鈕類型、批次結果及統計斷言保留。 |
| `wp35-36-corrections.e2e.mjs` WP35 | 模式關閉時進度卡片數量為 0／固定單一卡片數 | 每張已顯示的區域卡片都有進度，依全專案分組數量驗證 | 進度常駐後按既有分組列出所有區域；分組選擇與名稱斷言保留。 |
| `md.e2e.mjs`、`review.e2e.mjs`、`synthetic-project.e2e.mjs`、`wp16.e2e.mjs` 決策讀取 | 以單一 `data-screen-review`／`data-component-review` 節點讀取決策 | 讀取第一個對應控制組的相同決策值 | 多個介面同時顯示相同鍵值；只消除定位歧義，決策、MD 與往返斷言不變。 |
| `guide-docs.test.mjs`、`guide-shots.test.mjs` | 引用檢查模式／確認模式截圖 | 引用常駐決策與樣式截圖 | 被移除的介面截圖改由新 UI 取代；生成器連續兩次輸出 SHA-256 相同。 |

此外，各 E2E 中只用來開啟確認模式的 checkbox `.check()` 前置操作已移除；其後所有原有資料、決策、網路、API、md 與安全驗證仍執行。新測試 `wp40-always-on-decisions.e2e.mjs` 已在舊版實作上失敗：舊頁面有 1 個模式 checkbox（預期 0），按鈕送出後摘要仍是「送出表單」而非被點選的 `Find Owner` 與「所屬表單」。

## 後果

UI 直接呈現決策狀態與操作入口；未確認項目保持無標記。所有介面仍共用原 review state，md 格式、決策鍵及模擬規則不變。
