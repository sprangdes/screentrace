# ADR 0119：R28 API 頁與角色頁加上數量的圖形摘要

## 背景

API 頁與角色頁幾乎只用文字呈現：API 頁以「需要注意 13」這類標籤表示狀態分布，角色頁以「會走到 12 · 可能走到 3」與 `user：是` 表示角色範圍與條件。要比較各 Controller 或各角色，使用者必須逐列讀數字。需求方希望呈現更直覺。

## 選項

1. 在現有版面加入小型的長條與標記，數字仍以文字呈現：採用。
2. 加入圖表函式庫畫圓餅圖或力導向圖：違反 ADR 0019 不引入執行期圖形相依的決定；力導向圖每次排版不同，也違反確定性分析的原則，不採用。
3. API 詳情加呼叫鏈圖（畫面 → 觸發元件 → API → 處理程式）、角色比較改為重疊長條：價值高但需要 SVG 排版，留待後續，不在本次範圍。

## 決定

- R28-1：API 頁標題下方加一條狀態分布條（使用中、未被使用、可移除），下方以文字列出三種狀態的數量；分布條依全部 API 計算，不受篩選與搜尋影響。每個分組標題右側加一條小分布條，依該分組目前顯示的 API 計算。
- R28-2：角色清單每一列加一條觸及條，依序為會走到、可能走到、走不到、不適用，寬度依畫面數。
- R28-3：判定條件依成立與否加上 ✓（綠底）或 ✕（灰底）的標記，條件文字不變。
- R28-4：角色流程有兩步以上時，流程小節加上每一步的畫面數直條（會走到在下、可能走到在上，以斜紋區分）；點直條捲動到該步的清單。
- R28-5：圖形只呈現頁面上已有的數字，不新增判定；數量為 0 的區段不畫。圖形不帶文字內容，報讀以 `aria-label` 提供；已有相同數字的列（分組標題、角色列）中的圖形對報讀隱藏。只用 CSS 與 DOM，不引入相依。

## 後果

使用者可以一眼比較各 Controller 的狀態與各角色的範圍。狀態色彩沿用既有的保留／警示／移除色，「未被使用」改用較亮的琥珀色、「可移除」與「可能走到」加斜紋，讓色覺差異的使用者也能分辨。
