# ADR 0112：R21 角色流程改以流程圖呈現

## 背景

R20 讓報表能依角色呈現流程，但實際在 reservio 使用時不直覺：角色說明是程式條件（例如 `me.role === "ROLE_USER"：是`）、角色選單藏在左側清單、選了角色後畫布仍是原本依網址分區的版面而看不出流程、比較表大多是灰色「不適用」、四種狀態名稱難以區分。

## 選項

1. 只調整 R20 的顏色與文字：畫布仍看不出流程，拒絕。
2. 選了角色時改用該角色的流程排版，並簡化文字與比較表：採用。

## 決定

- R21-1：角色切換改為畫布左上角的一排按鈕（含「不套用角色」），左側清單不再有角色選單；開啟畫面時按鈕隱藏。按鈕與勾選框在切換時保持原元素，鍵盤焦點不會遺失。
- R21-2：選了角色時，畫布改用角色流程排版：第 N 步一欄，欄內依前一步畫面的位置排序；只畫從第 N 步到第 N+1 步的線，每條線在欄間有自己的垂直軌道。走不到、不適用的畫面排在最後兩欄，預設隱藏，可勾選顯示。回到「不套用角色」時恢復原本的版面。
- R21-3：設定檔每個角色可加選填的 `description`（最多 80 字），寫入圖中 `application.personas[].description`；未設定時不輸出，schema 版本仍為 2.4。報表優先顯示說明，沒有時顯示「依 N 個條件判定」；條件收在「判定條件」裡。
- R21-4：狀態文字改為「會走到」「可能走到」「走不到」「不適用」。畫面上主要只分兩種：會走到為綠色實線框，可能走到為灰色虛線框（不再用像警告的橘色）；卡片徽章只在不是「會走到」時出現。
- R21-5：比較表依各角色最早到達的步數排序，不適用顯示「—」，可勾選只看各角色不同的畫面。
- R21-6：報表上的「第 N 步」只算畫面：經由網址入口轉址（畫面 → 網址入口 → 畫面）算一步，不另算網址入口那一步。viewer 從圖中 `flow.entryPoints` 與 `flow.steps` 依此重新計算步數，並把經由網址入口的移動也畫成流程圖上的線；是否「會走到／可能走到」仍只用圖中的 `reached`。圖中的 `depth` 不變。

## 後果

選角色後可直接從左到右讀出流程。流程圖只畫往下一步的線，返回先前畫面或同一步之間的連結不畫在流程圖上，仍可在開啟畫面後的連線中看到。
