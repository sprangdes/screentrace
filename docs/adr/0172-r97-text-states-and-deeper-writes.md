# ADR 0172：R97 文字／數字狀態與超過呼叫鏈深度的狀態寫入

## 背景

R82（[ADR 0160](0160-r82-state-changes.md)）只認專案列舉，且只掃呼叫鏈 4 層內的方法。legacy 專案常把狀態存成字串或數字代碼（`setStatus("PAID")`、`setStatus(2)`），狀態寫入也常在較深的 Service 裡。

## 決定

- **文字／數字狀態**：欄位名稱以 `status`、`state`、`stage`、`phase` 結尾（不分大小寫）時，setter、builder 或欄位指定寫入的字串字面值、整數字面值，或 `static final` 常數（同類別或 `其他類別.常數`）所持有的上述字面值，記為狀態寫入。狀態名稱為「被寫入物件的型別.欄位」（型別取自區域變數、參數或欄位宣告；取不到時只有欄位名），`values` 為整個專案寫入過的值（排序），`kind` 為 `TEXT`。其他欄位名稱的字串寫入不列入，避免把一般資料當成狀態。
- **原狀態**（ADR 0169）同樣適用，比較對象為字串或整數字面值（`"NEW".equals(o.getStatus())`）；原狀態不限於寫入過的值。
- **深度**：呼叫鏈（`backendCalls`）仍只列 4 層；狀態寫入繼續追到 8 層，超過 4 層的方法每個只掃一次。

## 測試

- Java `R97TextStatesTest`（2）。既有測試不需修改。

## 後果

- reservio 沒有文字狀態；多找到 2 筆在第 5 層以後的 `NotificationEventType` 寫入。
- 以欄位名稱判斷是否為狀態屬於命名慣例；命名不同的狀態欄位（例如 `flag`）不會列出。
