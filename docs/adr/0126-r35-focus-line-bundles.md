# ADR 0126：R35 放大畫面時的關聯線左進右出、依區塊合併

## 背景

放大到一個畫面時，四周的關聯線原本指向對方畫面在總覽上的方位（ADR 0084 起的作法）。被很多畫面連到的畫面，線會從四面八方進出：reservio 的登入畫面有 34 條進來、7 條出去的線，方向各異、互相交錯，看不出從哪些功能來、往哪些功能去。需求方要求把放大後的關聯線排整齊。

## 選項

1. 左進右出，每個畫面一條平行線：整齊，但線多時一側擠滿。
2. 依方位合併成粗線：線變少，仍是放射狀。
3. 左進右出，依區塊合併：採用（需求方選擇）。

## 決定

- R35-1：進來的線一律在預覽框左側、出去的線在右側，水平排列；一列代表一個區塊（總覽依網址分的區，或角色流程中的步驟欄），畫布沒有分區時一列代表一個畫面。列依那些畫面在畫布上的平均位置由上而下、再由左而右排序，在框邊等距分布。
- R35-2：同一區有兩個以上畫面的列合成一條線，線寬隨畫面數增加（`2.5 + log2(數量) × 1.5`，最多 8），外側的標籤（`.focus-bundle`）寫區名與數量；點標籤列出這些畫面，選一個就前往，Esc 關閉。出去的合併線滑過時，會一起標出預覽中所有會走這些線的按鈕。
- R35-3：只有一個畫面的列維持原本的線（`.focus-line-hit` 的 `data-kind` 仍是 `known`／`incoming`，滑過顯示縮圖與按鈕，點了前往），同一畫面的多條流程在同一列上下並排。有合併線時，這些列也加上寫著畫面名稱的標籤，點了前往。
- R35-4：有合併線時，預覽框左右的留白由 56px 加寬到 176px 放標籤；沒有時維持 56px，預覽大小不變。
- R35-5：頁首／頁尾共用連結、回到自己的線與無法確定去處的出口，位置與原本相同。
- R35-6：`r17-focus.e2e.mjs` 中「出去的線方向和總覽相同」的斷言改為「從右邊緣水平向右、依畫布位置由上而下」，這是本次刻意改變的行為。只改 viewer 的程式、樣式、測試與文件；分析與 graph JSON 不變。

## 後果

被很多畫面連到的畫面，四周的線從幾十條減為每側幾列，並直接看得出來自或前往哪些功能區。代價是看不出對方畫面在總覽上的方向，且有合併線時預覽框較窄。
