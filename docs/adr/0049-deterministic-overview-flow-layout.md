# ADR 0049：總覽依可證明流程分層

## 決定

依 R5 WP23，overview.ts 僅用既有 partitionNavigation 的 flows（排除自我迴圈）計算總覽座標；不改 canonical graph、主要 URL 推導、schema、API 狀態或 md。無入向邊的入口先按 ID 訪問；剩餘循環優先主要 URL `/`、URL 字串長度、ID。排序 DFS 只移除祖先回邊，DAG 最長路徑決定 x 層；同層四次交替重心排序，最後按 ID 決勝。沒有流程邊者置於最右欄並標「未連結的畫面」。

保留 250×145 卡片與 340×240 格距、既有卡片間正交走廊路由；回邊、跨層與自我迴圈均避開非端點卡片。全站導覽開關只重繪關聯，不重新計算座標；純導覽邊較淡，同一來源／目的只畫一條，混合關聯保持流程樣式。進出邊 hover／focus 仍強調相關項目。自動適合完成後設定 data-fitted，新增 E2E 等待此狀態。

超過 150 畫面或 600 關聯直接採舊 gridLayout，不進 DFS／重心排序。既有 500／5,000／3,000 效能 E2E 保留，首次渲染上限仍為 3 秒。

## 測試與既有斷言

失敗測試提交 f3f57a7，舊實作沒有 flowLayout，10 個新單元案例全部失敗；後續另涵蓋重心排序與無入口的 URL／ID 決勝。合成離線 E2E 驗證 Find Owners → Owners List → Owner Details → 表單的 x 嚴格遞增、導覽切換不移動卡片、hover 與初始適合。

`WP20 grid and gutter routes are deterministic and never cross non-endpoint cards even with cycles and self loops`：**全部原有斷言逐字保留，沒有修改預期或放寬。** 唯一調整是測試資料準備。舊測試只在第一個 index 手動覆寫全互連關聯，第二次卻索引未加入那些邊的 graph；舊 grid 忽略邊所以掩蓋了兩次輸入不同。新準備把同一批全互連邊寫進合成 graph，再讓兩次索引都讀取它，依然檢查全互連（含循環／自我迴圈）、反轉節點順序座標相同、每條邊不穿越非端點卡片。保留的舊實作無法通過新 WP23 流向規格，失敗紀錄見 R5。沒有更動資料／證據／安全／決策／md／golden 斷言。

## 限制

流向只代表現有靜態證據。循環回邊仍需繞行；全站導覽全開可能增加幾何交叉，不能宣稱全部邊更少交叉。窄畫布自動適合後卡片較小，保留縮放與聚焦操作；不猜補缺少的流程、不增加相依。
