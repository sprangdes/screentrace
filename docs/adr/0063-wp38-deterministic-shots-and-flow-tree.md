# ADR 0063：WP38 截圖穩定與流程樹去重

狀態：Accepted

## 決定

指南截圖在擷取前將主文件與 iframe 內所有可捲動區域重設到原點，並以明確狀態條件等待應用程式、字型、圖片與預覽完成；動畫停止且文件連續 16 個動畫影格沒有 DOM 變更後才截圖。截圖用的樣式隱藏捲軸、固定 SVG 線段光柵方式，並將少數有抗鋸齒邊界的卡片、狀態籤與原型目的按鈕改成方角，以避免瀏覽器合成層在相同狀態下產生一像素顏色變化。截圖再連續擷取至兩張相鄰畫面逐像素相同。所有截圖仍列入決定性檢查，不因偶發差異而排除。

流程大綱以縮排樹呈現。每個可證明的目的畫面僅遞迴展開一次；後續參照以「（已在上面展開）」標示並可點選跳轉。來源畫面中的未解析目的合併為一個節點並列出全部觸發按鈕。觸發名稱沿用 R5 可讀名稱規則；若只有內部識別名稱，改用元件類型與所在畫面、行號描述。渲染層再做一次標籤白名單檢查，讓圖內舊版的「連結 6」等預設名稱不會漏到報表。深度與寬度限制不變。

## 證據與測試

- 紅測試先於實作提交：`2b26c19` 鎖定目的畫面只完整展開一次、未解析目的合併、內部名稱不出現在樹中；舊實作在「目的畫面展開次數為 1」斷言得到 2 時失敗。
- `758d626` 先加入延遲 iframe 的截圖就緒紅測試；原實作因缺少 `waitForGuideScreenshotReady` 匯出而失敗。實作後測試另確認延遲預覽完成與擷取前捲動位置歸零。
- `wp38-flow-outline.test.mjs` 將一處既有斷言由「回到已出現的畫面」改為「已在上面展開」。舊預期描述循環列，會鼓勵逐條重複畫面；新預期符合只展開一次並提供跳轉的需求。
- PetClinic 實際報表曾顯示舊圖中的預設名稱「連結 6」；新增渲染層的防漏檢查後，Chromium `file://` 實測顯示「連結（所在畫面）」，表單則顯示畫面名稱與行號。此名稱例外不會影響已有人類可讀名稱的觸發按鈕。
- Chromium `file://` E2E 驗證回訪節點可跳轉、未解析觸發按鈕合併、無可讀名稱改用「按鈕／連結（畫面名稱、第 N 行）」，且內部名稱未出現在可見文字中。

## 截圖差異根因

`guide-shots` 在同一個頁面依序切換地圖、功能、按鈕、預覽與資訊面板；各模式的側欄共用可捲動區域。功能區截圖因此會繼承先前互動留下的捲動位置。特定輪次中捲動區位於頂端，其他輪次則保留舊位置；瀏覽器已完成圖片、字型與 DOM 更新仍不足以消除此差異。捲動歸零後，少數差異只剩卡片／狀態籤圓角與 SVG 細線的邊緣像素，故截圖專用樣式固定了這些易受抗鋸齒影響的邊緣。沒有時間戳或隨機值參與指南畫面。
