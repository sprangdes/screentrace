# ADR 0187 模擬流程中輸入的資料與返回上一頁

## 背景

報表模擬中輸入的資料不會帶到下一個畫面：insure 填寫投保資料後，確認頁、申請明細、繳費與保單頁仍顯示範例值（如「ReviewForm」）；「返回修改資料」回到空白表單；工具列「上一頁」回到的畫面也不保留剛才輸入的內容。ADR 0085 的提交欄位回放只處理 handler 直接綁定 `@ModelAttribute` 並由同一 JSP 顯示的情況，insure 經由工作階段保存的確認資料不在其中。

## 決定

報表模擬維護一份「本次流程的資料」，依真實伺服器的方式帶值（`journey-data.ts`），不修改圖、審查結果或瀏覽器儲存：

- **送出表單時**記錄表單中有名稱的欄位值（忽略 `_` 開頭、密碼、未勾選的核取方塊；預覽中只有範例值的隱藏欄位不覆蓋先前的值）。
- **到達畫面時**，若是由送出表單到達，或畫面主要網址含路徑變數（顯示既有紀錄，例如 `/applications/{id}`），則：
  - 由伺服器模型填值的欄位（圖中有 `model` 綁定的 Spring 表單標籤）顯示流程資料；查詢表單這類未綁定模型的欄位維持空白，與真實系統相同。
  - 顯示欄位（`DISPLAY_FIELD`）的屬性與欄位名稱在忽略大小寫、`_`、`-` 後相同時顯示流程資料，例如 `ownerName` 對應 `reviewForm.ownerName`、`policy.owner_name`、`application.owner_name`。支援 `${物件.屬性}`、多個 `${…}` 組成的文字與 `${物件.屬性 eq '值' ? '甲' : '乙'}`。重複列不改。
  - 新開的頁面（例如 `/applications/new`、`/renew`、`/policies`）不帶入資料。
- **上一頁／下一頁**：離開畫面前保存該畫面的輸入，回到該歷程位置時還原，並重新套用流程資料到顯示欄位，與瀏覽器返回時看到原頁面一致。
- 從畫布或清單直接開啟畫面時重新開始一份流程資料；畫面狀態切換器視為同一流程。

- **布林屬性。** JSP 以 EL 寫的布林屬性（`readonly="${not empty form.previousId}"`、`disabled`、`checked` 等）在預覽中原本被換成範例文字，HTML 只要有該屬性就成立，使新投保表單的車牌、姓名、證號無法輸入。捕捉器改以畫面事實判斷：成立時寫成 `readonly="readonly"`，不成立或無法判斷時省略，續保表單仍為唯讀。

名稱對應是推論，不代表資料庫實際儲存或轉換；伺服器計算的值（如保障迄日、保單號碼）仍是範例值。

## 驗證

insure：填寫投保資料（機車、XYZ-9876、陳大文…）→ 確認投保申請顯示相同資料與起保日 → 返回修改資料帶回所有欄位 → 上一頁回到確認頁、再上一頁回到當時輸入的表單 → 送出後申請明細、模擬繳費、測試保單顯示同一車牌、車主與起日 → 以此資料申請續保時續保表單帶入原資料 → 進度查詢表單為空白。
