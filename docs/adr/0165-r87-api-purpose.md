# ADR 0165：R87 API 的白話用途

## 背景

[reservio 評估（2026-11-18）](../RESERVIO_EVALUATION_20261118.md) P7：API 頁只有技術路徑（`POST /api/reservations/{id}/cancel`）與處理方法名稱，非工程師看不出用途。

## 決定

- `apiPurpose(index, callers, external)` 只由已推導的呼叫來源組成一句話，不推測：
  - 按鈕：「按下「A」、「B」…時呼叫」，依呼叫它的畫面數排序，最多列三個，其餘寫「等 N 個按鈕」；
  - 畫面載入：「開啟「X」等 N 個畫面時自動呼叫」；
  - 外部呼叫（Webhook，ADR 0102）：「由外部系統（Webhook）呼叫」。
- 按鈕名稱去掉右側欄加上的元件種類與「（第 n 個）」；`busy ? '送出中…' : '送出'` 這類文字去掉以「…」或「...」結尾的處理中選項；含「示例值」或只有標籤名（`<button>`）的不採用。
- API 詳情標題下顯示「用途：…」；清單每列路徑下方顯示最多兩個按鈕名稱（或「畫面載入時」、「外部系統」）。沒有呼叫來源時不顯示。md 不變。

## 測試

- viewer `r87-api-purpose.test`（2）。既有測試不需修改。

## 後果

- 用途只反映畫面上的觸發方式，不解釋後端做了什麼；後端效果見處理程式、後端呼叫鏈與「會改變的資料狀態」（ADR 0160）。
- 按鈕文字只有處理中狀態可證明時（reservio 的「處理中」），用途就只有這個字。
