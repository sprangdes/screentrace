# ADR 0185 JSP 畫面的模型事實與共用狀態

## 背景

同一個 Spring handler 依 servlet 路徑選擇兩個 Tiles 定義（例如客戶的 `detail` 與後台的 `adminDetail`），兩者共用同一個 JSP 頁身，並由 `adminPage` 這類模型屬性決定顯示的元件與連結。ADR 0182 只在預覽代入這些事實，圖中兩個畫面仍擁有彼此的元件：客戶頁出現核保按鈕，後台頁出現繳費連結，`${adminPage ? '/admin' : '/'}` 這類連結在兩邊都要使用者選擇目的地。ADR 0183 的狀態畫面也只建立在有提交按鈕的那一頁，客戶頁看不到核保通過後的繳費流程。

## 決定

- `SpringRequestCondition` 證據另記同一方法中、由該分支單獨決定的布林模型屬性（`derivedFacts`），例如 `customerAccess = !adminPage && …` 在後台分支為 false。只採方法本體中寫在回傳前、鍵值唯一的 `addAttribute`／`addObject`，以 `!`、`&&`、`||`、括號與名稱做三值判斷。
- `JspScreenFacts` 取畫面所有條件式 RENDERS 共同成立的事實，以 JSP 守衛的三值判斷（名稱、字串與布林常值、not/and/or、eq/ne）移除守衛必為假的 CONTAINS。無法判斷的守衛保留歸屬。
- 共用元件若有字面 URL 候選（`requestAlternatives`），該畫面的 CONTAINS 證據加上 `JspScreenFacts`，記錄事實、保留的路徑與端點。元件節點不複製；報表的畫面地圖與模擬以這些端點縮小該畫面上的目的地，只剩一個時直接前往。
- 狀態畫面延伸到共用同一 JSP 頁身、且擁有以同一狀態欄位比較之元件的其他畫面。入口值與狀態值相同，沒有轉換按鈕，證據註明共用來源。狀態依入口與提交按鈕的到達順序記錄 `jspStateOrder`，報表工具列以「流程狀態」切換同一頁的各狀態畫面。
- JSP 守衛判斷改用同一個三值判斷器，並同時代入畫面事實與狀態值。
- 連結文字為兩個字面字串的條件運算式時，名稱列出兩者（「返回申請總覽／返回投保首頁」），預覽仍依畫面事實顯示其一。
- 回傳到多個畫面的請求，模擬選項以 handler 自己的回傳條件標示（「當 service.issuance(id) != null」／「其他情況」），不再把 URL 運算式當成條件顯示。

## 限制

只使用分支條件證明的事實；沒有設定該屬性的回傳路徑（例如 `missingReview` 呈現的錯誤頁）不推定為 false。服務呼叫結果、工作階段與資料庫狀態仍無法判斷，相關選項保留讓使用者選擇。

## 驗證

`spring-jsp.test.mjs` 的共用 Tiles fixture 檢查兩個畫面的元件歸屬、條件連結的路徑與端點、衍生事實、共用狀態畫面與狀態順序。insure 的客戶申請明細有待核保、核保中、核保通過、核保未通過四個狀態，可從核保通過前往模擬繳費並完成出單；後台明細不再出現繳費與續保連結，返回連結直接前往各自的首頁。
