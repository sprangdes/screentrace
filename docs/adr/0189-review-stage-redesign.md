# ADR 0189 審查工作台：開啟的畫面是審查主體，關聯改為可收合的卡片欄

## 背景

R17 起，開啟畫面是把畫布放大到該畫面（ADR 0085），預覽四周畫出淡化的關聯線、合併標籤與頁首／頁尾虛線（ADR 0035、0126、0127）。實際使用時有幾個問題：

- 預覽只是畫布上的一個框，左右要留給關聯線與標籤，畫面本身被壓小；關聯線平常淡化，要滑過才看得清楚，卻一直占著空間。
- 一進入畫面，左側清單就自動收起，審查時看不到還有哪些畫面要確認。
- 右側欄把按鈕、欄位、API、來源畫面一路往下排，畫面的決定與按鈕清單擠在同一欄。
- 總覽的三種看法分散在不同地方：畫布、左側「功能」切換、上方「角色」分頁。

需求方以設計稿（審查工作台、角色流程總覽、依功能、自由畫布、API 呼叫鏈）確認新的方向：系統的畫面是主體，「從哪裡來」「會去哪裡」不必一直完整顯示。

## 決定

1. **審查舞台（`review-stage.ts`）。** 開啟畫面時，主區域改為「從哪裡來」欄、預覽、「會去哪裡」欄，不再放大畫布。畫布保留在記憶體，返回時回到原本的位置。
   - 兩欄預設收起成直立的標籤，寫著方向與數量；點標籤展開，展開與否在切換畫面時保留。
   - 「從哪裡來」：畫布會畫的流程（不含全站導覽）中前往這裡的畫面，每張卡片寫出經由哪些按鈕；只經頁首／頁尾連進來的畫面收在一組。沒有來源時說明可能由網址、書籤或其他系統直接進入。
   - 「會去哪裡」：同樣的流程中由這裡出發的畫面，以及「留在本頁」、「無法確定前往哪個畫面」、頁首／頁尾可前往的畫面。目的畫面已標記移除時，卡片標示提醒。
   - 滑過「會去哪裡」的卡片，預覽中會前往那裡的按鈕以藍框標出；滑過預覽中的按鈕，對應的卡片被標出。
   - 右側欄原本的「從哪些畫面可來到這裡」移到「從哪裡來」欄，不再重複列出。
2. **審查佇列。** 左側清單在開啟畫面時不再自動收起，也不再浮在畫布上方；只有使用者按下收起時才收成窄欄。每一列都有狀態符號（保留、移除為實心圓，隨功能決定為淡色外框，未確認為虛線圓），清單底部固定一個「下一個未確認（n）」按鈕。
3. **決定面板。** 畫面的「保留／移除／未確認」是一整排的分段按鈕，各自標出快捷鍵 K／X／U。按鈕、欄位、API 改為分頁（`role="tablist"`），一次顯示一個；在預覽中點欄位或從別處指定元件時，自動切到它所在的分頁。
4. **頂部進度。** 「已確認 n／總數」下方加一條保留（綠）與移除（紅）的比例條，有衝突時旁邊顯示「n 衝突」。主要按鈕改用深色。
5. **全螢幕預覽。** 預覽蓋滿視窗，四周為深色；底部置中一條浮動工具列，可以直接標記保留／移除／未確認、看確認進度、前往下一個未確認或結束全螢幕。按預覽中的按鈕前往其他畫面時維持全螢幕（同 R17）。
6. **總覽版面切換。** 畫布、功能頁與角色頁的右上角都有同一組「依角色步驟／依功能／自由畫布」切換（沒有角色時不顯示「依角色步驟」）。原本的入口（左側「功能」、上方「角色」分頁）保留。
7. **API 呼叫鏈延伸到後端。** 呼叫鏈的處理程式卡片加上原始碼檔名與行號；處理程式呼叫專案內 Service／DAO 的已證明呼叫（ADR 0156 的 `backendCalls`）接在後面，標出層級與深度，無法唯一確定的呼叫以虛線框表示。名稱過長時在卡片內換行，不截斷。
8. **配色。** 色彩改為新的一組（墨色 `#151821`、藍 `#2450d3`、保留 `#13795b`、移除 `#b42318`、進入的關聯 `#b5520b`），字級基準 14px；仍只使用系統字型，報表維持離線。

## 第二批決定（2026-11-25，與需求方逐項確認）

比對設計稿後，需求方決定以下差異照設計稿處理：

9. **頂部三個分頁「流程總覽／審查／API」。** 「流程總覽」回到上次的總覽版面（角色頁併入其「依角色步驟」）；「審查」打開上次看的畫面，沒有時打開下一個未確認的畫面；「返回總覽」與 Esc 回到開啟前的總覽版面。主要按鈕改稱「交付 md」。
10. **狀態篩選攤開。** 「全部／未確認／保留／移除」附數量直接列在搜尋框下方，取代漏斗按鈕；搜尋框標出 `/` 快捷鍵。
11. **畫面備註一直展開。** 「給 AI 的備註」文字框一直顯示，保留／移除後仍可選原因；按鈕與欄位的備註維持收合。
12. **歷程麵包屑與上一頁／下一頁並存。** 預覽上方列出最近 3 個看過的畫面，點了以歷程回到那裡。
13. **按鈕列為 ✓ ✕ ↺。** 「未確認」在列上以 ↺（跟隨畫面）表示，意義不變。
14. **全螢幕。** 「結束全螢幕 Esc」放在上方細列；底部工具列顯示決定、進來／出去數量、衝突、下一個未確認與進度。
15. **補足的細節。** 頂部進度另寫「保留 n · 移除 n」；角色標題下的清單列標出步數、「可能」與衝突符號；左窄欄有未確認數量與 `n`，右窄欄有保留／移除／跟隨與衝突符號；右側欄頂端有角色與步數；「會去哪裡」卡片與「留在本頁」寫出途中呼叫的 API。

## 第三批決定：總覽重做（2026-11-25）

16. **依角色步驟改為所有角色的同一張表**（`persona-page.ts`）。列是角色、欄是步驟，格子是該角色在那一步看到的畫面卡片（狀態符號、可能走到的虛線框、n 種狀態、移除時刪除線）；左欄為摘要、審查進度與「需要你注意」（衝突、無法確定去向、可能走到）；點角色名稱展開判定條件與起點。原本的角色卡片列與「全部角色對照」表移除。
17. **跨角色的交接點只列可證明的關係**（`role-handoffs.ts`，需求方決定）：(a) 畫面 A 只在角色甲的流程、畫面 B 只在角色乙的流程，A 有連結或表單直接前往 B；(b) 同一 `stateVariantOf` 頁面的不同狀態，分別只在不同角色的流程中。每條寫出依據，不推論業務意義。insure 得到一條：error（一般用戶）按「返回投保首頁」前往 home（後台管理員）。「任何角色都走不到」列出角色分區為「其他」的畫面。
18. **依功能改為功能卡片清單**（`feature-map.ts`）。一個功能一張卡片，標題寫出分組依據、畫面數、已確認數與用到它的角色，流程以箭頭相連的畫面方塊呈現並換行；左欄為功能目錄與圖例；「其他」以虛線卡片放在最後。

## 取代

- ADR 0085 的「畫布 zoom in 聚焦」由本 ADR 取代；其點擊模擬不變。
- ADR 0123 的角色頁版面（角色卡片列、全部角色對照）由第 16 點取代；其 API 方法色標、路徑參數與呼叫數長條不變。
- ADR 0035、0126、0127 的聚焦關聯線、合併標籤與標籤版面由本 ADR 的卡片欄取代。畫布在總覽中的關聯線（ADR 0049、0090、0124）不變。

## 限制

- 「從哪裡來／會去哪裡」只列畫布會畫的流程與頁首／頁尾連結；畫布上「→ 數字」那種常用目的地仍依 ADR 0039 歸在全站導覽。
- 「會去哪裡」不寫出途中呼叫的 API；需要時從右側欄的 API 分頁或 API 頁查看。

## 驗證

以 `insure` 報表（重新封裝為新版檢視器）在 1440×900 下逐項操作：開啟「detail（核保中）」顯示兩個收起的欄（0／7），展開後列出 3 個前往的畫面、1 個無法確定、頁首／頁尾 3 個；滑過卡片在預覽標出 2 個按鈕；點卡片前往該畫面且「上一頁」可用；全螢幕中按 k 標記保留，頂部與浮動工具列同步為「已確認 1／24」；Esc 依序結束全螢幕、返回畫布，畫布維持原位；三種總覽版面可互相切換；API 頁 `POST /admin/applications/{id}/underwriting` 的呼叫鏈為 2 個畫面 → API → `PolicyController.updateUnderwriting()`（PolicyController.java:194）→ `PolicyService#updateUnderwriting`（SERVICE，第 1 層）。主控台沒有錯誤；`tsc`、Prettier、ESLint 通過。
