# ADR 0164：R86 功能地圖依選單分組，說明只列實際用到的依據

## 背景

[reservio 評估（2026-11-18）](../RESERVIO_EVALUATION_20261118.md) P6：React 專案沒有處理程式類別或 Tiles，功能地圖只能依網址第一段分組，顧客功能（`/dashboard`、`/my/reservations`、`/profile`）多落在「其他」；說明文字仍寫「Struts module、Tiles 定義名稱」。需求方於 2026-11-18 決定（OQ-057）：說明依專案技術調整，並依選單分組。

## 決定

- 新增分組依據 `MENU`（選單），優先序在 Tiles 之後、網址之前：同一個原始碼位置（檔案與行號相同，即同一份清單逐項產生）的 LINK 元件，連到兩個以上不同畫面時成為一個選單；這些畫面以該選單分組。一個畫面同時在多個選單中時，沿用既有規則：取共用畫面最多的值，相同時依值的碼序。
- 功能 key 為 `menu:<檔案>:<行號>`；名稱為「選單：」加前三個項目文字（依清單中的順序，取自元件 `expansionAnchor` 的 `[n]`），超過三項加「等」；無文字的 `<Link>` 不列入。
- 功能地圖的說明只列這次實際用到的分組依據；用到選單時說明「選單」是同一份清單產生的連結。
- md §8 的固定說明加入「選單(同一份清單產生、連到兩個以上畫面的連結)」。

## 測試

- viewer `r86-menu-features.test`（1）。
- 修改的既有斷言：三份 md golden 只有 §8 說明那一行不同（以腳本把新句還原為舊句後逐位元組相同）；`wp40-md-decision-equivalence` 雜湊更新，還原後等於 R82 的值。

## 後果

- reservio 的功能由「網址前綴 + 其他」變為商家側欄、設定選單、顧客選單、登入註冊、服務等選單分組；仍有 14 個畫面在「其他」（沒有被同一份清單連到，或只被單一連結連到）。
- 以清單產生的連結才算選單；手寫的一排 `<Link>` 不會被辨識。

## R93 補充：未分組畫面併入兄弟畫面的功能

- 依規則分組後仍落在「其他」的畫面，依序檢查：(1) 它是網址參數或頁面狀態的版本（`entryQuery`、`stateVariant`）時，同網址的其他畫面所屬功能；(2) 同一個頁面元件（`view`）畫出的其他畫面所屬功能。取票數最多的功能，相同時依功能 key 碼序。只負責轉址的畫面（有 `redirectTargets`）不參與第 (2) 項；依身分分出的版本（例如未登入與商家的首頁）不依網址合併。
- 測試：viewer `r86-menu-features.test` 新增 1 個（R93）。
- 結果：reservio 的「其他」由 14 個降為 8 個（轉址、強制改密碼、想預約店家、兩個通知設定版本、兩個 LINE 綁定頁、訪客首頁）；預約中心的「今天」「待處理」併入商家側欄選單，登入／註冊的 LINE 返回版本併入登入註冊選單。
