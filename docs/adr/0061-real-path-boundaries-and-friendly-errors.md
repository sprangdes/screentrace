# ADR 0061：以實際路徑判定邊界並回報可理解的錯誤

## 背景

macOS 可透過 `/var` 等系統符號連結存取同一個目錄；不分大小寫的磁碟也會接受不同大小寫的路徑。預覽擷取資料記錄的是檔案系統解析後的 `file:` URI，而工作區舊設定可能保留使用者輸入的拼法。以路徑字串直接比較會誤判輸出資源越界。字串前綴比較也可能把 `output-private` 誤當成 `output` 的子目錄。

## 選項

1. 對路徑字串小寫化或比較字首；平台差異與目錄邊界仍不正確。
2. 對既有路徑使用 `toRealPath()`，對尚未建立的尾端路徑解析最近既有祖先後接回剩餘片段；以 Path 元件邊界判斷包含關係。

## 決定

採用選項 2。Java 共用 `RealPaths` 處理允許缺少尾端片段的正規化；安全讀寫仍透過 `SafeProjectFiles`，保留輸出根本身可用別名設定、但拒絕根目錄以下的符號連結與越界路徑。Node 的共用路徑邊界使用 `path.relative()` 的分段結果，不使用字串前綴。捕捉器將 `file:` 請求以 `fileURLToPath()` 解碼，再由 `resolveExistingFileWithin()` 做唯一的實際路徑驗證。

工作區設定載入及儲存時，專案根目錄、輸出根目錄與專案 context 設定鍵都正規化為實際路徑。互動式 `config` 若使用者輸入和採用值不同，輸出一行中文校正提示。越界預覽資源仍以結束碼 2 拒絕；CLI 只輸出中文摘要、相對化後的資源名稱及根目錄類型，不輸出例外堆疊或使用者絕對路徑。

## 後果

- 符號連結或大小寫別名的根目錄，在相同輸入下可產生逐位元組一致的輸出。
- `..`、輸出根以下的符號連結、輸出外資源與其他磁碟路徑仍遭拒絕。
- 系統採用作業系統回報的實際路徑；Windows 行為由平台測試覆蓋，但本次執行環境不是 Windows。
- 失敗測試先於實作提交：`999745a`。舊版在輸出根別名、工作區設定正規化與 CLI 符號連結輸出測試失敗；輸出根以下的外部符號連結也未被拒絕。
