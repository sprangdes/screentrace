# ADR 0115：R24 角色判定認得「物件為否時的可選存取」

## 背景

reservio 的訪客（`loading` 為否、`me` 為否）連首頁都只能判為「可能走到」。原因是整個 App 外層有 `!(me?.mustChangePassword) || ...` 這類判斷式：`me` 為否時 `me?.mustChangePassword` 一定是 `undefined`，判斷式一定成立，但判定規則只認得 `me?.role === "X"` 這種等式，不認得單純的 `me?.flag`。

## 決定

- R24-1：已知識別字為否時，直接接在它後面的可選存取（`name?.prop`，以及之後整條鏈）不可能為真。
- R24-2：只套用在 `?.` 緊接在該識別字之後、屬性名稱是一般識別字的情況；物件或基本型別都繼承的名稱（`Object`、`String`、`Number`、`Boolean` 原型上的名稱，例如 `toString`、`length`）與計算屬性（`name?.[key]`）不套用。
- R24-3：矛盾判斷重建條件時保留原本含 `?.` 的寫法，規則才看得到可選存取。

## 後果

reservio 訪客的首頁改為「會走到」，3 個畫面由無法判定改為適用。訪客與顧客其餘「可能走到」來自畫面狀態（選單是否打開、網址的 `?lineLogin=`、登入表單的回呼狀態），不是角色條件能決定的，屬於後續工作。
