# ADR 0124：R33 縮小的總覽上看得出每一區與每個畫面

## 背景

畫面超過 12 個時，總覽依網址第一段分區（ADR 0090 的區塊框）。區名與畫面名稱都畫在畫布裡、跟著畫布縮放；reservio 的 41 個畫面在 1440×900 的視窗下縮到約 17%，區名約 5px、畫面名稱約 3px，使用者看不出每一區是什麼、每張卡片是哪個畫面。需求方要求改善，但不要大改。

## 選項

1. 區名固定在可讀的字級，並在下面列出這一區前幾個畫面的名稱：採用。
2. 卡片夠大時讓畫面名稱固定字級：卡片在 70% 以上本來就顯示名稱，效果有限，這次不做。
3. 滑過卡片立即顯示名稱與網址：採用。
4. 大幅調整區塊的版面或預設縮放：改動大，不採用；只加高區塊頂端的標題帶。

## 決定

- R33-1：區塊的標籤（`.screen-group-label`）放在區塊框頂端的標題帶裡；標題帶由 64 加高到 200（`groups.ts` 的 `TITLE`），足以放下縮小時反向放大的兩行標籤。區塊之間的連線只走框與框之間的間隔，不會經過標籤；標籤不接收滑鼠事件（`pointer-events:none`），點擊會落到區塊。
- R33-2：標籤依縮放反向放大（`scale(clamp(1, 0.4667 / zoom, 2.4))`），區名在螢幕上約 14px；最多放大 2.4 倍以免超出標題帶，因此在縮放比例低於約 19% 的大型專案中區名會略小於 14px；放大到區名本來就比 14px 大時維持原本的大小。標籤最寬到區塊框的寬度，過長以「…」截斷。
- R33-3：區名下面一行列出這一區前 3 個畫面的名稱（依卡片由上而下、由左而右的順序，`areaPreview`），還有更多時加「…」；只在卡片小到看不清的縮放（`data-semantic-zoom=compact`，70% 以下）顯示。名稱取自 graph 已有的畫面名稱，不另外推測或歸納。
- R33-1a：曾試過把標籤放在框的上方、讓連線從標籤後方通過，但文字與線仍會互相遮擋，不採用。
- R33-4：標題帶加高讓整個總覽略高，適合畫面時的縮放比例稍微變小；區塊位置與連線的走法不變。
- R33-5：在縮小的總覽上滑過或用鍵盤移到卡片時，卡片下方（太靠近底部時改在上方）立即顯示畫面名稱與網址（`.card-tip`，`aria-hidden`，卡片本身的文字已提供名稱）；移動或縮放畫布、離開卡片或打開畫面時隱藏，放大到卡片看得清楚時不顯示。原本卡片上延遲出現的瀏覽器預設提示（`title`）移除，避免兩個提示重疊。
- R33-6：只改 viewer 的程式、樣式、測試與文件；分析與 graph JSON 不變；版面只加高區塊的標題帶。

## 後果

不放大也看得出每一區大概在做什麼，找特定畫面時滑過卡片即可確認；區塊與卡片的位置、縮放與互動都和原本相同。窄的區塊（只有一、兩欄畫面）區名會被截斷，滑過區塊框仍可看到完整區名。
