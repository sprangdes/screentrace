# ADR 0039：全站導覽、格狀流程與可讀明細

日期：2026-10-04。狀態：採用。WP20／G9／G10；不改 schema。

## 決定與邊界

- 全站導覽由 viewer overview.ts 分區：已識別連結／導覽元件，同目的、名稱與排序後全部屬性出現在至少兩個、且 ≥50% 畫面。不因兩個畫面的任意按鈕指向同處便當成版型導覽。混合畫面對保留頁面特有觸發者；開啟切換還原原始合併關聯，不重複計線。統計允許兩類交集，隱藏不刪圖、右欄與 API。
- 總覽以穩定 ID 排序格狀位置，邊走卡片外行／列走廊；保留方向箭頭、透明度與 hover 進出邊高亮。不新增布局相依。座標測試涵蓋循環、自我邊與全部畫面對，實際 PetClinic DOM 另驗證。
- 聚焦將全站導覽另分組，未解析目的合併為一個可選節點，但列出每個行為、觸發、原因與技術證據。欄位／核取方塊／表格收合；可操作項目與 API 呼叫來源使用共用 labels.ts。
- JspTagFileExpander 只對已知呼叫屬性的 fn:escapeXml(var) 做 XML 跳脫字面代入；未知函式、動態屬性不當透明函式。保留 tag 呼叫／定義來源；EL 與程式不執行。core 不加入框架名稱。
- diagnostics.ts 明確列出目前產生的全部代碼中文說明；測試掃描 producer，漏譯即失敗。中文種類收合，原訊息／檔案／行號完整換行，原英文代碼位於技術明細，全部以 textContent。
- 主要 URL 優先已存在直接 RENDERS 的端點，再以 GET／單一回傳分支排序；顯示選擇不新增端點或改信心。其他 route 候選仍保留與可 hover 查看。中心與目的卡片只列主要 URL，避免多路由清單淹沒預覽。

## 測試先行

5c4d85b：自行撰寫 tag fixture 2 測試全失敗；新版診斷斷言舊實作 3 測試中 1 失敗；初始 3 map 與 3 UI 測試均失敗。f34b340：直接 render 主要 URL 測試先失敗（預期 /records/{id}、實際 /records），並新增全部診斷代碼覆蓋檢查。既有斷言只改 OQ-014 授權三處，逐處原因見 ADR 0038；其他測試僅因新收合群組增加展開操作，斷言原文不變。

## 後果

呈現更清楚不代表分析信心提高。未設定前綴、缺資源、未知函式、候選歧義仍保留。分類是依圖資料的呈現規則，並非推測任意版型的執行結果；無法證明的 URL 不因布局而連線。真實預覽不同輸出根的背景資源路徑差異仍是既有可攜性缺口，本工作包不修。
