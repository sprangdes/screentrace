# ADR 0169：R94 推論狀態寫入前的原狀態

## 背景

R82（[ADR 0160](0160-r82-state-changes.md)）依需求方當時的決定只列「誰把狀態設成什麼」。需求方於 2026-11-18 改為：推論原狀態並標為推測（OQ-058）。

## 決定

- `BackendCallChains` 對每筆列舉寫入，從**同一個方法內、同一物件**的狀態讀取比較推論寫入前的值（`Prior`），寫入 `stateChanges` 的 `from`（只可能是這些值）、`fromNot`（不是這些值）、`fromCreated`（builder 新建立）與 `fromLines`（依據的條件行號）。
- 狀態讀取：`x.getStatus()`、`x.status`，或宣告一次、未再指定、初始值為前兩者的區域變數；`x` 的原文須與寫入的物件相同。比較：`==`、`!=`、`.equals(...)`，以及全為相等的 `||`、全為不等的 `&&`；比較的常數須屬於寫入的列舉。
- 依據：寫入所在的 `if` 分支（then 取條件、else 取相反）、寫入之前同一區塊中「條件成立就 `throw`／`return`」的守衛（取相反）、以狀態為選擇值的 `switch` 分支。其他條件（例如 `isEnded(x)`、另一個物件的狀態）不影響推論。`from` 與 `fromNot` 都有時，從 `from` 扣除 `fromNot`；只有 `fromNot` 時輸出 `fromNot`。
- 不跨方法：呼叫端的條件（例如另一個方法裡的 `switch` 再呼叫寫入的方法）不列入。
- viewer：狀態詳情每筆寫入加「原本：…（推測）」；API／作業詳情的「會改變的資料狀態」寫成「待確認（PENDING） → 已取消（CANCELLED）」並註明原狀態為推測。md §13 新增「原狀態(推測)」欄，說明文字改寫。

## 測試

- Java `R94PriorStateTest`（1）；viewer `r82-states.test` 新增 1 個。
- 修改的既有斷言：三份 md golden 只有 §13 說明句不同（以腳本把新句換回舊句後逐位元組相同）；`wp40-md-decision-equivalence` 雜湊更新，換回後等於 R86 的值。

## 後果

- reservio：顧客取消「待確認 → 已取消」「已確認 → 取消申請中」；商家處理取消申請「取消申請中 → 已取消／已確認」；商家變更狀態「不是已完成 → 依參數」；建立預約「新建立 → 待確認」。
- LINE 對話的步驟由另一個方法依狀態 `switch` 分派，原狀態推不出（不跨方法），多數步驟沒有原狀態。
