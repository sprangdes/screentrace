# ADR 0183 JSP 表單流程狀態變體

## 背景

同一個 JSP URL 依後端狀態顯示不同內容。預覽若同時展開「開始」「處理中」「已完成」等互斥分支，無法呈現實際操作順序。

## 決定

- 以 JSP 的字面狀態等值條件、提交按鈕的 `name/value`、Spring 請求契約以及轉址回同一畫面的關係推論狀態轉換。限定單一狀態欄位、唯一可推得的入口狀態及 2 至 8 個可達值。結果標為 INFERRED 並保留來源。
- 使用既有 `stateVariant`／`stateVariantOf` 畫面屬性。入口狀態沿用原畫面 ID，其他狀態各自產生圖節點、靜態文件與 PNG。條件可證明為假的元件從該畫面的歸屬排除。
- 捕捉器以畫面狀態代入受支援的 JSTL 比較，保留來源樣式。展示快照的選填資料預設為空。檢視器依提交按鈕的狀態導覽帶入獨立畫面，保留原端點用於 API 追溯。
- 此規則處理有限的表單流程。資料庫實際狀態、未解析的 EL、錯誤與其他條件的任意組合仍需另外的來源證據，畫面預覽使用合成資料。

## 驗證

合成 Spring JSP fixture 涵蓋三個狀態的元件歸屬、導覽關係和穩定的入口 ID。另以 insure 檢視待核保、核保中、核保通過與核保未通過的獨立預覽。
