# ADR 0120：R29 API 詳情的呼叫鏈圖與角色比較的重疊長條

## 背景

R28（[ADR 0119](0119-r28-visual-summaries.md)）為 API 頁與角色頁加上數量的圖形摘要，並把兩項留待後續：API 詳情的呼叫鏈圖，以及角色比較的重疊長條。現在 API 詳情要往下讀過處理程式與呼叫來源兩節，才看得出「哪些畫面 → 這個 API → 哪個處理程式」；角色頁「和其他角色比較」只列出各組的畫面數，要逐列比較數字。

## 選項

1. 呼叫鏈以 SVG 畫出每條連線：每個畫面與觸發元件各畫一條線，文字寬度要另外量測，排版複雜，不採用。
2. 呼叫鏈以三欄（畫面、API、處理程式）加上欄與欄之間的箭頭呈現，只用 CSS 與 DOM：採用。
3. 角色重疊改為多色堆疊長條：組數不固定，需要多種分類色，色覺差異的使用者不易分辨，不採用。
4. 角色重疊每組加一條長度依比例的單色長條：採用。

## 決定

- R29-1：API 詳情在狀態原因下方加呼叫鏈：左欄是呼叫這個 API 的畫面（依畫面名稱排序，每個畫面一格，下方寫觸發元件；同一畫面有兩個以上的觸發時寫「N 個觸發」，完整名稱放在提示文字），中欄是 API 本身（外框顏色依狀態），右欄是處理程式。
- R29-2：左欄與右欄最多顯示 5 格，其餘寫「還有 N 個畫面／處理程式」，完整清單仍在下方的「呼叫來源」與「處理程式」兩節。沒有呼叫來源或找不到處理程式時，以虛線格寫出。
- R29-3：點左欄的畫面與點「呼叫來源」中的畫面名稱相同，回到該畫面。畫面或它的所有呼叫來源已標記移除時，格子以刪除線與灰字呈現。
- R29-4：「和其他角色比較」每一組的標題加一條長條，長度是該組畫面數占這個角色流程畫面數的比例（四捨五入到整數百分比，至少 1%）；「只有這個角色」用保留色，共用的組用灰色。長條靠右對齊，各組可以直接比較長度。
- R29-5：與 R28-5 相同，圖形只呈現頁面上已有的數字與關係，不新增判定。呼叫鏈以 `role="group"` 與 `aria-label` 提供整條鏈的文字，箭頭與重疊長條對報讀隱藏。只用 CSS 與 DOM，不引入相依。

## 後果

開啟 API 詳情的第一眼就能看到呼叫來源的數量與處理程式；沒有呼叫來源的 API 以虛線格明顯標出。角色比較中各組的大小可以直接比較。呼叫鏈只呈現前 5 個畫面，畫面很多的 API 仍需往下看「呼叫來源」。
