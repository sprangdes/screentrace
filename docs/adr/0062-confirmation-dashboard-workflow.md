# ADR 0062：以既有決策模型擴充確認工作流

- 狀態：已接受（2026-10-07）
- 關聯：R10 WP37；R11 無模式決策介面

## 背景

R11 已讓三態決策常駐，並提供「已確認 N／M」進度標籤與簡易展開面板。WP37 要求在此基礎提供區域儀表板、可預期的下一項導覽、鍵盤決策、移除影響提示與匯出前檢查；重做模式開關或另建決策資料會違反 R11 及 WP37 的決策模型限制。

## 決定

沿用既有 `featureRegions`、`statistics`、`conflicts`、`deriveApiUsage`、`setScreen` 與 `setComponent`。新增純函式依既有區域排序、畫面 ID、畫面內元件 ID 排列確認目標；`n` 與標記後自動前進共用此順序。快捷鍵只在沒有輸入欄位焦點時處理。自動前進與「不再顯示匯出檢查」只存於瀏覽器偏好，不進 review state。

移除影響預覽以暫時套用既有移除決策後再次呼叫 `deriveApiUsage`，只顯示狀態因此成為 REMOVABLE 的 API；畫面流入關係與畫面元件數取自現有圖。保留既有衝突推導，並清楚註明靜態分析可能看不到外部或動態呼叫。匯出前摘要只讀既有決策與圖，確認後仍呼叫原 Markdown 產生器。

無終端機執行 `config` 時，回報專屬訊息「config 需要互動式終端機」，仍以結束碼 2 退出，不顯示通用 workspace 設定提示。

## 後果

不變更分析器、graph schema、API 狀態規則、review state 格式與 Markdown 內容。舊簡易進度面板擴為儀表板；確認操作沒有模式開關。測試涵蓋共用順序、進度與直接跳轉、自動前進、輸入欄位隔離、移除影響、衝突、匯出檢查摘要、Markdown 位元組不變及無互動終端機的 config 訊息。
