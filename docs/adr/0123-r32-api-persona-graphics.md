# ADR 0123：R32 API 方法色標、路徑參數、呼叫數長條，與角色頁改版

## 背景

R28、R29 已在 API 頁與角色頁加上狀態分布條、呼叫鏈與重疊長條，但 API 清單的每一列仍只有灰色的方法標籤、整段的網址文字與「N 個畫面」；角色頁一次只看得到一個角色，想知道「哪個畫面哪些角色到得了」必須逐一點開每個角色。需求方要求再加入圖形化元素，但不增加功能的複雜度。

## 選項

1. 在呼叫鏈放畫面縮圖：最直覺，但要載入封裝的預覽文件，報表變慢、程式變複雜，不採用。
2. 角色重疊改畫文氏圖：4 個角色以上畫不清楚，現有的比較長條已足夠，不採用。
3. 只把頁面已有的資訊換成顏色與形狀，不新增按鈕、篩選或狀態：採用。

## 決定

- R32-1：方法標籤依 `data-method` 上色：GET 藍、POST 紫、PUT／PATCH 青、DELETE 洋紅；其他方法維持灰色。這些顏色刻意避開狀態用的綠、黃、紅。
- R32-2：網址中 `{name}` 形式的參數以 `.api-path-param` 標示，用於清單列、詳情標題與呼叫鏈。拆分由 `pathParts` 負責，接回後與原網址相同，`textContent`、搜尋與 aria 標籤都不變；跨越 `/` 的大括號不算參數。
- R32-3：清單每一列的「N 個畫面」前加一條短長條（`aria-hidden`），長度是這個 API 的呼叫畫面數占全部 API 中最多者的比例；沒有呼叫來源時只有底色。比例由 `proportion.ts` 新增的 `sharePercent` 計算（有數量時至少 1%），R29 的 `overlapPercent` 改為同一個函式。
- R32-4：角色頁加上「畫面 × 角色」覆蓋表（`[data-persona-section=coverage]`），放在「全部角色對照」檢視中，只在有兩個以上角色、且至少一個角色走得到畫面時提供。列是任一角色走得到的畫面，依「第一個走得到它的角色、該角色的步數、畫面名稱」排序（`coverageScreens`）；欄是角色。每格一個點：實心是會走到，空心圈是可能走到，灰色小點是走不到或不適用。走得到的點是按鈕，點了以那個角色打開畫面；點欄標題的角色名稱會回到那個角色的流程看板。表格寬度依角色數計算（名稱欄 320px，每個角色 72px），避免寬螢幕上點和畫面名稱離太遠。
- R32-5：API 頁詳情區原本最寬 880px 並靠左，寬螢幕右側留下大片空白。視窗寬度 1360px 以上時，詳情區最寬 1440px，標題、原因與呼叫鏈仍佔滿整列，其下分成左右兩欄：左欄是處理程式與 Request／Response，右欄是呼叫來源。較窄時維持單欄，區塊順序與原本相同。
- R32-5a：角色頁不再沿用 API 頁的左右版面（取代 ADR 0114 的版面決定，ADR 0119 的每步直條也由看板取代）。最上方是角色卡片（`.persona-cards`，仍是 listbox，上下左右鍵都能切換）與「全部角色對照」切換鈕（`[data-persona-compare-all]`，`aria-pressed`）。選了角色時，下方左邊是流程看板（`.persona-board`）：每一步一欄（`[data-persona-step]`），每個畫面一張卡片（`.persona-card[data-reach]`），可能走到的卡片是虛線框並附「可能走到」；右邊 320px 是判定條件、起點、和其他角色比較與流程以外。視窗寬度 1100px 以下時右欄移到看板下方；步數多時看板橫向捲動。切換到全部角色對照時，下方換成覆蓋表，卡片不顯示選取。離開角色頁再回來時，保留上次的角色與檢視。
- R32-5b：兩頁的主要兩欄改成比例配置並可調整寬度：API 頁的清單預設占頁寬 30%（20%～50%，至少 280px），角色頁的條件與比較欄預設占 28%（20%～45%，至少 260px）。兩欄之間是共用的分隔線（`splitter.ts`，`role=separator`）：拖曳調整；方向鍵每次 2%，Home／End 到兩端，按兩下或 Enter 恢復預設。比例只在報表開著時記住，切換分頁或角色時不變，重新開啟報表回到預設；不寫入瀏覽器儲存，避免不同報表互相影響。單欄版面（API 頁 900px 以下、角色頁 1100px 以下）不顯示分隔線。API 詳情內的左右兩欄已是 1:1，不加分隔線。
- R32-5c：viewer 中 15px 以下的字級各放大 1px（最小字 11px→12px、內文 14px→15px、說明與標籤 12px→13px、13px→14px），18px 以上的標題不變，讓標籤、網址與說明文字較易閱讀。
- R32-5d：移除畫布左上角的操作提示（「點一下畫面看關聯 · 點兩下開啟畫面 · n 下一個未確認 · / 搜尋」）；這些操作已寫在使用說明與「?」說明中。有角色按鈕時，左上角只留角色按鈕，總覽的定位改以角色按鈕的下緣為準。
- R32-5e：畫布旁的畫面清單也改為比例寬度：預設占視窗 18%（1440px 視窗為 260px，14%～35%，至少 200px），取代原本依視窗寬度分段的 260／220／200px。分隔線放在清單右緣，沿用 `splitter.ts`；為了讓清單收合、展開的寬度動畫照舊，比例以不帶單位的 `--list-split` 寫在 `.shell` 上，由樣式表乘以 1vw 換成長度。清單收起或在聚焦畫面時改為浮動清單時不顯示分隔線；拖曳時暫停寬度動畫。
- R32-6：判定條件的 ✓／✕ 標記已在 R28 完成，本次不再修改。
- R32-7：只改 viewer 程式、樣式、測試與文件；分析、graph JSON 與 Java 不變。圖形只用 CSS 與 DOM（ADR 0019）。

## 後果

API 清單掃一眼就能分出讀取與寫入、看出網址中的參數，以及哪些 API 被大量畫面共用；角色頁不必逐一點開角色，就能看出每個畫面哪些角色到得了；角色頁的流程改成一眼看得出步數與每步畫面的看板；寬螢幕上兩頁都不再只用左半邊。報表的 graph 與封裝資料不變，只有 viewer 的 HTML 輸出改變。
