# ADR 0123：R32 API 方法色標、路徑參數、呼叫數長條與角色覆蓋表

## 背景

R28、R29 已在 API 頁與角色頁加上狀態分布條、呼叫鏈與重疊長條，但 API 清單的每一列仍只有灰色的方法標籤、整段的網址文字與「N 個畫面」；角色頁一次只看得到一個角色，想知道「哪個畫面哪些角色到得了」必須逐一點開每個角色。需求方要求再加入圖形化元素，但不增加功能的複雜度。

## 選項

1. 在呼叫鏈放畫面縮圖：最直覺，但要載入封裝的預覽文件，報表變慢、程式變複雜，不採用。
2. 角色重疊改畫文氏圖：4 個角色以上畫不清楚，現有的比較長條已足夠，不採用。
3. 只把頁面已有的資訊換成顏色與形狀，不新增按鈕、篩選或狀態：採用。

## 決定

- R32-1：方法標籤依 `data-method` 上色：GET 藍、POST 紫、PUT／PATCH 青、DELETE 洋紅；其他方法維持灰色。這些顏色刻意避開狀態用的綠、黃、紅。
- R32-2：網址中 `{name}` 形式的參數以 `.api-path-param` 標示，用於清單列、詳情標題與呼叫鏈。拆分由 `pathParts` 負責，接回後與原網址相同，`textContent`、搜尋與 aria 標籤都不變；跨越 `/` 的大括號不算參數。
- R32-3：清單每一列的「N 個畫面」前加一條短長條（`aria-hidden`），長度是這個 API 的呼叫畫面數占全部 API 中最多者的比例；沒有呼叫來源時只有底色。比例由 `proportion.ts` 新增的 `sharePercent` 計算（有數量時至少 1%），R29 的 `overlapPercent` 改為同一個函式。
- R32-4：角色頁詳情加上「畫面 × 角色」覆蓋表（`[data-persona-section=coverage]`），只在有兩個以上角色、且至少一個角色走得到畫面時出現。列是任一角色走得到的畫面，依「第一個走得到它的角色、該角色的步數、畫面名稱」排序（`coverageScreens`）；欄是角色。每格一個點：實心是會走到，空心圈是可能走到，灰色小點是走不到或不適用。走得到的點是按鈕，點了以那個角色打開畫面；點欄標題的角色名稱等同在清單選那個角色，選取的角色欄會加上底色。表格最寬 560px，避免寬螢幕上點和畫面名稱離太遠。
- R32-5：詳情區原本最寬 880px 並靠左，寬螢幕右側留下大片空白。視窗寬度 1360px 以上時，詳情區最寬 1440px，標題、原因與呼叫鏈仍佔滿整列，其下分成左右兩欄：API 頁左欄是處理程式與 Request／Response，右欄是呼叫來源；角色頁左欄是判定條件、起點與流程，右欄是和其他角色比較、畫面 × 角色與流程以外。較窄時維持單欄，區塊順序與原本相同。左欄的角色清單不再放其他內容。
- R32-6：判定條件的 ✓／✕ 標記已在 R28 完成，本次不再修改。
- R32-7：只改 viewer 程式、樣式、測試與文件；分析、graph JSON 與 Java 不變。圖形只用 CSS 與 DOM（ADR 0019）。

## 後果

API 清單掃一眼就能分出讀取與寫入、看出網址中的參數，以及哪些 API 被大量畫面共用；角色頁不必逐一點開角色，就能看出每個畫面哪些角色到得了；寬螢幕上兩頁的詳情區左右均衡，不再只用左半邊。報表的 graph 與封裝資料不變，只有 viewer 的 HTML 輸出改變。
