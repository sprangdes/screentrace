# ADR 0188 Spring MVC／JSP 依存取規則推論角色並依角色呈現

## 背景

insure 明顯有兩種使用者：免登入投保的一般用戶，以及在 `/admin/login` 登入的後台管理員。報表卻看不出來，所有畫面混在同一張圖。原因是角色功能只支援 React：ADR 0107（R19-4）規定只有 React 畫面帶角色資訊，ADR 0167 的自動建議也只讀 React 的路由守衛。insure 的分析結果沒有任何角色，而登入頁的預覽還會顯示只有登入後才出現的後台導覽列。

insure 的原始碼其實寫明了角色：`AccessFilter` 對 `/admin` 開頭（`/admin/login` 除外）、工作階段沒有 `operator == TRUE` 的請求轉到 `/admin/login`；登入成功設定 `operator`，登出清除工作階段；`admin-layout.jsp` 只在 `sessionScope.operator eq true` 時顯示導覽列。

## 決定

本 ADR 擴充 ADR 0107 與 ADR 0167：Spring MVC／JSP 專案也有角色，來源是應用程式自己的存取規則。

- **存取規則（`SpringSessionRoles.rule`）。** 讀實作 `Filter`／`HandlerInterceptor`（或繼承 `OncePerRequestFilter`、`GenericFilterBean`）的類別中 `doFilter`／`doFilterInternal`／`preHandle` 的 `if`：條件為「路徑 `startsWith` 前綴」且「`!Boolean.TRUE.equals(session.getAttribute("屬性"))`」或「`getAttribute("屬性") == null`」，可另有 `!"路徑".equals(path)` 排除；成立時 `sendRedirect` 到登入頁。路徑變數必須來自 `getServletPath()`／`getRequestURI()`。只有找到唯一一條規則時採用。
- **畫面的工作階段事實。** 畫面的所有 RENDERS（轉址不算，轉址的頁面由後續的 GET 呈現；例外處理器依其 servlet 路徑條件）都在受保護前綴下時，記錄 `sessionFacts = {"sessionScope.屬性": true}`；由登入頁網址呈現且沒有受保護網址時記為 false。`JspScreenFacts` 與預覽據此判斷 `${sessionScope.operator eq true}` 等條件：登入頁不再顯示後台導覽列，後台頁面顯示。元件在唯一的畫面上條件不成立時保留歸屬並註明不顯示，以維持圖的完整性。
- **自動建議角色。** 專案沒有手動設定角色時建議兩個角色：「一般用戶」（屬性未設定，從 `/` 開始）與登入後的角色（屬性為 true，從登入頁開始，名稱取自登入頁 `<h1>` 去掉「登入」，例如「後台管理員登入」→「後台管理員」，取不到時為「管理者」）。描述以「自動建議」開頭並寫出規則來源。報表不顯示自動建議的描述（只顯示分析人員在 `config.json` 寫的描述），角色只以名稱、走到的畫面數與判定條件呈現；描述仍保留在圖中供追溯。
- **角色流程。** 由 Spring 圖直接計算：起點是角色起始網址的 ENTRY_POINT（新增節點，RENDERS 到起始畫面）；從每個畫面依其連結與表單（守衛以角色事實、畫面模型事實、狀態值與請求模式判斷）找到端點，再依 handler 的 RENDERS／FORWARDS_TO（連結的實際網址與查詢參數可選分支）前往畫面。受保護的端點對一般用戶不前往。handler 正常流程（ADR 0186）的目的與元素確定顯示時為「會走到」，其他分支、狀態切換、請求模式不一致時為「可能走到」。`PersonaFlows` 保留轉接器已算好的流程。
- **報表依角色呈現。** 每個畫面歸屬於唯一走到它的角色，多個角色都走到為「共用」，都走不到為「其他」：
  - 畫布預設依角色分區（取代網址分區）；角色切換仍可只看單一角色的流程。
  - 功能頁以角色為第二層，每個角色下的功能畫面依該角色流程的步驟排序；左側「功能」與「清單」以角色標題分段；預覽工具列顯示畫面所屬角色。
  - 同一 JSP 頁的狀態畫面與請求模式畫面歸入其本體畫面的功能。
  - 角色相關的畫面只呈現角色會走到與可能走到的畫面：角色流程圖不提供「顯示走不到、不適用的畫面」，左側清單、角色頁（流程以外、角色卡比例條）與全部角色對照不列走不到／不適用的畫面或圖例。圖中仍保留這些判定供追溯。
  - 每個角色有一個固定的淡底色（依角色順序：藍、琥珀、綠、紫；「共用」淡青，「其他」維持中性灰），畫布的角色區塊與單一角色流程圖的步驟欄、角色切換按鈕、左側角色標題與摘要、功能頁的角色節點、預覽工具列的角色標籤、角色頁的角色卡與步驟欄都使用同一個顏色。

## 限制

- 只處理單一、以路徑前綴與工作階段屬性表示的規則；Spring Security 設定、多條規則、以資料庫判斷的權限需要分析人員在 `config.json` 手動設定（Spring／JSP 的手動角色仍未支援）。
- 「一般用戶」可進入的公開頁面，後台角色也能開啟，但只計入其流程走到的畫面。

## 驗證

`spring-jsp.test.mjs` 以 `Guard` 過濾器（`/back` 需 `staff`）與登入處理方法驗證：schema 2.4、兩個角色與名稱「員工」、起點、畫面工作階段事實、登入頁上條件不成立的元件、一般用戶排除後台畫面、員工流程走到登入與後台首頁。insure：一般用戶會走到 10、可能走到 6（核保結果、繳費、錯誤頁）；後台管理員依序走到登入 → 申請總覽 → 待核保 → 核保中 → 核保通過／未通過；畫布、功能頁與清單分為「一般用戶」「後台管理員」「其他」；以模擬操作時登入前沒有後台導覽列，登入後才出現。
