# ADR 0057：全站導覽使用語意欄位分組

狀態：已採用（R10 WP34）

## 背景

總覽以元件目的、名稱和屬性判定跨畫面的同一導覽項目。R7 為每次 tag 展開加入唯一的 `expansionAnchor` 後，整份屬性被序列化進分組鍵，導致同一導覽項目在不同畫面無法合併。

## 決定

分組鍵只使用目的畫面、可見元件名稱與具名白名單：`kind`、`tag`、`componentType`、`href`、`target`、`httpMethod`。白名單按固定順序序列化。錨點、元件 ID、來源檔案／行號及其他溯源屬性不表示導覽項目本身，故不參與分組。保留逐畫面、同目的地的特有連結為流程。此規則只改 viewer 呈現，不改圖、分析或決策資料。

## 測試與斷言紀錄

新測試 `screentrace-viewer/test/wp34-global-navigation.test.mjs` 使用四個畫面；每個畫面各有三個相同名稱／目的、但 `expansionAnchor` 不同的全站導覽元件，另有一條獨有流程連結。新測試在修正前實際失敗：全站導覽為 0（預期 12），證明舊版無法通過新行為要求。此為新增測試，沒有修改或刪減既有斷言；R5 的同一目的地仍保留畫面特有流程測試也繼續通過。

## 影響

viewer 其餘以屬性建立的鍵或比較僅處理明確欄位／候選陣列，沒有第二處以整份元件屬性做導覽分類。列舉／溯源資料的其他用途維持原狀。
