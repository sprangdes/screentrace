# R16：Struts 1 分析補正（WP54、WP55）

## WP55 規則與 WP10 合成 fixture

OQ-029（方案 C）已套用：被其他 definition `extends` 的 definition，或只由 `put`／`put-attribute`／`insert` 引用的 definition，分類為版型／片段；其餘 definition 一律保留為畫面，沒有入口時照實標示。非 Tiles JSP 不因沒有入口移除。被 page definition 引用的片段內容歸入引用畫面；沒有 page definition 引用的版型／片段保留為無入口畫面。

`fixtures/wp10/struts1` 實際畫面是 `page`（`src/main/webapp/WEB-INF/views/page.jsp`，有直接入口）與 `outer`（`WEB-INF/tiles-defs.xml:1`，無入口），共 2 個。實際輸出符合要求。`base`、`child`、`nested` 與其 composition JSP 不再各自增加畫面；`outer` 仍保留自己的畫面及元件。

行為來源不變量取自 WP55 前 commit `27a5af6` 的 graph：49 個 `(檔案, 行號, 行為類型)` tuple。WP55 後 graph 有 53 個 tuple，49 個舊 tuple 全部仍存在，未找到遺失 tuple；新增 4 筆為設定／Struts config 的行為證據來源，不用來替代舊來源。測試 `wp10BehaviorSourceTuplesBeforeWp55RemainPresentAfterTilesDeduplication` 每次比較完整集合。

| 移除的版型／片段 | 證據 | 去重後仍保留的行為來源 |
|---|---|---|
| `base` | `tiles-defs.xml:1`；`child` extends `base`；template `layout.jsp`、put `page.jsp` | `page.jsp:3–28`、`js/module.js:1`、`js/module-helper.js:1`、`js/owned.min.js:1` 的來源仍在 page／outer 畫面；49 tuple 不變量全數通過 |
| `child` | `tiles-defs.xml:1`；`outer` extends `child` | 同上；繼承只改變畫面歸屬，不刪除來源 |
| `nested` | `tiles-defs.xml:1`；`outer` 以 `put-attribute` 引用 `nested`，其 path 是 `page.jsp` | page.jsp 的元件與行為歸入引用畫面；`page` 仍是直接 JSP 畫面 |
| `layout.jsp` 隱含 JSP 畫面 | 僅由 `base` 作為 template 引用；檔內 insert 是 attribute 名稱，無自身行為 | 此 JSP 無獨立行為來源；頁面行為仍由上述 49 tuple 測試鎖定 |

WP10 golden 授權範圍只涉及 `screens` 與 `behaviors_by_type`。`screens` 從 6 更新為 2；正確修正後 behavior 數與原 golden 一致，因此沒有改寫 `behaviors_by_type`。其他欄位及其他 golden 都未動：

| 欄位 | 修正前 golden | 修正後實際值 | 是否改檔 |
|---|---:|---:|---|
| `screens` | 6 | 2 | 是 |
| `behaviors_by_type.CALL_API` | 49 | 49 | 否 |
| `behaviors_by_type.NAVIGATE` | 12 | 12 | 否 |
| `behaviors_by_type.OPEN_DIALOG` | 28 | 28 | 否 |
| `behaviors_by_type.SELECT_CHANGE` | 2 | 2 | 否 |
| `behaviors_by_type.SUBMIT_FORM` | 10 | 10 | 否 |
| `behaviors_by_type.UI_STATE_CHANGE` | 20 | 20 | 否 |

| `behaviors_by_type.VALIDATE` | 26 | 26 | 否 |

前置錯誤實作 `0e39ee0` 的失敗證據：`wp10FixtureKeepsUnroutedPageDefinitionAndDirectJspAsScreens` 預期 `{page, outer}`、實際只有 `{page}`；未入口 page definition 測試亦失敗。該 graph 只有 1 個 screen，behavior summary 為 CALL_API 28、NAVIGATE 7、OPEN_DIALOG 22、SELECT_CHANGE 2、SUBMIT_FORM 9、UI_STATE_CHANGE 11、UNKNOWN 20、VALIDATE 19，因此新 `screens=2` 與原有各 behavior 數在錯誤實作上均不成立。失敗測試先於對應實作提交。

八個模組均以 `analyze`、`report` 重跑；分析目標只讀，沒有啟動範例應用或發送請求，圖、預覽及 HTML 寫在封存目錄外。CLI 使用 `/dev/null` 標準輸入。實際命令：

```sh
java -Duser.home=<workspace-home> -jar screentrace-cli/target/screentrace-cli-0.1.0-SNAPSHOT.jar analyze <module> < /dev/null
```

R15 到 R16 的變化以可證明的 URL alias 與 forward 修正為主；WP55 只收斂 Tiles 畫面與片段歸屬。`faces-example2` 的 13 個畫面由 6 個 page definitions 與 7 個獨立 JSP 畫面組成；`.base`、`.loggedoff`、`.loggedon` 不列為畫面。`layout.jsp` 仍保留為無入口畫面：Tiles definition 使用 `/layout.faces`，該路徑沒有唯一、直接的 JSP 檔案證據；`layout.jsp` 中的 attribute insert 也沒有可證明的 page-definition 檔案引用，因此依 OQ-029 不猜測並保留。
