## WP55 規則與 WP10 合成 fixture

OQ-029（方案 C）已套用：被其他 definition `extends` 的 definition，或只由 `put`／`put-attribute`／`insert` 引用的 definition，分類為版型／片段；其餘 definition 一律保留為畫面，沒有入口時照實標示。非 Tiles JSP 不因沒有入口移除。被 page definition 引用的片段內容歸入引用畫面；沒有 page definition 引用的版型／片段保留為無入口畫面。

`fixtures/wp10/struts1` 實際畫面是 `page`（`src/main/webapp/WEB-INF/views/page.jsp`，有直接入口）與 `outer`（`WEB-INF/tiles-defs.xml:1`，無入口），共 2 個。實際輸出符合要求。`base`、`child`、`nested` 與其 composition JSP 不再各自增加畫面；`outer` 仍保留自己的畫面及元件。

行為來源不變量取自 WP55 前 commit `27a5af6` 的 graph：49 個 `(檔案, 行號, 行為類型)` tuple。WP55 後 graph 有 53 個 tuple，49 個舊 tuple 全部仍存在，未找到遺失 tuple；新增 4 筆為設定／Struts config 的行為證據來源，不用來替代舊來源。測試 `wp10BehaviorSourceTuplesBeforeWp55RemainPresentAfterTilesDeduplication` 每次比較完整集合。

| 移除的版型／片段 | 證據 | 去重後仍保留的行為來源 |
|---|---|---|
| `base` | `tiles-defs.xml:1`；`child` extends `base`；template `layout.jsp`、put `page.jsp` | `page.jsp:3–28`、`js/module.js:1`、`js/module-helper.js:1`、`js/owned.min.js:1` 的來源仍在 page／outer 畫面；49 tuple 不變量全數通過 |
| `child` | `tiles-defs.xml:1`；`outer` extends `child` | 同上；繼承只改變畫面歸屬，不刪除來源 |
| `nested` | `tiles-defs.xml:1`；`outer` 以 `put-attribute` 引用 `nested`，其 path 是 `page.jsp` | page.jsp 的元件與行為歸入引用畫面；`page` 仍是直接 JSP 畫面 |
| `layout.jsp` 隱含 JSP 畫面 | 僅由 `base` 作為 template 引用；檔內 insert 是 attribute 名稱，無自身行為 | 此 JSP 無獨立行為來源；頁面行為仍由上述 49 tuple 測試鎖定 |
