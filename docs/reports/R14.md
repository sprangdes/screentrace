## eMusicStore 查核

| 查核項目 | 實際結果 |
|---|---|
| View Product Inventory、Edit Product、View Product | 三個動態 JSP 連結各新增一條 INFERRED 畫面關聯，來源分別為 productInventory.jsp 與 productList.jsp 的原始 spring:url 樣板。 |
| deleteProduct | JSP URL 可匹配 /admin/productInventory/deleteProduct/{productId} 樣板；透過 handler 的 redirect 新增通往 Product Inventory 的 INFERRED 畫面關係。原始 handler 是一般 Spring MVC 畫面端點，不是 REST_API；因此結果是畫面導向，不標為 API 呼叫。 |
| /rest/cart endpoint 類別 | GET、PUT cart、PUT add、DELETE cart、PUT remove 共 5 個皆為 REST_API。 |
| 4 個帶動態前綴的 JS 呼叫 | 分析追蹤到 $http 呼叫與來源（包含 CART 的 ng-init 畫面載入），但 URL 是 /eMusicStore/rest/cart/...。workspace contextPaths 為空，專案沒有 server.servlet.context-path 設定；不能證明 /eMusicStore 是 context path，因此不剝除。相關呼叫維持 UNRESOLVED，5 個 /rest/cart endpoint 狀態均為 UNREFERENCED。 |
| PUT /rest/cart/{cartId} | UNREFERENCED，符合要求。 |
| Login | autoRedirect=LOGIN_PAGE；evidence 指向 applicationContext.xml 的 /admin/** 保護規則與登入頁設定。 |

R14 §4 原列「deleteProduct 與 4 個 /rest/cart endpoint 各有 INFERRED 呼叫來源」。實際靜態證據只足以證明 deleteProduct 是導向至一般 MVC handler 的畫面行為；四個 JS 呼叫的 path 前綴缺少 context path 證據。沒有為了符合預期而把畫面導向改成 API 呼叫，也沒有猜測 context path。此項需要需求方提供明確 workspace context path 或專案設定後才能重新驗證。
