# R17：回到主要流程，全面簡化

## 第一階段（WP60＋WP61，並提前完成 WP64）

### 結果

- 報表只剩「畫面」「API」兩頁。頂部列：頁籤、確認進度（點開可看保留／移除／未確認數量與衝突）、暫存狀態、下載 md、開啟 md、說明（?）。
- 左側欄：一個搜尋框（實際 URL 或畫面名稱，沿用路由樣板比對）、清單／檔案結構切換、狀態篩選（全部／未確認／保留／移除）。
- 中間：未選畫面時是畫布（保留原排版，移除泳道）；選了畫面是完整預覽，可點按鈕模擬操作。
- 右側欄：畫面名稱與網址、三段式決定（保留／移除／未確認）、衝突與 JSF 提示、按鈕清單（預設收合，頁首頁尾按鈕另成一組）、呼叫的 API、從哪些畫面可來到這裡。
- API 頁：一張清單，狀態只有使用中／未被使用／可移除；點一筆展開呼叫來源，點來源回到畫面並標出該按鈕。
- 快捷鍵：k／x／u 標記、n 下一個未確認、/ 搜尋、Esc 返回畫布、Alt＋←／→ 預覽歷史。
- §2 移除清單全部移除，被刪的模組與測試見 [ADR 0084](../adr/0084-r17-two-page-report-and-retired-tests.md)。

## 第二階段（WP62＋WP63）

### 結果

- 點畫布上的畫面（或左側清單、右側欄連結、`n`）：同一張畫布平移縮放到該畫面，其他畫面淡出，中央顯示完整預覽；四周是它出發的關聯線，方向與原畫布相同。
- 滑過線：顯示目的畫面名稱、網址、縮圖與觸發按鈕，預覽中同時以藍框標出那些按鈕。點線（或 Enter）移動到目的畫面。
- 目的無法確定的出口畫成框下方的短虛線，滑過顯示「無法確定前往哪個畫面」，不可前往。
- Esc、「返回畫布」、在線區滾輪向下：縮回原本的畫布位置。
- 放大時左側畫面清單自動收成左緣細條，讓預覽框更大；點細條在原位展開，清單頂端的按鈕可收起，`/` 也會展開（需求方檢視後追加）。
- 在預覽中點擊：唯一目的直接前往；多個候選在點擊處列出（縮圖＋名稱）；表單不做檢核攔截；API 呼叫顯示一行提示；彈窗照舊。

設計與測試見 [ADR 0085](../adr/0085-r17-canvas-zoom-focus-and-click-simulation.md)。

### 驗證

- `npm --prefix screentrace-viewer test`：全部通過。
- `node --test test/*.e2e.mjs`：全部通過（含新增 `r17-focus.e2e`）。
- `mvn -o verify`：通過。

**第二階段完成，停止等待需求方檢視外觀與手感。**

## 第三階段（WP65＋WP66）

### 結果

- 第一次標記時，頂部「進度檔」選單自動展開，請使用者選擇 md 存放位置（可稍後）。之後每次標記自動寫入，狀態顯示「已自動儲存」。
- 重新開啟報表：顯示「繼續上次進度：<檔名>」，點一下取得授權並載入；仍有授權時自動載入。進度檔內容優先於瀏覽器暫存。
- 寫入失敗時保留決策並可重試；不支援的瀏覽器退回瀏覽器暫存＋下載／開啟 md。
- md 一律匯出 v1，正文移除元件庫、樣式、原因／備註與 API 信心欄；舊 v2、v3 檔仍可開啟。

設計與測試見 [ADR 0086](../adr/0086-r17-progress-file-autosave-and-md-v1.md)。

### 技術驗證

Chromium 以 `file://` 開啟時，檔案選擇 API 與 IndexedDB 均可用（ADR 0086）。原生存檔視窗與重新開啟後授權須在實際 Chrome 中手動確認：需求方於 2026-10-11 以驗證頁及報表在 Chrome 實測，選擇存檔位置、寫入、重新開啟後授權並帶回進度皆成功。

**第三階段完成，需求方已驗收（2026-10-11）。**
