## WP16 查證

1. **元素樣式：**擷取器為每個非 `script`／`style` DOM 元素保存穩定路徑及相對乾淨瀏覽器預設值的 computed-style 差異；單一報表中相同差異以雜湊共用。inline CSS、封裝後的本機外部 CSS 與繼承後的 computed 結果都反映在差異值中，不輸出 CSS 原始碼。點選普通段落元素的 Chromium E2E 測試確認右欄顯示顏色、字重及來源。擷取上限為每頁 50,000 元素、樣式字典 16 MiB；超限會產生診斷並保留資料。瀏覽器無法計算或未成功封裝的樣式不保證完整，須檢查預覽診斷。
2. **檔案結構與實際 URL：**新增測試確認 `/orders/7` 匹配 `/orders/{id}`、`.do` 副檔名路由可匹配。context path 只從圖中 `UrlResolution` evidence 的「採用值」讀取；測試確認 `/shop/orders/7` 會剝除已記錄的 `/shop` 並比對路由，沒有採用值時不猜測。
3. **四種框架流程：**Chromium `file://` E2E 分別對 `struts1`、`struts1-spring`、`spring-mvc-jsp`、`spring-boot-jsp` 執行總覽、聚焦、關聯線 hover、右欄按鈕資訊、review 標記、md 匯出、清除 localStorage、md 匯入及決策還原。四項均通過。另有獨立 Chromium E2E 以實際滑鼠 hover 關聯線並確認 URL 提示。
4. **150 畫面／600 關聯：**Chromium 實測總覽載入 51 ms、切換聚焦 56 ms、搜尋回應 15 ms；均低於 3 秒目標。此為單次本機量測，非跨環境效能保證；本輪未做效能調校。

查證未發現需要改動分析邏輯或圖 schema 的缺陷；未更新 WP10 golden。使用者指南與架構文件已同步更新。畫面結構未改變既有截圖所示功能，因此沒有重拍截圖。
