## OQ-016 補強與最終驗證

失敗測試先提交 e6f1bcf：同一合成專案輸出到兩個目錄，原實作 styleId 不同，且最終 HTML 含實際輸出路徑，2 項皆失敗。新測試直接使用正式 packed documents 工具；檢查 HTML、styles、styleId、defaults、packed documents 逐位元組一致，同時保存 capture 原始 bytes。另新增 query／fragment 的失敗邊界再修正，以及越界 URL 拒絕測試。括號輸出目錄反例也先失敗，再補正引號內的 URI 邊界。既有測試斷言與 golden 完全不變。

影響的正式程式只有 `screentrace-report/src/main/java/io/screentrace/report/PreviewCaptureReader.java`：所有 CSS 屬性的本地 file URI 與 defaults 轉為 output-relative 穩定識別，重算改變的 styleId 與元素引用；原始 capture 不覆寫。新增 `PreviewResourceDeterminismTest.java`，文件更新 ADR 0047、ARCHITECTURE、OPEN_QUESTIONS、ROADMAP 與本報告。分析器、graph schema、共用 API 向量、md 模組及 packed documents 程式未改。

最終完整驗證：**255 Java／40 JS／55 viewer／33 capture／67 Chromium E2E，全部通過，沒有 skipped**。WP10 `SyntheticProjectIntegrationTest.sourceOnlyCliPipelineTwiceProducesIdenticalGraphPreviewAndHtmlAndRejectsStrutsTwo` 仍通過；原 fixture 的圖／preview／HTML／md 決定性與 golden 比對、API 向量、md 往返、安全測試均保留。沒有新增相依。遠端 CI 未執行。

對兩個真實專案的既有原始 capture，僅重新執行報表資料讀取／產生（不重新 capture、不改分析器）。四個結果目錄合計 **152 檔原始 static-preview、application-graph、viewer-documents** 的 SHA-256 前後完全相同。Petclinic 原有 465 檔、eMusic 160 檔來源也仍與基線一致。每個專案的兩個不同結果目錄，application-graph、preview-model、packed documents 與最終 HTML 現在全部逐位元組相同。

最終 HTML 全文掃描實際兩個輸出根、實際目標專案根、當前使用者家目錄，以及 `file://`、`/Users/`、`C:\Users\` 與 JSON 跳脫形式，均無命中。補強前逐欄位掃描只有 Petclinic 的兩筆 background-image 洩漏，沒有其他欄位需要保留絕對路徑。合成測試另涵蓋 border-image-source、cursor、list-style-image、mask-image、多 URI、defaults、Unicode／空白與 query／fragment；data URI 保留。輸出根之外或無效 URI 被明確拒絕，錯誤不帶原始路徑。
