## 根因與修正

預覽擷取器把瀏覽器回報的 `file:` 資源路徑，與設定檔內的輸出根目錄字串直接比較。macOS 的 `/var`→`/private/var` 別名與大小寫變體因此被當成輸出外資源。其他限制也有字首比較的風險，例如 `output-private` 不應被視為 `output` 的子目錄。

新增共用 `RealPaths`：既有路徑使用 `toRealPath()`，尾端尚不存在時先解析最近既有祖先再接回缺少片段。Java 預覽資料正規化、安全檔案邊界、CLI 專案目錄排除都使用實際路徑。工作區設定載入／儲存會正規化專案根目錄、輸出根目錄與 context 設定鍵；`config` 輸入拼法與實際路徑不同時輸出一行校正提示。Node 的 containment 檢查改用 `path.relative()` 的路徑元件，不依賴字串前綴；file URL 以 `fileURLToPath()` 解碼後交給共同安全讀取器驗證。

根目錄本身可以用符號連結作為設定別名；根目錄下的符號連結仍拒絕。`..` 逃逸、外部資源、其他磁碟路徑也仍拒絕。CLI 對越界預覽資源回傳結束碼 2，只顯示中文摘要、相對化資源名稱及根目錄種類，不輸出堆疊或絕對路徑。

## 路徑檢查盤點

| 檢查位置 | 實際路徑判定／安全結論 |
|---|---|
| `SafeProjectFiles` | 讀取以 `toRealPath()` 及 canonical root 的 `Path.startsWith` 元件邊界判定；讀寫保留根目錄別名，根目錄以下的符號連結、越界路徑拒絕。此處 `Path.startsWith` 比較路徑元件，不是字串前綴。 |
| `PreviewCaptureReader` | 輸出根與資源解析成實際路徑後判定，使用 `relativize` 產生穩定資源鍵；外部符號連結解析後越界即拒絕。 |
| `ProjectScanner` | 先 canonicalize 專案根，再以未啟用 FOLLOW_LINKS 的 `walkFileTree` 遍歷；符號連結項目略過。相對來源路徑由 canonical root 產生。 |
| `ProjectCatalog` | 排除輸出目錄時比對 `RealPaths.isSame`；避免根目錄大小寫／符號連結別名使輸出目錄被列作專案。 |
| `JspProjectParser`、Spring／Struts include 解析 | include 候選實際讀取前均經 `SafeProjectFiles.isSafeRegularFile` 或受限讀取；其 `relativize` 只將已驗證的 inventory 路徑轉為證據相對路徑。 |
| `safe-files.mjs` | 根、既有候選與最近既有祖先會 realpath；`path.relative` 檢查元件邊界，並逐段拒絕根目錄以下的 symlink。根本身的 symlink 作為設定別名可用。 |
| `capture-static-jsp.mjs` 的 file 請求 | `fileURLToPath` 正確解碼 URL 後，僅由 `resolveExistingFileWithin` 決定是否可載入；移除重複的路徑字串前綴檢查。 |
| `spring-resource-mappings.mjs` | 先以 `path.relative` 排除詞法逃逸，再經 `safe-files.mjs` 驗證 canonical 路徑；缺少的資源仍依既有規則略過。 |
| `pack-preview.mjs` | CSS／圖片／字型皆經 `readUtf8Limited` 或 `readBufferLimited`，未自建另一套檔案邊界。 |
| `screentrace-js/modules.mjs` | `../` 檢查在已載入的記憶體模組表內解析相對模組，不讀取任意檔案系統路徑；不適用真實路徑比較。 |
| 其餘 `startsWith` 命中 | 用於 URL、CSS token、HTML 標籤、證據字串、檔名分類或 UI 資料，不執行檔案系統 containment；沒有路徑大小寫／符號連結風險。 |

## 失敗測試先行與實際 CLI

提交 `999745a` 只新增回歸測試。舊實作實測有以下失敗：輸出根符號連結與大小寫別名在 `PreviewCaptureReader` 被誤判越界；輸出外符號連結資源未被拒絕；舊 workspace 設定的符號連結根未正規化；CLI 經符號連結輸出根分析失敗。Windows 磁碟機大小寫／混合分隔符測試明確限 Windows 執行。

以打包 CLI 對同一份只讀的合成 `spring-mvc-jsp` fixture 執行實際 `analyze`、`report`。三種設定共用同一實際專案與輸出目錄：標準拼法、大小寫變體（此 macOS 檔案系統不分大小寫）、符號連結別名。每種 `analyze`／`report` 均結束碼 0，報表 SHA-256／bytes 比對逐位元組相同。實際輸出路徑在以下摘錄中以 `<測試目錄>` 代換：

```text
[normal analyze] exit=0 INFO: 單一 HTML 報表：file://<測試目錄>/shared/CaseOutput/spring-mvc-jsp/report/screentrace-report.html
[normal report] exit=0 INFO: 單一 HTML 報表：file://<測試目錄>/shared/CaseOutput/spring-mvc-jsp/report/screentrace-report.html
[case analyze] exit=0 INFO: 單一 HTML 報表：file://<測試目錄>/shared/CaseOutput/spring-mvc-jsp/report/screentrace-report.html
[case report] exit=0 INFO: 單一 HTML 報表：file://<測試目錄>/shared/CaseOutput/spring-mvc-jsp/report/screentrace-report.html
[symlink analyze] exit=0 INFO: 單一 HTML 報表：file://<測試目錄>/shared/CaseOutput/spring-mvc-jsp/report/screentrace-report.html
[symlink report] exit=0 INFO: 單一 HTML 報表：file://<測試目錄>/shared/CaseOutput/spring-mvc-jsp/report/screentrace-report.html
```

設定測試另驗證保存後 `projectRoot`／`outputRoot` 是真實路徑，載入舊的 symlink 設定也得到同一真實路徑；大小寫變體在此檔案系統能解析時同樣正規化，並取得「已將…校正為…」提示。單一 HTML 掃描未發現分析輸出目錄、專案根目錄、家目錄、`file://`、`/Users/` 或 `C:\Users\`。
