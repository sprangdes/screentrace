## 實際開啟與導覽操作

Chromium、1440×900、file:// 開啟 petclinic 新單一 HTML。選 Welcome，依序點原型預覽中的四個導覽連結；每次等待預覽完成後觀察主畫面標題與 URL：

| 點選文字 | 實際目的畫面 | 主 URL |
|---|---|---|
| Home | Welcome | / |
| Find owners | Find Owners | /owners/find |
| Veterinarians | Vet List | /vets |
| Error | Exception | /oups |

四次皆能直接切換預覽，沒有「靜態分析無法確認」提示，瀏覽器仍停留原本 file URL；未發生 pageerror 或額外網路請求。最後 Exception 中央顯示既有靜態示例內容，導覽列保留在預覽頂端；右側顯示此畫面有圖支持行為 5 個、原生欄位 0 個、無法確認 1 個。漢堡選單按鈕雖已有錨點元件對應，仍沒有圖支持的開關行為，不宣稱可模擬。無文字品牌連結的 / 目標已有圖支持，仍以既有通用元件名稱顯示。動態示例文字／資料不是真實執行結果。

eMusic 亦以 file:// 開啟，分析資訊抽屜實際顯示行為 28、欄位 13、無法確認 87，無額外請求或 pageerror。此次沒有增加對其無圖支持行為的猜測。

本機觀察結果 r7-observations.json 與 r7-petclinic-nav.png 僅留 /private/tmp，未提交真實畫面或資料。

## 決定性、大小與隱私

兩個真實專案各在不同輸出根執行兩次完整 analyze＋preview＋report。以下四個檔案皆逐位元組相同：application-graph.json、preview-model.json、viewer-documents.json、report/screentrace-report.html。合成 CLI 流程同樣通過。真實圖刪除新增 expansionAnchor 屬性後，與 R6 圖完全相等；元件 ID、名稱、信心、關係、API、檢核與診斷沒有改變。

| petclinic | 3,497,203 | 3,607,940 | 3.166% |
