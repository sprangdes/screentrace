# R13：畫面切換動畫（WP43）

狀態：實作與完整驗證完成，等待需求方驗收；未進入後續工作。

## 修改與測試

完整畫面內的模擬導覽、上一頁／下一頁與畫面跳轉現在保留舊預覽直到新 iframe 載入，再以 150ms opacity 交叉淡化，不使用縮放或縮圖。快速切換只提交最後目的地。總覽卡片進入／返回完整畫面仍使用 300ms 等比 zoom，幽靈縮圖與真正預覽在實際預覽框重疊交接；延遲載入最多等待 1.5 秒後使用既有載入占位。系統偏好減少動態效果時兩種轉場都直接交接。

測試先行提交 `9f9ae42` 先新增 3 項 WP43 E2E；將該版本封存到暫存目錄、以舊來源重建 viewer 後執行，3 項中 2 項失敗：畫面內導覽於 iframe 載入前已移除舊預覽；卡片 zoom 的幽靈終點是主區 832×712（x=280），與預覽實際框 784×551.25（x=304）不符。快速導覽案例通過。實作後擴成 6 項測試，涵蓋延遲載入與無空白期、淡化重疊上限、無導覽 zoom、等比 zoom 與端點、逾時交接、快速切換與 reduced motion。既有斷言未修改或放寬；舊 E2E 只增加等待轉場 DOM 明確移除的條件。詳細決策見 [ADR 0066](../adr/0066-r13-screen-transition-animations.md)。

分析器實際輸出 19 個 endpoint、10 個畫面、92 個元件。PetClinic 原始碼保持唯讀，未啟動目標應用或對它發出網路請求。報表以 Chromium 在 `file://` 開啟，視窗 1440×900；透過 `document.getAnimations()` 讀取當下動畫物件與 `KeyframeEffect.getTiming()`／`getKeyframes()`。

| 操作 | 實際動畫讀值 | 實際觀察 |
|---|---|---|
| 點總覽的「Owner Details」卡片 | `Animation`，300ms，`cubic-bezier(0.2, 0.8, 0.2, 1)`；起始 `translate(334.082px, -7.08075px) scale(0.14775)`，結束 `none` | 縮圖由卡片位置等比放大到工具列下方的預覽；iframe 載入後縮圖與清晰預覽交疊交接，沒有再放大到整個主區。 |
| 在 Owner Details 點「Edit Owner」 | 兩個 `CSSTransition`，各 150ms、`ease`：新 `.preview` opacity `0→1`，`.prototype-outgoing` opacity `1→0` | Owner Details 留在原位直到編輯表單載入，之後短暫淡化交接；沒有縮放、位移或放大的模糊縮圖。 |
| 點「上一頁」 | 預覽交接仍為兩個 150ms `ease` opacity transition。讀值時另有游標經過上一頁圖示引起的 160ms `ease` 顏色 transition；後者不是畫面切換 | 回到前一個完整畫面時預覽交叉淡化，歷史操作沒有觸發卡片 zoom。 |
| 點「Create Or Update Owner Form」卡片 | `Animation`，300ms，`cubic-bezier(0.2, 0.8, 0.2, 1)`；起始 `translate(492.889px, 140.05px) scale(0.14775)`，結束 `none` | 卡片進入仍有地圖式放大語意，終點是載入後的實際預覽框。 |
| 空白送出表單，再選 `POST /owners/new（有歧義）` | 選取候選後 `getAnimations()` 為空 | 仍停留在「Create Or Update Owner Form」，沒有 outgoing layer，也沒有建立第二個 iframe。這個候選只確認模擬的 POST 路由與伺服端檢核資訊，靜態圖沒有證明 POST 後會顯示哪個畫面，因此沒有畫面轉場。候選 `POST /owners/{ownerId}/edit（有歧義）` 同理保留為另一選項。 |
| 再點總覽第一張卡片，並返回總覽 | 進入卡片：300ms `cubic-bezier(0.2, 0.8, 0.2, 1)`，起始 `translate(175.275px, -7.08075px) scale(0.14775)`；返回：同為 300ms，起始 `translate(-175.275px, 7.08075px) scale(5.96062)`；兩者結束 `none` | 進入與返回是方向相反的卡片 zoom。返回卡片可見名稱／URL；完整畫面導覽保持淡化規則。 |
