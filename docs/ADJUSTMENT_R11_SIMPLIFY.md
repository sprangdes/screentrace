# ScreenTrace 第十一輪調整指示（R11：去除模式，簡化畫面檢視器與確認操作）

給 Codex 執行。執行前依 AGENTS.md §10 讀取 `AGENTS.md`、`docs/CODEX_INSTRUCTIONS.md`、`docs/REQUIREMENTS.md`、`docs/ROADMAP.md`、`docs/USER_GUIDE.md`、`docs/ADJUSTMENT_R10_UX.md`、`docs/reports/R4.md`、`docs/reports/R6.md`、`docs/reports/R10.md`。REQUIREMENTS §1 原文與 §2 決策不得更動。R3–R10 的「不要做」與「停止條件」仍適用。

**與 R10 的關係**：本輪取代 R10 中所有「確認模式」「操作／檢查模式」的前提。R10 尚未完成的 WP37（確認工作流）與 WP38，須在本輪完成後，以「**沒有確認模式開關、決策介面永遠可用**」為前提重新實施；R10 文件已加註。執行順序：先完成 R10 WP35／WP36 的待修正項（審查者已另行回覆），再做本輪 WP39，驗收後做 WP40，最後回到 R10 WP37、WP38。

## 0. 需求方的要求

> 這些模式太複雜了，請簡化。

具體決定（需求方已確認）：

1. 完整畫面檢視器的「操作／檢查」切換、「顯示可操作元素」勾選框、縮放下拉全部移除，工具列只剩少數常用控制。
2. **樣式做成右側欄固定的「樣式」標籤頁。**
3. **頂部的「確認模式」開關也移除**：決策（保留／移除／未確認）的狀態永遠可見、永遠可標記。

設計原則：**讓畫面本身告訴使用者能做什麼，而不是要使用者先選模式。**

## 1. 預先授權（同 R4 §0）

只可修改**直接鎖定被取代的模式、控制項或版面**的斷言（例如「存在『確認模式』核取方塊」「點擊在檢查模式只選取」「縮放為下拉選單」）。鎖定資料正確性、證據、安全、決策保存格式與鍵、md 往返、決定性、API 狀態推導、模擬規則結果的斷言一律不得修改。每處在新 ADR 逐處記錄（測試名稱、舊預期、新預期、原因），並證明新斷言在舊實作上失敗。無法歸入者寫 OPEN_QUESTIONS 並停止該項。

## 2. 硬性原則

1. 只改呈現與互動。不改分析器、graph schema、模擬規則（`simulate` 的結果）、API 狀態推導、決策資料模型與保存格式、md 格式。
2. 決策的資料來源與鍵不變：畫面一鍵，元件以（畫面,元件）為鍵。以相同決策匯出的 md 必須與本輪之前**逐位元組相同**（以現有 md 往返 fixture 鎖定）。瀏覽器暫存中既有的決策必須仍能還原；舊版若存有「確認模式開關」旗標，載入時忽略即可。
3. 資訊只能移動，不能消失：被移除的控制項所提供的能力（看樣式、重置、縮放、列出所有可操作元素、統計）都必須仍可到達（見各 WP）。
4. 單一 HTML、離線、決定性、不含本機路徑；報表大小增幅不超過 3%。
5. 觸控裝置（沒有 hover）也必須能完成所有操作。

## 3. 工作包

### WP39　畫面檢視器去除模式

**1. 工具列**（完整畫面檢視器，由左至右）：

```text
[← 返回總覽]  [‹][›]   /owners/{ownerId}（唯讀 URL）                [看流程]  [⋯]
```

- `返回總覽`、`上一頁／下一頁`（圖示按鈕）、唯讀 URL 維持。
- `流程視圖` 改名為「**看流程**」並加圖示；功能不變（切換為中央畫面＋四周關聯線，可從該視圖點中央畫面回來）。
- `重置` 收進「⋯」選單，選單內另有「回到起點」「縮放：適合寬度／75%／100%」。選單項目可用鍵盤操作。
- 移除：操作／檢查切換、「顯示可操作元素」勾選框、縮放下拉。預設永遠「適合寬度」；`+`／`-` 鍵與右下角小型圖示（＋／－／適合寬度，與總覽畫布一致）仍可縮放。
- 工具列在 1024px 以下仍不得逐字折行或溢出；全部控制項可用鍵盤到達。

**2. 預覽中的點擊與資訊（取代「操作／檢查」）**

- **點擊＝試操作**，永遠如此：行為與 R6／WP26 的模擬結果完全相同（導覽、送出表單、彈窗、API 提示、無法確認提示）。點擊後，若停留在同一畫面（例如開彈窗、顯示候選窄條），該元素同時成為「已選取」；若換到其他畫面則清除選取。
- **滑過＝預覽資訊**：滑鼠移到可互動元素上時，該元素出現外框、游標改為手指，並顯示小提示（例如「前往 Owners List」「送出表單」「無法確認」）；右側欄同步顯示該元素的資訊，不改變已選取的元素（滑出後還原顯示已選取者，無選取則顯示畫面資訊）。反應有 120ms 左右的緩衝以免閃爍。鍵盤焦點移到元素上時行為與滑過相同。
- **鎖定元素而不執行動作**：按住 Alt（Option）點擊元素＝只選取、不執行；再次 Alt 點擊同元素或按 Esc 取消選取。此功能在「?」說明浮層與右側欄頂部一行小字（「Alt＋點擊可只查看不操作」）中說明。**觸控裝置**：長按元素＝只選取不執行。
- 不可互動的元素（純文字、裝飾）滑過不反應；Alt 點擊仍可選取（用來看樣式與來源）。
- 首次進入某畫面時，所有「有圖支持」的可操作元素淡淡脈動外框一次（約 1.2 秒，`prefers-reduced-motion` 下改為靜態短暫顯示），之後不再干擾。畫面的「可操作元素總覽」改由右側欄「操作」標籤頁列出（原本就有）；點列表項目時在預覽中高亮並捲動到該元素。

**3. 右側欄新增固定的「樣式」標籤頁**

- 標籤順序：**操作｜API｜檢核｜樣式｜技術細節**。
- 「樣式」顯示目前（滑過或已選取）元素的樣式：元素類型與路徑摘要、版面（位置與大小）、字型、顏色、間距、邊框、背景、以及與瀏覽器預設不同的所有 computed 樣式（沿用既有的 `styleId` 去重資料，不新增資料）；長清單分組並可收合；顏色以色塊＋色碼顯示。沒有元素時顯示空狀態提示。
- 「操作」頁頂部的元素摘要不再放大量原始 CSS（原本在檢查模式優先顯示的樣式移到此頁）。
- 切換標籤頁的選擇在同一次瀏覽內保留（不寫入決策資料）。

**驗收（WP39）**：
- 單元／E2E：工具列控制項數量上限（測試鎖定為 ≤ 7 個可見控制項）；不存在「操作」「檢查」「顯示可操作元素」「縮放下拉」；點擊永遠模擬（以現有模擬 fixture 的結果逐項比對）；滑過更新右側欄且不改選取；Alt 點擊只選取不執行；觸控長按（以 Playwright 觸控模擬）只選取；Esc 取消；首次脈動只出現一次；「樣式」頁內容與舊檢查模式顯示的樣式資料一致（同一元素同一組值）；「⋯」選單的重置行為與舊「重置」相同。
- 零網路請求、零 script 執行（沿用探針）。
- **WP39 完成後停止**，等需求方檢視外觀與手感。

### WP40　移除確認模式：決策介面永遠可用

原則：**未確認是預設，不顯示多餘標記；已決定的才顯示狀態；標記動作永遠一鍵可得。**

1. **頂部列**：移除「確認模式」開關。改為永遠顯示的進度標籤，例如「已確認 23／78」；點擊展開簡易面板（保留／移除／未確認各數量、依狀態篩選的連結、衝突提示數量）。R10 WP37 的「確認儀表板」以此面板為基礎擴充。
2. **總覽卡片**：已決定的畫面左側顯示狀態色條與右上圖示（保留＝綠勾、移除＝紅叉）；未確認不顯示任何標記。滑過卡片時，卡片右上角出現三個小圖示按鈕（保留／移除／未確認，單擊標記，已選者高亮）；鍵盤焦點在卡片上時同樣顯示。觸控裝置：長按卡片顯示相同按鈕列。
3. **畫面檢視器標題列**：畫面名稱旁永遠顯示三段式選擇器（保留｜移除｜未確認），以 `radiogroup` 實作，方向鍵可切換。
4. **預覽內的已決定元素**：已標記保留／移除的按鈕在預覽中以細外框（綠／紅）加小圖示標示；未確認不標示。「隨畫面移除」的元件以淡化＋說明標籤呈現。
5. **右側欄**：選取元素時，元素摘要頂部永遠有三段式選擇器；若所在畫面已標移除，顯示「隨畫面移除」並保留元件本身的決策值（沿用既有規則）。
6. **左側清單與按鈕總表**：畫面清單、按鈕總表每列永遠顯示狀態（已決定者）與一鍵三態小按鈕；R10 WP36 的批次標記保留。狀態篩選晶片（全部／未確認／保留／移除／隨畫面移除）永遠顯示在清單頂部。
7. **功能區域卡片**（R10 WP35）：確認進度永遠顯示（不再有「開啟確認模式查看」字樣）。
8. **衝突與影響提示**：「保留元件導向移除畫面」等既有提示，在相關畫面／元素的右側欄永遠顯示（有衝突時才出現），不再依賴模式。
9. **鍵盤**：選取畫面或按鈕時 `k` 保留、`x` 移除、`u` 未確認（輸入欄位內不觸發）；說明列在「?」浮層。（R10 WP37 的自動前進與「下一個未確認」於回到 R10 時實作。）
10. **「?」說明浮層**（若 R10 WP38 尚未實作，本輪先做最小版）：快捷鍵、點擊與 Alt 點擊的差異、狀態圖例（保留／移除／未確認、已確認／推定／未解析）。頂部列有「?」入口。
11. **文件與截圖**：更新 `docs/USER_GUIDE.md`（移除所有「開啟確認模式」「操作／檢查模式」說法，改寫為新操作；保留全部「必須保留的聲明」與暫存提醒；行數維持精簡）、`docs/ANALYST_GUIDE.md` 必要處；更新 `guide-shots` 並重拍受影響截圖（兩次輸出逐位元組相同，使用合成 fixture，移除孤兒圖）。

**驗收（WP40）**：
- E2E：頁面不存在「確認模式」開關；未確認項目不顯示狀態標記；各介面（卡片、檢視器標題、右側欄、清單、按鈕總表）一鍵標記皆可用且彼此同步（在任一處標記，其他處立即反映）；`k`／`x`／`u` 與輸入欄位內不觸發；觸控長按卡片顯示按鈕列。
- **決策等價**：以固定的決策序列（含畫面移除、元件覆寫、隨畫面移除、批次標記）操作，匯出的 md 與既有 md 往返 fixture **逐位元組相同**；匯入舊版 md 與舊版暫存格式仍能還原決策。
- 進度數字、區域進度與衝突提示數字一致。
- 單元測試：狀態標記顯示規則（未確認不顯示、保留／移除顯示、隨畫面移除顯示）。
- **WP40 完成後停止**，等需求方驗收，再回到 R10 WP37／WP38（以無模式為前提）。

## 4. 測試與報告

每個工作包提交前執行完整驗證（指令同 R3 §5）；基線以 R10 WP35／WP36 修正完成時為準，只增不減（被授權修改的斷言除外）。

報告 `docs/reports/R11.md`：各 WP 狀態與提交；被授權修改的每處斷言（對應 ADR）及其在舊實作上失敗的證明；報表大小前後；**以 petclinic 實際重新分析並開啟報表的觀察**（1440×900：檢視器工具列、滑過資訊、Alt 點擊、樣式頁、卡片標記、按鈕總表標記、進度面板各一段，列出不順手之處）；決策等價的證明（md 位元組比對的檔案雜湊）；所有數字須來自一次實際執行並註明命令，不得手算。未驗證不得寫成已完成。

## 5. 不要做的事

- 不改分析邏輯、schema、模擬規則、API 狀態推導、決策資料模型、md 格式。
- 不新增任何新的「模式」或全域開關；若某功能看來需要開關，先寫 OPEN_QUESTIONS。
- 不得隱藏資料：被移除的控制項所對應的能力必須仍可到達。
- 不新增外部相依或網路資源；不複製真實專案內容、截圖或輸出進 repo。
- 各停止點後不得自行進入下一個工作包。
