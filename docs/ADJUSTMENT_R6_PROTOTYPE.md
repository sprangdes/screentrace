# ScreenTrace 第六輪調整指示（R6：畫面原型檢視與模擬操作）

給 Codex 執行。執行前依 AGENTS.md §10 讀取 `AGENTS.md`、`docs/CODEX_INSTRUCTIONS.md`、`docs/REQUIREMENTS.md`、`docs/ARCHITECTURE.md`、`docs/ROADMAP.md`、`docs/reports/R4.md`、`docs/reports/R5.md`。REQUIREMENTS §1 原文與 §2 決策 D1–D8 不得更動。R3–R5 的「不要做」與「停止條件」仍適用。

## 0. 需求方的新要求

目前沒有「展示專案畫面」的功能。需求方預期：

1. 總覽（Screen Map）上，**每個畫面的縮圖以畫面本身為主**（畫面內容是卡片主體，名稱／URL 只是輔助標題）。
2. **點擊畫面後，直接 zoom in 到所選畫面**，展示**完整的畫面渲染結果**（整頁，不是只有第一屏）。
3. 畫面中的**元素與按鈕可以實際操作**，但**不是 runtime 運行專案，只是渲染模擬**：點連結會前往對應畫面、點按鈕會開啟彈窗、送出表單會走到下一個畫面……全部依靜態分析的圖來模擬。

## 1. 硬性原則（不可違反）

1. **絕不執行被分析專案的程式**：不執行其 JavaScript、不執行 EL／JSP／Java、不發出任何網路請求、不連資料庫。模擬行為的唯一來源是**已有的圖**（Behavior、Relationship、ValidationRule、preview 元素對應）與瀏覽器原生表單輸入。這符合 AGENTS.md「Do not silently guess」與 §8（不做完整 JavaScript 執行）。
2. **無法證明就說無法證明**：元素對不到圖元件、行為目的未解析、行為為 UNKNOWN／JS 狀態變更，一律提示「靜態分析無法確認這個操作」，**不得猜測、不得以文字相似度或 DOM 順序配對**。AMBIGUOUS 要列出全部候選讓使用者選，不得替使用者選一個。
3. 模擬不得改變任何資料：不改決策、不改 md、不改圖；關閉瀏覽器或按「重置」即回到初始狀態。
4. 單一 HTML、離線可開（D6）；不新增外部資源；決定性（同輸入逐位元組相同）；`application.path` 等本機路徑不得出現在報表。
5. 不改 graph schema、分析器、API 狀態推導與 md 格式。**唯一允許的分析側改動**是 capture 的縮圖產生（WP24）。若實作需要其他資料而圖中沒有，寫 OPEN_QUESTIONS 並停止該項。

## 2. 已查證的現況（請自行再驗證）

- 預覽以 `<iframe sandbox="allow-same-origin" srcdoc=…>` 顯示靜態文件（無 `allow-scripts`，原專案 JS 不會執行）。父頁面因 same-origin 可讀取並綁定 iframe 內 DOM 事件——**模擬層應在父頁面實作**，不得開啟 `allow-scripts`。
- 每個畫面在 `payload.preview.screens[]` 有 `thumbnail`（目前 320×200 PNG，取畫面頂部一屏）、`width`／`height`；`payload.preview.elements[]` 有 `path`、`bounds`、`graphComponentId`、`graphComponentCandidates`、`componentResolution`；圖中 `behaviors[]` 以 `triggerId` 指向元件並有 `type`（NAVIGATE／SUBMIT_FORM／CALL_API／OPEN_DIALOG／VALIDATE／UI_STATE_CHANGE／SELECT_CHANGE／UNKNOWN）與 `targetId`。
- 部分 tag 展開的元素（如導覽列）`graphComponentId` 為空、`componentResolution=UNRESOLVED`（見 OQ-015）。這類元素本輪**照實顯示為「無法確認」**，不另外補強對應。

## 3. 預先授權（同 R4 §0）

只可修改**直接鎖定被取代的呈現／互動結構**的斷言（例如「點擊畫面卡片進入四周目的畫面的聚焦視圖」「卡片文字為名稱＋URL 的版面」）。鎖定資料正確性、證據、安全、決策保存、md 往返、決定性、API 狀態推導的斷言一律不得修改。每處在新 ADR 逐處記錄（測試名稱、舊預期、新預期、原因），並證明新斷言在舊實作上會失敗。無法歸入者寫 OPEN_QUESTIONS 並停止該項。

## 4. 工作包

### WP24　總覽卡片以畫面為主

1. 卡片改為「縮圖為主體」：縮圖佔卡片約 80% 面積，保持畫面比例；名稱與主要 URL 以縮圖下方（或底部半透明條）的小標題呈現；確認模式的狀態色條與圖示維持。
2. **縮圖品質**：現行 320×200 放大後會模糊。capture 改產生至少 2 倍於卡片顯示寬度的縮圖（建議 640 寬，取畫面頂部 1440×900 視窗，維持既有裁切語意）；格式與壓縮由你以報表大小實測決定（可比較 PNG／WebP／JPEG），須**決定性**（同環境同輸入逐位元組相同）。報表大小增幅相對 R5 結束時不得超過 25%，超過須在報告說明並寫 OPEN_QUESTIONS。
3. 無縮圖（預覽來源缺失）的畫面顯示明確的占位卡（畫面名稱＋「未取得重建預覽」），不得留白。
4. 流向排版（R5 WP23）、全站導覽切換、hover 關聯高亮、搜尋、自動適合視窗全部維持；卡片變大後節點間距隨之調整，仍不得有邊穿越非端點卡片。
5. 大規模保護：>150 畫面時縮圖採延遲解碼（`loading=lazy` 或 IntersectionObserver），總覽首次渲染不得退步到超過 R5 量測的 3 倍。

驗收：單元／E2E 斷言縮圖面積占比、無縮圖占位、縮圖解析度（寬度 ≥ 卡片顯示寬度 ×2）、決定性、報表大小增幅。

### WP25　Zoom in 與完整畫面檢視（畫面原型檢視器）

1. **點擊總覽中的畫面卡片 → 鏡頭 zoom in 動畫**：卡片從其在畫布上的位置與大小平順放大（FLIP，250–350ms）到主視窗，之後換成完整畫面檢視；`prefers-reduced-motion` 時直接切換。返回時反向動畫回到卡片位置，並維持原本畫布的平移／縮放狀態。
2. **完整畫面檢視器**：
   - 以 iframe 顯示該畫面的靜態文件，寬度為畫面記錄的 `width`，並依檢視器可用寬度縮放（預設「適合寬度」，可選 50%／75%／100%／適合寬度）；高度為**整頁內容高度**（依內容自動撐高，檢視器內垂直捲動），確保展示的是完整畫面而不只第一屏。
   - 載入前先顯示該畫面縮圖作為占位，載入完成後無縫替換（無空白閃爍）。
   - 頂部有「瀏覽器列」樣式的簡潔工具列：返回總覽、上一頁／下一頁（模擬歷史）、**主要 URL（等寬、唯讀）**、縮放選單、重置按鈕；不使用真實網址列，也不更改瀏覽器的 URL。
   - 一次只存在一個即時 iframe（切換畫面時卸載前一個）。
   - 畫面頂部沿用小徽章「示意」說明動態資料為範例值。
3. **右側欄**維持 R4 的資訊架構（操作／API／檢核／技術細節）並與檢視器同步：選取的元素在頁面中以外框標示，反之亦然。
4. **流程視圖**：工具列提供「流程視圖」按鈕，切換為既有的「中央畫面＋四周目的畫面與關聯線」聚焦視圖（原需求）；也可由流程視圖點中央畫面回到檢視器。檢視器底部或側邊另有可收合的「可前往的畫面」縮圖列（含全站導覽分組），點擊等同模擬導覽。
5. **鍵盤**：`Esc` 返回總覽（若有開啟的模擬彈窗則先關閉彈窗）；`Alt+←／→` 或工具列按鈕前進後退；`+`／`-` 縮放。
6. 外部連結與未知目的在 WP25 階段只需攔截並顯示提示（實際互動在 WP26）；**任何點擊都不得讓 iframe 或父頁面真的導向其他 URL**。

驗收：E2E 驗證點擊卡片後出現檢視器、iframe 高度 ≥ 內容高度、占位到內容的替換、Esc／前進後退、reduced-motion 無動畫、流程視圖往返；斷言報表運行期間**零網路請求**與**零 script 執行**（在受測文件中放探針：`<script>`、行內 `onclick`、`javascript:` 連結，皆不得執行）。

### WP26　模擬操作

模擬層為純函式規則加薄薄的事件綁定：**輸入＝被點元素（透過 `path` 對到 preview 元素與 `graphComponentId`）、圖、目前畫面；輸出＝動作描述**（導覽／開彈窗／送出／API／無法確認），再由 UI 執行。規則函式必須可單元測試。

1. **操作模式與檢查模式**：工具列切換「操作｜檢查」。「操作」（預設）下點擊執行模擬並在右側欄顯示該元素資訊；「檢查」下點擊僅選取並顯示樣式／來源（R4 既有行為，含確認模式直接標記按鈕）。「顯示可操作元素」開關以淡色外框標出所有可模擬的元素；滑過可操作元素顯示游標與簡短提示（例如「前往 Owners List」）。
2. **導覽（NAVIGATE，連結／按鈕）**：目的已解析 → 執行 zoom 過渡到目的畫面，並寫入模擬歷史。目的為 UNRESOLVED → 浮出說明「靜態分析無法確定目的」並列出原始運算式；AMBIGUOUS → 列出全部候選供選擇。
3. **送出表單（SUBMIT_FORM）**：
   - 先套用瀏覽器原生約束驗證（`required`、`pattern`、`type` 等，用 `checkValidity`／`reportValidity` 或等價顯示）；失敗則留在原畫面並顯示原生訊息。
   - 通過後：顯示「模擬送出 METHOD 路徑（不會真的送出）」提示，並依圖中該路由 handler 的畫面流向導覽：單一目的直接前往；多個（含 AMBIGUOUS、驗證失敗回表單等）列出全部可能結果供選擇，標示各自的證據等級。
   - 伺服端檢核規則（ValidationRule，SERVER 層）以「可能的檢核訊息」清單呈現於提示，**不捏造訊息文字**，只用規則已有的欄位與描述。
4. **彈窗（OPEN_DIALOG）**：目的彈窗元件可對應到頁面內元素 → 顯示為覆蓋層（背景遮罩＋關閉鈕／點遮罩／Esc 關閉），內容為該元素本身；對不到 → 「彈窗內容無法從靜態分析重建」。
5. **API 呼叫（CALL_API）**：顯示非阻斷提示「模擬呼叫 METHOD 路徑（不會真的送出）」，含「在 API 頁查看」連結（跳到該 API 詳情）；不假造回應內容。
6. **其他行為**：`UI_STATE_CHANGE`、`SELECT_CHANGE`、`VALIDATE`、`UNKNOWN`、`componentResolution=UNRESOLVED` 或無對應圖元件的元素 → 提示「這個操作的結果取決於頁面腳本，靜態分析無法確認」並在右側欄顯示已知的行為與證據。輸入框、下拉、核取、單選、文字區域保持原生可編輯（僅在 iframe 內的暫時狀態，重置即清除）。
7. **攔截**：所有 `<a>` 點擊 `preventDefault`；外部 URL 顯示「外部連結（不會開啟）」；表單永不原生送出；iframe 內不得載入任何遠端資源（在受測文件注入 CSP meta：僅允許 `data:` 的圖片／字型／樣式，禁止其他）。
8. **模擬歷史**：上一頁／下一頁在已造訪的畫面與其捲動位置之間移動；「重置」清空歷史並回到起點畫面與初始表單狀態。歷史僅存在記憶體，不寫入 localStorage、不影響 md 匯出。
9. **覆蓋率誠實揭露**：右側欄「操作」頁顯示「此畫面 N 個可操作元素中 M 個可模擬」；全專案覆蓋率顯示於「分析資訊」抽屜（可操作元素＝連結、按鈕、表單、下拉、輸入）。未對應的元素數量不得被隱藏。

驗收：
- 單元測試（規則函式）：已解析導覽、未解析導覽、AMBIGUOUS 導覽、表單通過／不通過驗證、單一／多個送出結果、彈窗有／無對應元素、CALL_API、UI_STATE_CHANGE、UNKNOWN、無對應圖元件、外部連結、`javascript:` 連結。
- E2E（合成 fixture，三種引擎中環境可用者皆跑，無法啟動者在報告註明）：點連結 zoom 到目的畫面並可上一頁；必填欄位空白送出顯示驗證訊息、填寫後出現送出提示與目的畫面；彈窗開啟與三種關閉方式；API 提示連到 API 頁；未對應元素顯示無法確認提示；操作／檢查模式切換；重置；零網路請求、零 script 執行（探針）；md 匯出在模擬前後逐位元組相同。
- 覆蓋率數字寫入報告（fixture 四個 family 與 petclinic）。

## 5. 停止點與測試

1. **WP24、WP25 完成後停止**，等需求方檢視外觀與動畫（主觀設計）。
2. 驗收通過後做 WP26，完成後停止。
3. 每個工作包提交前執行完整驗證（指令同 R3 §5）。基線：256 Java／40 JS／67 viewer／33 capture／69 E2E，只增不減（被授權修改的斷言除外）。
4. 報告寫入 `docs/reports/R6.md`：各 WP 狀態與提交；被授權修改的斷言（對應 ADR）及其在舊實作上失敗的證明；報表大小與首次渲染時間前後；**以 petclinic 唯讀重新分析、實際開啟報表的觀察**（1440×900：總覽卡片、zoom in、完整畫面、點選連結／送出表單／彈窗各一例，列出不滿意與無法模擬之處）；未驗證項目。未驗證不得寫成已完成。

## 6. 不要做的事

- 不執行專案程式、不開 `allow-scripts`、不發網路請求。
- 不補強 OQ-015 的元件對應；對不到就如實顯示無法確認。
- 不改 schema、分析器、md 格式、API 狀態推導、決策保存。
- 不引入外部相依或資源；不複製 petclinic／eMusicStore 內容進 repo。
- WP25 完成後不得自行進入 WP26。
