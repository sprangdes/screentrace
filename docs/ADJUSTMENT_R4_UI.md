# ScreenTrace 第四輪調整指示（R4：介面改善）

給 Codex 執行。執行前依 AGENTS.md §10 讀取 `AGENTS.md`、`docs/CODEX_INSTRUCTIONS.md`、`docs/REQUIREMENTS.md`、`docs/ARCHITECTURE.md`、`docs/ROADMAP.md`、`docs/reports/R3.md`。REQUIREMENTS §1 原文與 §2 決策不得更動。

## 0. 目標與範圍

需求方的要求：**在不改變功能的前提下，讓報表使用更直覺、畫面更簡潔優雅。**

- 只改 viewer 的呈現與互動（`screentrace-viewer/`，必要時 `screentrace-report` 內的模板）。
- **不改**分析器、graph schema、md 匯出／匯入格式、決策保存規則、API 狀態推導。
- **不新增外部資源**：字型、圖示、CSS、JS 全部內嵌，單一 HTML 離線可開（D6）。圖示用內嵌 SVG。
- 報表檔案大小增幅不超過 10%（以 petclinic 與四個 fixture 的前後大小比較，寫進報告）。
- 決定性（同輸入逐 byte 相同）必須維持。
- **資訊只能移動，不能消失**：目前能到達的每一項資料（路由、來源、證據、診斷明細、元件庫摘要、技術細節）改版後仍須能到達。

### 預先授權（避免再次因既有斷言停下）

改版會使一批鎖定「舊版面文字或結構」的 E2E／viewer 斷言失效。授權如下，條件同 OQ-014：

1. 只可修改**直接鎖定被取代的版面結構、文字或控制項型態**的斷言（例如「按鈕位於左側欄」「checkbox」「select」）。鎖定資料正確性、證據、安全（不執行、不洩漏）、決策保存、md 往返、決定性的斷言**一律不得修改**。
2. 每處被改的斷言須在 ADR（新增 `docs/adr/00xx-viewer-redesign-assertions.md`）逐處記錄：測試名稱、舊預期、新預期、原因。
3. 改完後，在**舊實作**上確認新斷言會失敗，結果寫進報告。
4. 若某斷言無法歸入第 1 點但又與新設計衝突，才寫 OPEN_QUESTIONS 並停止該項。

## 1. 目前介面的問題（以 petclinic 報表實測）

1. **左側欄像一堆同等重要的大按鈕**：畫面／API／總覽／檔案結構四個等寬按鈕、診斷文字、未樣式化的 checkbox／select／檔案選擇器、匯出匯入、元件庫摘要全擠在一條窄欄。導覽、模式、動作、資訊沒有層次。
2. **右側欄閒置時是一片空白**，只有「畫面資訊」四個字；選取畫面後每個項目重複「已由來源確認」與「查看內容」按鈕，資訊密度低、雜訊多。
3. **畫布**：關聯線粗、沒有箭頭、集中在卡片左側軌道互相重疊，難以辨識方向；縮放按鈕與統計文字疊在畫布底部；載入時未自動置中縮放。
4. **黃色「示意畫面」橫幅**佔據聚焦畫面頂部，每次都出現；「返回上一個畫面」是一顆孤立的按鈕。
5. **API 頁是擠壓的表格**：方法被折成「G／E／T」、狀態折成「使／用／中」，處理器長路徑佔大量寬度，右欄完全閒置。
6. **審查（確認）操作藏在下拉選單**，需求方要點兩次才能標記，狀態也不顯眼。
7. 整體缺乏統一的視覺語言（間距、字級、色彩、圓角、狀態色）。

## 2. 設計原則

1. **一次一件事**：預設只呈現當下任務所需，其餘漸進揭露（摺疊、抽屜、標籤頁）。
2. **導覽在上、脈絡在左、細節在右**：頂部列放主要切換與全域動作；左側只放「找畫面」；右側只放「選取物件的資訊」。
3. **狀態要一眼可辨，且不只靠顏色**：保留（綠＋勾）、移除（紅＋叉）、未確認（灰＋問號），文字同在。
4. **少即是多**：預設值正確的資訊不重複說（例如「已由來源確認」是常態，只在「推定」「未解析」「有多個候選」時標示）。
5. **可預期的互動**：整列可點、Esc 返回、`/` 聚焦搜尋、焦點環清楚、hover 與選取回饋一致。

## 3. 設計系統（UI1 先建立）

在 `viewer.css` 以 CSS 變數定義，並套用到全部元件：

- **色彩**：中性灰階 8 階；一個主色（沿用既有墨綠系或選一深青，須通過 WCAG AA 對比）；語意色：保留綠、移除紅、未確認灰、推定琥珀、未解析橘、錯誤紅。背景為淡暖白或淡灰，卡片為白。
- **字型**：系統字型堆疊，含繁中（`-apple-system, "PingFang TC", "Noto Sans TC", "Microsoft JhengHei", system-ui, sans-serif`）；等寬用於 URL／路徑（`ui-monospace, "SF Mono", Menlo, Consolas`）。字級 12／13／14／16／20／24，行高 1.5。
- **間距**：4 的倍數（4／8／12／16／24／32）。**圓角** 8px（卡片 12px）。**陰影** 兩階（卡片、浮層），皆淺。
- **控制項**：自訂樣式的 segmented control、toggle switch、primary／secondary／ghost 按鈕、輸入框（含搜尋圖示）、徽章（badge）、晶片（chip）、tooltip、抽屜（drawer）、空狀態。檔案選擇器改為按鈕觸發隱藏的 `<input type=file>`。
- **圖示**：內嵌 SVG sprite（搜尋、畫面、API、箭頭、勾、叉、問號、資訊、警示、複製、縮放、適合視窗、返回、更多）。
- **動效**：150–200ms 淡入／位移；`prefers-reduced-motion` 時關閉。
- **無障礙**：所有互動元素可鍵盤操作且有可見焦點環；圖示按鈕有 `aria-label`；對比 AA。

## 4. 版面規格

```text
┌──────────────────────────────────────────────────────────────────────┐
│ ScreenTrace · 專案名   [ 畫面 | API ]        ⚑確認模式  [匯出 md] [匯入] [ⓘ 分析資訊 52] │  頂部列（高 56px）
├───────────────┬──────────────────────────────────────┬───────────────┤
│ 🔍 搜尋 URL…  │                                      │ 選取物件資訊   │
│ [地圖|檔案結構]│            主畫布 / API 清單          │ （空狀態有引導）│
│ 狀態晶片篩選   │                                      │               │
│ 畫面清單       │                                      │               │
└───────────────┴──────────────────────────────────────┴───────────────┘
```

### 4.1 頂部列
- 左：品牌＋專案名。中：**畫面／API** segmented control（取代左側四顆大按鈕）。右：確認模式 toggle switch、匯出 md（primary）、匯入（secondary）、「分析資訊」按鈕（含診斷數量徽章）。
- 「分析資訊」開啟右側抽屜：診斷（中文分組，沿用 R3 內容與明細）＋元件庫摘要。左側欄不再放診斷與元件庫。

### 4.2 左側欄（寬約 280px，可收合）
- 最上為搜尋框（`/` 聚焦；有清除鈕；結果即時過濾）。
- 其下 segmented：**地圖｜檔案結構**（取代「總覽」「檔案結構」）。「地圖」模式列出畫面清單（名稱＋URL，點選聚焦）；「檔案結構」為樹狀。
- 確認模式開啟時顯示：狀態晶片（全部／未確認／保留／移除，附數量）與迷你統計條（畫面與按鈕各三色比例條）。
- 每個畫面列顯示狀態圖示，選取列高亮。

### 4.3 畫布
- **載入時自動「適合視窗」置中**；縮放控制改為右下角小型圖示按鈕群（＋、－、適合視窗），不與統計文字重疊。
- 卡片：統一尺寸；縮圖比例保持；第一行名稱（14px 半粗），第二行 URL（等寬 12px 灰）；確認模式下左側 4px 狀態色條＋右上狀態圖示。
- 關聯線：1.5px、淺灰藍；**有箭頭**；hover／聚焦時線與兩端卡片加深，其餘淡化到 25%；不穿越非端點卡片；在卡片間隙（gutter）中走線，避免集中於單一側邊軌道。全站導覽預設隱藏的切換移到畫布左上角小工具列（含「流程 14／全站導覽 36」文字）。
- 版面：以畫面間流程方向決定欄位（入口畫面在左，被導向的在右）；無關聯畫面放最後一欄；仍須決定性。若此項工程過大，可先維持格狀但必須做到上述線條規格，並在報告註明。
- 聚焦視圖：沿用中央＋四周目的畫面；**移除黃色橫幅**，改為預覽右上角小徽章「示意」，hover 說明「動態資料為範例值」；左上角改為返回圖示按鈕＋麵包屑（顯示走過的畫面，可點回）；`Esc` 返回上一畫面。
- 畫面決策改為標題旁的三段 segmented（保留｜移除｜未確認），取代下拉選單。

### 4.4 右側欄
- **空狀態**：置中小圖示＋「點選畫面或關聯線，查看它的按鈕、API 與來源」，並列出 3 個快捷提示（`/` 搜尋、`Esc` 返回、拖曳平移）。
- **選取畫面後**：頂部為名稱、主要 URL（等寬、可複製）、來源檔（截斷＋tooltip）；其下以標籤頁分區：**操作｜API｜檢核｜技術細節**。
  - 「操作」：緊湊列表，每列＝圖示（按鈕／連結／表單／下拉…）＋標籤＋動作晶片（→ 目的畫面、呼叫 API、彈窗）。整列可點，展開顯示該項詳情；**移除「查看內容」按鈕與每列重複的「已由來源確認」**。信心非「已確認」時才顯示徽章（推定／未解析／有多個候選）。
  - 確認模式下每列右側有三態小按鈕（勾／叉／問號）可直接標記，取代下拉選單。
  - 「API」：去重後列出，附呼叫次數；點選展開契約與呼叫來源。
  - 「技術細節」：既有 JSON／證據／解析器／信心，預設收合。
- 導覽元件的標籤優先序落實為：可見文字（含 `jsp:doBody` 內容）→ `title` → `name` → `id` → 「類型＋序號」。`find owners`／`home page` 這類 `title` 在有可見文字（Find owners／Home）時不應被採用。
- 同一畫面的 URL 格式統一：卡片、右側欄、tooltip 一律使用 `{ownerId}` 樣板寫法，不出現 `:ownerId`。

### 4.5 API 頁（主從式）
- 左：API 清單（約 55% 寬）。每列＝方法徽章（`GET` 色彩區分，**不換行**）＋路徑（等寬，可水平省略並 tooltip）＋狀態晶片（使用中／可移除／未被使用，**不換行**）＋呼叫來源數。處理器移出清單。
- 頂部工具列：搜尋、狀態晶片篩選、方法下拉。「外部系統、反射或動態路徑呼叫無法靜態偵測」改為工具列旁的資訊圖示 tooltip＋首次顯示的可關閉提示。
- 右：選取 API 的詳情（處理器與來源檔、契約、檢核、呼叫來源依畫面分組，來源可點回畫面並高亮按鈕）。
- 同路徑多處理器的列以小標籤區分（處理器名稱／方法）。

### 4.6 響應式
- ≥1280px：三欄。1024–1279px：右欄改為覆蓋式抽屜。<1024px：左欄收合為圖示、單欄內容，右欄為底部抽屜。任何寬度（含 390、768）**不得出現整頁水平捲動**。

## 5. 工作包與停止點

每個工作包獨立提交，提交前跑完整驗證（指令同 R3 §5，基線 241 Java／40 JS／50 viewer／33 capture／48 E2E，只增不減，被授權修改的斷言除外）。

| 工作包 | 內容 |
|---|---|
| UI1 | 設計系統（§3）＋應用外殼：頂部列、左側欄、分析資訊抽屜、空狀態（§4.1、§4.2、§4.4 空狀態） |
| UI2 | 畫布與聚焦視圖（§4.3） |
| UI3 | 右側欄資訊架構與審查操作（§4.4）、標籤與 URL 格式統一 |
| UI4 | API 主從頁（§4.5） |
| UI5 | 響應式、鍵盤、無障礙、動效、文件與截圖（§4.6、§6） |

**UI1 完成後停止**，等需求方檢視外觀與整體方向（這是主觀設計，先確認基調再往下做）。UI2–UI4 可連續，完成 UI4 後停止驗收。UI5 後結案。

## 6. 驗收

自動測試（新增，只增不減）：
- 每個頁面在 1440／1024／768／390 寬度下 `document.documentElement.scrollWidth <= innerWidth`。
- 方法徽章與狀態晶片單行（元素高度 ≤ 1 行高）。
- 鍵盤：`/` 聚焦搜尋、`Esc` 返回、Tab 順序可達所有互動元素、焦點環可見。
- 空狀態存在且在選取後消失；三態審查按鈕可標記並與 md 匯出一致（往返測試維持通過）。
- 診斷、元件庫摘要、技術細節仍可到達（以測試點到並斷言內容）。
- 對比：主要文字／背景組合 ≥ 4.5:1（以 CSS 變數計算的單元測試）。
- 載入時畫布自動適合視窗（所有畫面卡片在視窗內可見）。

人工與文件：
- 以 **fixture**（非 petclinic）產生報表，重拍 `docs/images/user-guide/` 的截圖並更新 `docs/USER_GUIDE.md`。不得提交 petclinic 的截圖或輸出。
- 另以 petclinic 唯讀重新分析並實際開啟報表，在 `docs/reports/R4.md` 寫下對 1440×900 與 1024×768 的**觀察**（總覽、聚焦、確認模式、API 頁各一段），列出仍不滿意之處；不要只貼測試數字。
- 報告列出：被授權修改的每處斷言（對應 ADR）、報表大小前後、決定性驗證結果、未驗證項目。

## 7. 不要做的事

- 不改分析邏輯、schema、md 格式、決策與 API 狀態規則。
- 不引入外部字型、CDN、框架（維持現有 esbuild + 原生 TS）；若認為需要 UI 函式庫，先寫 OPEN_QUESTIONS。
- 不做深色模式、不做動畫過度的效果、不加入使用者未要求的新功能。
- 不更動 `fixtures/wp10/golden/*`。
- UI1 完成後不得自行進 UI2。
