## 沿用的作法

- **每一輪一個 PR**，只推到指定分支 `claude/kind-ramanujan-y2ot5a`；PR 合併後先 `git checkout -B claude/kind-ramanujan-y2ot5a origin/main` 再開始下一輪。一律以 **merge commit** 合併（`.git-blame-ignore-revs` 依賴原 SHA），合併前先取得使用者同意。
- **文件**：每輪寫一份 ADR，並在 ROADMAP 結尾加一節、更新 HEALTH_CHECK 的總表與進度。
- **排版**：Java 用 `./mvnw com.diffplug.spotless:spotless-maven-plugin:apply`；TS/JS 用 `npm --prefix screentrace-viewer run format`（Prettier 第一次可能不收斂，執行到 `format:check` 通過）。
- **只搬移類的重構**：用腳本逐一比對宣告或成員，確認內容不變。
- **行為不變的驗證**：在 git worktree 建出修改前的版本，用兩個版本的 CLI 分析 `fixtures/` 的 15 個專案（struts、struts-spring、spring-boot-jsp、spring-mvc-jsp、wp10 的 5 個、r3 的 3 個、r5/wp21、r7 的 2 個），比對產物；除了專案來源路徑與由它算出的報表 `fingerprint` 外要逐位元組相同。CLI 輸出位置是 `<screentrace.home>/analyze/<專案名>`，輸出目錄不要和 worktree 同名。
- **行為改變的驗證**：新測試要在修改前的版本失敗、修改後通過。
- **CI**：四個 job（build-and-test、windows、dependency-audit、node-dependency-audit）。runner 偶爾無法解析 Ubuntu 映像站（`playwright install --with-deps` 卡住），這時先取消 run，等網路恢復再重跑一次，不修改 CI。

## Sandbox 注意事項

- 執行 Maven 時設定 `LANG=C.UTF-8 LC_ALL=C.UTF-8`，否則含中文檔名的測試會失敗。
- Playwright 1.63.0 與 sandbox 內建的 Chromium 1243 相符，`/opt/pw-browsers` 可直接使用；不要 unset `PLAYWRIGHT_BROWSERS_PATH`。
- `node_modules` 不在版本控制中，新的 container 需先執行三個套件的 `npm ci`，並建置 viewer（`npm --prefix screentrace-viewer run build`）。
- `viewer` E2E 的 `performance.e2e.mjs` 在 sandbox 會因時間門檻失敗，CI 上通過。
- 下載的執行檔不能在 sandbox 執行（例如 pwsh），PowerShell 啟動器只能靠 Windows CI 驗證。
- 最近一次本機結果：Maven 594 個測試 589 通過、5 個依作業系統條件略過；JS 180、viewer 單元 148、capture 87 全部通過。
